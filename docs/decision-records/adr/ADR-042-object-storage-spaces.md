# ADR-042: Объектное хранилище: DO Spaces, приватные бакеты, presigned URL, порт без SDK

| --- | --- |

| **Date** | 2026-11-12 |

| **Decided by** | агент по поручению владельца (2026-11-12): владелец написал в чате «постарайся все делать сам без моих подтверждений»; варианты ниже выбрал агент, владелец их по отдельности не подтверждал |
| **Tags** | stack, storage, security |

## Context

- Spaces создан руками вместе с кластером, решения о нём не было: ADR-017 п. 5 отправил его в STACK-2. Имена бакетов, регион, ACL, CORS и ключи нигде не записаны; `docs/runbooks/malinina-kubernetes.md` называет их «не проверено», потому что `doctl` Spaces не видит. **Состояние бакета эта запись не знает и фактом не выдаёт**: сверка - владельцу, через RUNBOOK-1.
- Два Accepted-решения уже опираются на Spaces: ADR-032 п. 5 кладёт туда чанки Loki, ADR-037 отложил сюда проверку загружаемых файлов и ответ про шифрование и бэкап хранилищ, которых ещё нет (оси Input validation и Data at rest). Эта запись их не меняет и ничему не противоречит.
- Зачем нужны медиа: курсы владельца, загружаемые видео и аудио, которые разбирает AI-провайдер (ADR-041, `docs/discovery/product-vision/2026-11-11-owner-product-story.md`). В корпусе есть загрузка и разбор; воспроизведение медиа в браузере нигде не решено.
- Прав доступа заново не придумываем: сессии, два аккаунта и проверка прав в приложении - ADR-040. Один origin `malinina.ca`, CORS не нужен - ADR-038 п. 2; прямая загрузка в Spaces - второй origin, расширение этого решения, а не противоречие ему.
- Новая зависимость требует записи (ADR-005, красный флаг 3 в `AGENTS.md`); владелец 2026-11-12 сказал: никакого нового SDK сегодня. Спек и кода нет (`specs/` - шаблоны, `apps/backend` - скелет).
- Факты о Spaces ниже - из документации DO на 2026-11-12, не проверены на живом бакете: [совместимость с S3](https://docs.digitalocean.com/products/spaces/reference/s3-compatibility/), [лимиты](https://docs.digitalocean.com/products/spaces/details/limits/), [ключи доступа](https://docs.digitalocean.com/products/spaces/how-to/manage-access/).

## Options considered

| Развилка | Выбрано | Отклонено |
|---|---|---|
| Хранилище | DO Spaces по S3 API | «не нужно, добавим с первой спекой»: противоречит ADR-032 (Loki уже на Spaces) и оставляет отсрочку ADR-037 без ответа; PVC в кластере или Postgres: видео не по назначению, новая забота про диск и бэкап, уход от уже созданного ресурса |
| Доступ и путь файла | приватные бакеты; загрузка из браузера напрямую по presigned PUT | всё через бэкенд (стрим): гигабайты видео идут через ingress, под и лимиты тела запроса, о которых ADR-038 ничего не записал; остаётся запасным путём (п. 2); `public-read` или CDN: любой с ссылкой получает платный курс, расходится с ADR-040, presigned URL с CDN не работают (документация DO) |
| Ключи | бакет на назначение, Limited-ключ на бакет и на потребителя | один бакет с префиксами и один Full-access ключ: утечка открывает все бакеты и их администрирование; один бакет и один Limited-ключ на оба назначения: Loki и курсы делят ключ и права |
| Доступ приложения к хранилищу | порт по смыслу, адаптер, in-memory дубль; клиент выбирает отдельная запись | сразу AWS SDK v3 и эмулятор S3 в compose: две зависимости без спеки, против слов владельца, а свежая версия `@aws-sdk/client-s3` (3.1168.0) вышла в день записи и не прошла бы кулдаун ADR-005; своя подпись SigV4 в адаптере: крипто-код ради нулевой выгоды |

## Decision

1. **Хранилище - DigitalOcean Spaces по S3 API**, для медиа курсов и чанков Loki. S3-клиент не выбран и не установлен; локальной среды для Spaces нет (в `compose.yaml` только Postgres и NATS, ADR-033).
2. **Доступ - только приватные бакеты, `public-read` не используется.**
   1. Загрузка идёт из браузера напрямую в Spaces по presigned PUT, который выдаёт бэкенд после проверки прав по ADR-040 (QRY-17: доступ определяет приложение, не ссылка).
   2. Показ медиа в браузере (presigned GET и `media-src` в CSP-1) решает спека курсов; в корпусе есть только загрузка и разбор.
   3. TTL ссылок, лимиты размера и порядок multipart задаёт спека курсов, не эта запись.
   4. Если CORS на Spaces не заработает, загрузка идёт через бэкенд; новой записи для отката не нужно.
3. **Ключи - по ADR-020, по одному на потребителя и бакет.**
   1. Бакет на назначение: один для медиа курсов, один для чанков Loki. Имена записывает RUNBOOK-1 после сверки с консолью.
   2. На каждый бакет и каждого потребителя - Limited-ключ. Ключ медиа лежит в Sealed Secret бэкенда, ключ Loki - в Sealed Secret Loki; значения - из `.env.production`, не в репозитории и не в GitHub Secrets (ADR-020). Как и ключ OpenAI (ADR-041 п. 3.2), ключ получает только процесс, которому он нужен; если загрузкой занят не весь backend, это отдельный секрет.
   3. Full-access ключ, которым настраиваются CORS, lifecycle и отмена незавершённых multipart-загрузок, **в кластер и в репозиторий не попадает**: он лежит в менеджере паролей владельца, и им работают руками. Создание ключей, настройка бакетов и ротация - шаги RUNBOOK-1.
   4. Утечка ключа - выпуск нового в панели и перезапечатывание (ADR-020: меняются сами значения).
4. **Доступ приложения к хранилищу - порт по смыслу.**
   1. Порт лежит в `application/ports/` модуля курсов, формируется нуждой модуля, а не формой S3 (APP-12, PRG-3: внешний I/O и тест-шов); имя, операции и состав модуля - первая спека (`ddd-plan-module`).
   2. Адаптер - в `infrastructure/`, in-memory дубль - рядом с портом (`<порт>.in-memory.ts`, ADR-039 п. 3.2, TST-5). Тесты и локальная среда Spaces не трогают.
   3. S3-клиент и локальный эмулятор выбирает отдельная запись вместе с первой спекой курсов; сегодня зависимостей нет.
   4. Бизнес-исход (файл не найден, ссылка не выдана по правам) - `Result` с кодом `MODULE.REASON`; недоступность Spaces - `throw` (ERR-1..3, ADR-015).
   5. Подписанная ссылка не попадает в логи и метаданные ошибок (ERR-6): подпись в ссылке - секрет на время её жизни. Её параметры добавляются в список скрываемых полей pino-адаптера (ADR-032 п. 4).
5. **Оси ADR-037 для хранилища** (ответ, которого ADR-037 ждал от этой записи; текст ADR-037 не меняется):

| Ось | Ответ |
|---|---|
| Secrets | пп. 3 и 4.5; ключи не в репозитории |
| Authorization | ADR-040; ссылку выдаёт приложение после проверки прав |
| Input validation | **отсрочка** (тип, размер, содержимое, сканирование загружаемых файлов): строка SPEC-2 и спека курсов; запись фиксирует границу доверия - файл из браузера недоверенный |
| Data at rest | **не заявлено, не проверено**: по документации DO у бакета нет настроек шифрования (только SSE-C), версионирование - через API, Object Lock не заявлен; проверка и решение - BACKUP-1 |
| Transport | адрес Spaces - https; отдельного решения нет |
| Logging | п. 4.5 |

## Consequences

- Positive: решение закрывает ADR-017 п. 5 и последние отсрочки ADR-032 и ADR-037 по этому пункту; видео не идёт через поды и ingress; утечка одного ключа не открывает другой бакет; смена хранилища - новый адаптер за тем же портом; зависимостей и расходов сегодня нет.
- Negative: бакет не проверен: приватность (ACL у Spaces только `private` или `public-read`), CORS и регион - требование к владельцу в RUNBOOK-1. Пока не сверено, «приватные» - намерение, а не факт.
- Negative: в найденной документации DO CORS на Spaces не описан, поэтому прямая загрузка из браузера не доказана; запасной путь - через бэкенд (п. 2.4).
- Negative: Limited-ключи несовместимы с политикой бакета (`PutBucketPolicy`): политики не применимы, пока схема ключей такая.
- Negative: Spaces не заявляет шифрование уровня бакета; объём видео не оценён, а бюджетной записи нет: расходы Spaces сверять не с чем (BUDGET-1).
- Negative: presigned URL по документации не работают через CDN-адрес; для загрузки и показа нужен адрес самого Spaces, а CDN для приватных курсов не годится.
- Negative: ключи не доставить в кластер, пока нет контроллера и скрипта (SEALED-1, SECRETS-1); запись описывает правило, не работающую доставку.
- Negative: границу порта `pnpm deps` держит только для `domain/` (`dep-3-domain-no-libraries`): импорт S3-клиента из `application/` он пропустит, как и импорт `openai` (OPENAI-1); правило - в STORAGE-1.
- Делегирование: решено агентом по поручению владельца, варианты по отдельности владелец не подтверждал; владелец вправе оспорить любой пункт новой записью.
- Follow-ups: RUNBOOK-1, CSP-1, BACKUP-1, OBS-2, BUDGET-1 дополнены ссылкой на эту запись; новые строки STORAGE-1 (клиент, эмулятор, правило границ), LOG-1 (скрытие подписанных ссылок), SPEC-2 (вопросы к спеке курсов).

## Confirmation

- Ревью: `ddd-review` и `pre-pr-review` на первой спеке курсов (APP-12, PRG-3, DEP-3, DEP-4, ERR-1..3, ERR-6, TST-5): порт по смыслу, дубль на месте, подписанная ссылка не в логах.
- Машинно: `pnpm deps` ловит импорт в `domain/`; импорт клиента из остальных слоёв - после STORAGE-1; значения ключей в `secrets.yaml` проверяет ревью (ADR-020), gitleaks - репозиторий.
- Вручную: владелец сверяет бакеты с консолью, пока RUNBOOK-1 не закрыт; кода, который можно проверить, нет.

## Revisit when

- Сверка в RUNBOOK-1 показала, что бакет `public-read`, или CORS на Spaces не работает и загрузка идёт через бэкенд постоянно.
- Нужна политика бакета (мешает схема Limited-ключей) или шифрование на стороне хранилища, которого Spaces не даёт (BACKUP-1).
- Объём медиа или исходящий трафик вышли за включённое в базовую цену (по документации на 2026-11-12: 250 GiB хранения и 1 TiB исходящего, [цены](https://docs.digitalocean.com/products/spaces/details/pricing/)); сверять с потолком из BUDGET-1.
- Нужен CDN или публичные файлы (например, картинки витрины): п. 2 говорит только про курсы и Loki.
- Смена платформы ADR-017 или хранилища.
- Выбран S3-клиент и эмулятор: проверить, что порт не принял форму S3.
