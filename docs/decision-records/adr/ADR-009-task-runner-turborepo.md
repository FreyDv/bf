# ADR-009: Задачи монорепо: Turborepo поверх pnpm workspaces, общий пакет конфигураций

## Context

- Монорепо (ADR-008) на pnpm (ADR-007): frontend, backend с несколькими точками входа, общий код.
- Нужно решить, чем запускать `build`, `lint`, `typecheck`, `test` по пакетам: порядок, кэш, только затронутое.
- Решение спорное: при 6-8 пакетах и одном разработчике хватило бы голого pnpm.
- Node-стандарт рекомендует Turborepo (DECISIONS, пункт 2), запасной вариант - Nx.

## Options considered

| Вариант | Плюсы | Минусы | Итог |
|---|---|---|---|
| Turborepo | граф задач `dependsOn`; кэш по хешу; `--filter` затронутого; почти без конфигурации; путь стандарта | ещё один инструмент и зависимость | выбран |
| Только pnpm workspaces | без новой зависимости | нет кэша; порядок и параллелизм руками; CI медленнеет | отклонён |
| Nx | сильные границы и генераторы | тяжелее; стандарт - от 10+ пакетов; границы уже у dependency-cruiser (ADR-014) | отклонён |

Не рассматривались: Bazel, Lerna, Rush.

## Decision

**Граф задач** - один корневой `turbo.json`:

| Задача | Зависит от | Кэш | Замечание |
|---|---|---|---|
| `build` | `^build` | да | `outputs`: `dist/**`, `.next/**` без `.next/cache/**` |
| `typecheck` | `^build` | да | `tsc --noEmit` (ADR-007) |
| `lint` | `^build` при подключении type-aware | да | ESLint type-aware (ADR-016) |
| `test` | `^build` | да | Vitest (ADR-016); тесты против БД не кэшируются |
| `db:migrate`, деплой, `dev` | - | нет | побочные эффекты и долгие процессы |

**Кэш.**
1. Локальный и кэш CI (`actions/cache` по `.turbo`).
2. Удалённый кэш не подключаем: внешний сервис (красный флаг 3).
3. Переменные, влияющие на сборку, - в `globalEnv` или `env` задачи; строгий режим окружения включён.
4. Секреты в хеш и логи не попадают.

**Пакеты** - это приложения и общий код, не доменные модули:
1. Приложение frontend (ADR-011) и приложение backend (ADR-010) с точками входа ADR-008.
2. Пакет контрактов: схемы Zod и тип tRPC-роутера (ADR-012).
3. Пакет shared kernel (ENF-4): базовые типы, `Result`, ошибки, guard.
4. Один пакет конфигураций (scope имени выбирается при scaffold):
   - TypeScript: базовый `tsconfig` и профили Node-библиотеки, Nest, Next.js; строгие флаги ADR-007 только здесь;
   - ESLint: flat config фабриками (база, Nest, Next.js); путь к `tsconfig` задаёт потребитель;
   - Prettier: один конфиг, подключается ключом `prettier` в `package.json`;
   - Vitest: базовый конфиг с SWC-плагином (ADR-016), потребитель добавляет свои пути.
5. Пакет конфигураций не собирается: отдаёт JSON и ESM-файлы; потребители подключают его как `workspace:*`.
6. Доменные модули (STR-1) живут внутри backend-приложения; их границы держит dependency-cruiser (ADR-014), не граф Turborepo.

**Вне графа.** Проверка границ, `self-verify` и гарды стандарта - отдельные шаги из корня, чтобы нарушение не пряталось за кэшем.

**Зависимость.** Версия Turborepo закреплена точно, с кулдауном (ADR-005); вызываемые скрипты - TypeScript через `node` (ADR-007).

## Consequences

- Плюс: порядок и параллелизм декларативны; повторный прогон почти мгновенный; CI проверяет затронутое.
- Плюс: правило линтера, строгость TS или формат меняются в одном месте.
- Минус: правка общего конфига сбрасывает кэш всех пакетов.
- Минус: неверные `inputs`/`outputs` дают устаревший кэш, и ошибка тихая.
- Минус: проверку границ вне графа надо не забыть в CI (ADR-018).
- Дальше: `turbo.json`, пакет конфигураций, команды в AGENTS.md (backlog SCAFFOLD-1).

## Confirmation

`turbo.json` в репозитории; шаг CI с `turbo run`; ревью `inputs`/`outputs` при добавлении пакета; периодический прогон с `--force`. Автоматической проверки правильности кэша нет.

## Revisit when

- Пакетов 10 и больше, либо вторая команда и нужны границы на уровне оболочки (тогда Nx).
- Время CI превышает приемлемое владельцу и удалённый кэш окупается.
- Turborepo меняет лицензию или условия.
