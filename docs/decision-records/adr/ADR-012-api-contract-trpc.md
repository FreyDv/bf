## Context

- Frontend - Next.js (ADR-011), backend - Nest (ADR-010), оба на TypeScript.
- tRPC даёт сквозные типы без генерации клиента, но привязывает клиентов к TypeScript.
- ChatGPT подключается к платформе через MCP и tRPC-клиентом не является.

## Options considered

| Вариант | Плюсы | Минусы | Итог |
|---|---|---|---|
| tRPC | сквозные типы FE-BE | только TS-клиенты | выбран владельцем |
| REST + OpenAPI | открытый контракт для любых клиентов (совет ассистента) | генерация клиента, больше шагов | отклонён |
| GraphQL | гибкие запросы | избыточен для одного оператора | отклонён |
| Подключение к Nest: пакет `nestjs-trpc` | готовая интеграция | новая зависимость | выбран владельцем |
| Подключение к Nest: свой тонкий адаптер | без зависимости (совет ассистента) | свой код | отклонён |

## Decision

1. Канал FE-BE - tRPC на пакете `nestjs-trpc`.
2. Роутер tRPC - driving adapter (ADP-1): разбирает запрос, строит команду или запрос, отправляет в шину; бизнес-логики нет.
3. Входные схемы - Zod, они же request DTO (ADP-3).
4. MCP-сервер для ChatGPT - отдельный driving adapter к тем же командам и запросам (ADP-2).
5. Публичных интеграций на tRPC не строим.

## Consequences

- Плюс: типы FE-BE без генерации; один набор схем Zod.
- Минус: зависимость `nestjs-trpc` и риск отставания от Nest 12.
- Минус: внешние клиенты не на TS получают контракт только через MCP или отдельный REST-адаптер.
- Дальше: при scaffold проверить совместимость пакета с Nest 12 и TypeScript 6; если нет - supersede этой записи на свой адаптер (backlog SCAFFOLD-1).

## Confirmation

Ревью: роутеры без логики и без импорта domain (DEP-2); контрактные тесты через tRPC-клиент (TST-2).

## Revisit when

- Нужен публичный API для нетипизированных клиентов.
- `nestjs-trpc` перестаёт поддерживаться или отстаёт от Nest больше чем на одну мажорную версию.
