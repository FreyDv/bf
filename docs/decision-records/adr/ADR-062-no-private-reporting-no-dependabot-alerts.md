# ADR-062: Без private vulnerability reporting и Dependabot alerts; канал отчётов - issue «security contact»

| **Tags** | security, process |

## Context

- ADR-037 (строки «Dependencies» и «Embargoed work») оставил две настройки GitHub выключенными до включения владельцем: private vulnerability reporting и Dependabot alerts. `SECURITY.md` отправлял отчёты в приватный канал, который не работал.
- Владелец снял эту работу: обе настройки ему не нужны. `SECURITY.md` при этом не может обещать канал, которого нет.

## Options considered

| Развилка | Выбрано | Отклонено |
|---|---|---|
| Настройки GitHub | обе не включать | включить обе (ADR-037): владелец отказался |
| Канал отчёта в `SECURITY.md` | issue с заголовком «security contact» без подробностей; владелец отвечает и договаривается о канале | email владельца: личные данные в публичном репозитории; «приватного канала нет»: сообщившему некуда идти |

## Decision

1. **Private vulnerability reporting и Dependabot alerts не включаются.** Dependabot security updates и version updates тоже не включаются (как в ADR-037).
2. **Канал отчёта:** issue с заголовком `security contact` без технических подробностей; владелец отвечает в issue и предлагает канал. Подробности уязвимости в публичный issue не пишутся.
3. **Эмбарго** не меняется: исправление готовится во временном приватном форке security advisory, его владелец создаёт сам (ADR-037, «Embargoed work»).
4. **Уязвимые зависимости** видны только в отчёте Trivy в summary CI (ADR-029); правило «критичная находка с исправлением - за 7 дней» (ADR-037) действует для находок из этого отчёта.
5. **Заменяет** в ADR-037 строки «Dependencies» и «Embargoed work» в части включения обеих настроек владельцем; остальное в ADR-037 в силе.

## Consequences

- Positive: нечего включать и сопровождать; `SECURITY.md` описывает канал, который работает.
- Negative: сам факт обращения по безопасности виден публично (без подробностей).
- Negative: об уязвимости в зависимости владелец узнаёт, только когда читает отчёт Trivy после запуска CI; GitHub сам не оповещает.

## Confirmation

Review only. Состояние настроек - команды чтения в `docs/runbooks/github-settings.md`, раздел «Безопасность репозитория».

## Revisit when

- Появится второй разработчик или реальные пользователи с данными (тот же триггер, что делает Trivy блокирующим в ADR-029).
- Придёт первый настоящий отчёт об уязвимости через issue.
