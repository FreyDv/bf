## Context

Единая машина и отсутствие автоскейлинга из ADR-022 были пределом; бюджет остаётся 100-150 USD/мес.

## Options considered

- EC2 (ADR-022) - заменён.
- Fargate без сна - отклонён по цене.

## Decision

Каждое Nest-приложение - сервис Fargate (ARM64, 0,5 vCPU / 1 ГБ), который **спит на 0 задач** при простое и пробуждается модулем-оркестратором внутри `api` (состояние = `desiredCount` ECS + теги сервиса, без дополнительного хранилища); ECS Service Connect для `http://<svc>:<port>`; один CloudFront: `/` и `/admin/*` из S3 (статический экспорт Next.js), `/api/*` → ALB → `api`; два стека CDK `bf-prod` (платформа) и `bf-prod-apps` (сервисы); миграции - одноразовые задачи Fargate; публичные подсети и публичные IP, по-прежнему без NAT; релизы регистрируют ревизии task definition напрямую (`ecs-deploy.ts`), `cdk synth` читает работающий тег из SSM. Нет DynamoDB и нет иного хранилища состояния.

## Consequences

- Плюс: ≈ 65-120 USD/мес (≈ 40 фиксированных: ALB + всегда включённый `api`); простаивающие сервисы ничего не стоят; правило Aurora (health только `/health/live`) сохраняется.
- Минус: 30-60 с на первый запрос к спящему сервису (503 + `Retry-After`, клиенты повторяют); Next-приложения теряют серверные возможности (режим export).

## Confirmation

`infra/aws` (`cdk synth` в CI), `pipeline.yml` (release, smoke test); `docs/aws-target-architecture.md` как исходное описание.

## Revisit when

Месячный счёт выходит за верхнюю границу бюджета (BDR-002) или время пробуждения становится неприемлемым для клиентов.
