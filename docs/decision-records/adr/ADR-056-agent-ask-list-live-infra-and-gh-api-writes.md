# ADR-056: Ask-список агента: инструменты живой инфраструктуры и запись через `gh api`

| **Date** | 2026-11-13 |
| **Author** | агент |
| **Decided by** | агент по поручению владельца (2026-11-12): владелец написал в чате «постарайся все делать сам без моих подтверждений» и «Продолжай, не жди меня»; варианты ниже выбрал агент, владелец их по отдельности не подтверждал; владелец вправе оспорить любой пункт новой записью |

## Context

- ADR-037, ось Agent boundaries, оставила `.claude/settings.json` как есть и назвала пробелы: нет `kubectl`, `helm`, `doctl`, `kubeseal`; запись через `gh api` кроме `DELETE` не закрыта. Закрытие - строка AGENT-1.
- [`prerequisites.md`](../../standards/vendor/repository-standards-core/method/prerequisites.md) просит репозиторий, расширивший списки, записать добавленное под этой осью. Эта запись - то место.
- Списки сопоставляют строку команды. `gh api` с флагом поля (`-f`, `-F`, `--field`, `--raw-field`, `--input`) делает POST без `-X`; флаги стоят в любом порядке и пишутся по-разному (`-X POST`, `-XPOST`, `--method=POST`). Существующие записи `deny` для `DELETE` ловили только флаг сразу после `gh api`.
- Кластер, DO и удалённую БД агент не трогает (ADR-047, скилл `backlog-burndown`); ADR-043 исходит из того, что у агента нет разрешения на `kubectl`. Хук `no-ci-secret-writes.sh` уже блокирует `gh api` записи по путям secrets и variables.
- `.claude/settings.json` - запись манифеста `merge`: добавление ключей свободно. `.claude/hooks/*` и `scripts/verifyAgentGuards.sh` - `copy` с хэшем: правка требует исключения `content` (красная зона AGENTS.md, п. 10).

## Options considered

| Развилка | Выбрано | Отклонено |
|---|---|---|
| Уровень | `ask` | `deny`: ломает делегированные сценарии (чтение логов по явному разрешению, разовая команда владельца) и требует правки файла для каждого исключения; смешанный `deny`/`ask`: сложнее объяснять, отходит от строки AGENT-1 |
| Детализация | широкие шаблоны на весь инструмент для `kubectl`, `doctl`, `kubeseal`, `argocd`; для `helm` только изменяющие подкоманды | широкие и для `helm`: спрашивает на `helm lint`, `template`, `show`, `pull`, которые агент запускает локально; только изменяющие подкоманды для всех: `kubectl get` и `kubectl port-forward` тоже касаются живого кластера |
| Формы `gh api` | явные `-X`/`--method` (четыре написания) и неявные (`-f`, `-F`, `--field`, `--raw-field`, `--input`), в любой позиции; `DELETE` в `deny` в любой позиции | только явные формы: неявный POST остаётся открытым; правка хука регуляркой: два исключения `content` в манифесте, хук блокирует, а не спрашивает, и ломает записи GHSET-1 |
| Хук | без правки | расширить `no-ci-secret-writes.sh`: см. выше |

## Decision

1. **`ask` для живой инфраструктуры.** В `permissions.ask` файла `.claude/settings.json`: `kubectl`, `doctl`, `kubeseal` и `argocd` целиком (`Bash(<tool> *)` и голый `Bash(<tool>)`). `argocd` добавлен сверх строки AGENT-1: у него тот же радиус поражения, что у `kubectl apply`, он описан в `docs/runbooks/argocd.md`.
2. **`ask` для изменяющих подкоманд `helm`.** `install`, `upgrade`, `uninstall` (и псевдонимы `delete`, `del`, `un`), `rollback`, `push`, `repo add`, `registry login`. `helm lint`, `template`, `show`, `pull`, `dependency` не спрашивают.
3. **`ask` для записи через `gh api`.** Явный метод `PUT`, `PATCH`, `POST` в четырёх написаниях (`-X M`, `-XM`, `--method M`, `--method=M`) и неявная запись флагами `-f `, `-F `, `--field`, `--raw-field`, `--input`. Шаблон вида `Bash(gh api *<флаг>*)` ловит флаг и сразу после `gh api`, и после пути. Чтение `gh api <путь>` без этих флагов не спрашивает.
4. **`deny` для `DELETE` в любой позиции.** К существующим `gh api -X DELETE *` и `gh api --method DELETE *` добавлены четыре шаблона того же вида. Записи `deny` только добавлены, ни одна не удалена и не ослаблена; `hooks.PreToolUse` не тронут.
5. **Хуки и `verifyAgentGuards.sh` не правятся.** Исключений в манифесте нет. `$about` в `settings.json` дополнен строкой об этих добавлениях.
6. **Известные остаточные пробелы** (строка AGENT-2): строковые шаблоны не покрывают все написания и порядок флагов (`-fkey=value`, `-X=POST`, `-X post`); глобальные флаги `helm` перед подкомандой (`helm --namespace x upgrade`); другие команды записи `gh` (`gh repo edit`, `gh release create`, `gh workflow run`, `gh pr edit`, `gh label`); вызов через обёртку, переменную или `xargs`. Они остаются тем, чем были: запись, не защита.
7. **Что это не меняет.** Агент по-прежнему не трогает живой кластер, DO и удалённую БД (ADR-047): `ask` - видимый запрос, ответ на который даёт владелец, а не разрешение; ADR-043 остаётся верным по смыслу.

## Consequences

- Positive: пробел из ADR-037 закрыт в одном файле без дрейфа от стандарта; локальные `helm lint` и `template` и чтение `gh api` не спрашивают; ни одно правило `deny` не ослаблено.
- Negative: в автономных прогонах подтверждение останавливает работу (безопасная остановка); при режиме без запросов `ask` не защищает, держится только `deny` и хуки.
- Negative: `ask` на `-f`/`-F` спрашивает и на `gh api graphql -f query=...`, который читает: цена неявной формы.
- Negative: сопоставление строк не доказывает полноты (п. 6); дополнения идут записями, не ослаблением.
- Follow-ups: AGENT-2 (остаточные пробелы п. 6).

## Confirmation

`jq . .claude/settings.json` разбирает файл; `bash scripts/verifyAgentGuards.sh` зелёный (хуки целы); `git diff` строк `deny` показывает только добавления. Сам самотест списки `permissions` не проверяет, и запуск запрещённых команд для проверки не делался: срабатывание шаблонов опирается на документацию Claude Code о подстановке `*`, не на опыт.

## Revisit when

- Агенту понадобится читать кластер или DO штатно (например, сборщик логов или GitOps-проверка без владельца): пересмотреть уровень для чтения, отдельной записью.
- Claude Code изменит семантику шаблонов (подстановка в середине команды, `ask` против `deny`).
- Закрыта AGENT-2 или хук стал блокировать по любому пути `gh api`.
