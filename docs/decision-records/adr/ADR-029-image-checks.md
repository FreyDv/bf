# ADR-029: Проверки образа: hadolint и секреты блокируют, Trivy сообщает

## Context

- Образы публичные (ADR-026): секрет в слое читает любой, удалением образа его не отозвать.
- Gitleaks по репозиторию есть, образ он не смотрит.
- Владелец один: блокировка на каждой свежей CVE в базовом образе останавливает всю работу. Блокирующую проверку уязвимостей владелец отклонил.

## Options considered

| Вариант | Плюсы | Минусы | Итог |
|---|---|---|---|
| hadolint и секреты блокируют, Trivy сообщает | нет ложных остановок; утечка секрета невозможна | уязвимость видна, но не блокирует | выбран |
| Всё блокирует | строго | свежая CVE в Debian останавливает работу | отклонён |
| Без проверок образа | без трения | секрет в публичном образе | отклонён |

## Decision

1. `hadolint` по Dockerfile на PR и `main`; ошибка блокирует.
2. Поиск секретов в слоях образа (Trivy `--scanners secret` или gitleaks) перед публикацией; находка блокирует.
3. Trivy по уязвимостям не блокирует: отчёт в summary job, порог видимости HIGH и CRITICAL с доступным исправлением.
4. Недельный прогон Trivy по опубликованному образу не включается, пока сканер не блокирует.

## Consequences

- Плюс: Dockerfile и секреты в образе проверяются всегда; свежая CVE не останавливает работу.
- Минус: образ с известной уязвимостью попадёт в прод; её заметит только тот, кто читает отчёт.
- Минус: два инструмента (hadolint, Trivy или gitleaks) - новые зависимости с закреплённой версией (ADR-005).
- Дальше: шаги в workflow (CI-2).

## Confirmation

Шаги в workflow сборки; обязательные проверки `main` (GUARD-2). Чтение отчёта Trivy - по желанию владельца, автоматической проверки нет.

## Revisit when

- Появляется второй разработчик (тогда Trivy блокирует, плюс недельный прогон).
- Известная уязвимость из отчёта добирается до прода.
- Ложные срабатывания поиска секретов мешают работе.
