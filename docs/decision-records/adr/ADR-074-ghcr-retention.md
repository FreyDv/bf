# ADR-074: Хранение образов в GHCR: что остаётся и кто удаляет (уточняет ADR-026 п. 7, исключение из п. 3)

| | |
| --- | --- |
| **Status** | Accepted |
| **Date** | 2026-11-16 |
| **Author** | агент |
| **Decided by** | агент по поручению владельца, ADR-063 п. 2 (техническая развилка; денег не касается: пакеты публичные) |
| **Tags** | ci, images, registry, supply-chain |

## Context

- ADR-026 п. 7: старые образы удаляются, остаются «последние N по SHA плюс тот, что в `image.yaml`»; N и механизм не заданы (GHCR-1). Каждый merge в `main` публикует `bf-backend` и `bf-frontend`; на 2026-11-16 у `bf-backend` 58 тегов, все - SHA коммитов.
- Пакеты публичные: джоба `publish` в `.github/workflows/ci.yml` тянет образ анонимно и падает иначе (ADR-026 п. 2). Хранение публичных пакетов GHCR бесплатно, поэтому вопрос не о деньгах.
- Откат - revert коммита тега (`docs/runbooks/argocd.md`): образ прежнего SHA должен оставаться в реестре, иначе `ImagePullBackOff`.
- Опубликованный тег - индекс OCI: платформенный образ и манифест аттестации (SBOM, provenance, ADR-029) - отдельные версии пакета без тегов. Удалить их у живого индекса - сломать образ.
- Удалять версии из workflow можно только с `packages: write`; ADR-026 п. 3 даёт это право одной джобе `publish`.

## Options considered

| Развилка | Выбрано | Отклонено |
|---|---|---|
| N | последние 20 разных тегов из истории `image.yaml` плюс всё моложе 30 дней | 10 тегов: при нынешнем темпе (15 коммитов тега за 2 дня) это около суток отката |
| Источник «последних» | история `image.yaml` в git (то, на что откат реально вернётся) | дата создания версии: тег, никогда не бывший в `image.yaml`, вытеснял бы откатные |
| Безтеговые версии | остаются, если на них ссылается оставленный индекс или они моложе 30 дней; иначе удаляются | удалять все безтеговые: ломает оставленные образы |
| Механизм | свой скрипт `scripts/ghcr-retention.ts` на node без зависимостей, отдельный плановый workflow | `actions/delete-package-versions`: новая зависимость, не выражает набор по истории `image.yaml`; шаг в `publish`: удаление в цепочке публикации на каждом merge |
| Право | `packages: write` у единственной джобы `ghcr-retention.yml` | ручное удаление владельцем: `gh api` DELETE - его действие, чистка не была бы настроена |

## Decision

1. Для каждого приложения с `deploy/apps/<app>/image.yaml` пакет `bf-<app>` хранит: тег `image.yaml` на `main`; последние 20 разных тегов истории `image.yaml`; любую версию моложе 30 дней; любой тег, который не SHA коммита; манифесты, на которые указывает оставленный индекс. Остальное удаляется.
2. Если тега `image.yaml` нет в реестре, скрипт ничего не удаляет и падает: неверны входные данные.
3. `.github/workflows/ghcr-retention.yml`: по воскресеньям 06:00 UTC удаляет; ручной запуск (`workflow_dispatch`) по умолчанию только печатает план, удаляет при `apply: true`. Права файла `contents: read`; у единственной джобы ещё `packages: write` - это исключение из ADR-026 п. 3 (и строки прав CI в ADR-037), записанное здесь. ADR-026 остаётся Accepted и не правится.
4. Индексы читаются анонимно с `ghcr.io` (пакеты публичные); список версий и удаление - REST API GitHub с `GITHUB_TOKEN`.
5. Упавший плановый прогон приходит владельцу письмом GitHub, как у `cache-check` (ADR-073).

## Consequences

- Плюс: реестр не растёт бесконечно; откат ревертом достаёт до 20 выкаток назад и не меньше чем на 30 дней.
- Минус: ещё одна джоба с правом удалять пакеты; ограничена одним файлом, расписанием и ручным запуском, без триггеров PR.
- Минус: удалённую версию не вернуть; защита - п. 2, тест плана и пробный прогон перед первым удалением.
- Минус: работает ли `DELETE` с `GITHUB_TOKEN` для пакетов пользовательского аккаунта, видно только на первом боевом прогоне; при отказе прогон падает и приходит письмо.

## Confirmation

- `pnpm ghcr:retention:test` (шаг в `ci`): тег `image.yaml` не удаляется даже старым, отказ без него, 20 тегов истории, окно 30 дней, дочерние манифесты оставленного индекса остаются, сироты удаляются.
- После слияния: ручной пробный прогон, план просмотрен; затем запуск с `apply: true` и сверка, что тег `image.yaml` на месте.

## Revisit when

- GitHub начинает брать деньги за хранение публичных пакетов или пакеты становятся приватными: N и окно по цене.
- Откат понадобился дальше 20 выкаток или 30 дней.
- Появятся теги не-SHA (подписи cosign и подобное): их правило в п. 1.
