# ADR-024: Контракт фильтров query: описание полей, EXISTS, публичный фасад модуля

| | |
| --- | --- |
| **Status** | Accepted |
| **Date** | 2026-11-08 |
| **Author** | владелец |
| **Decided by** | владелец |
| **Tags** | api, contract, query, architecture |

## Context

- Каждый модуль получает tRPC-роутер с query (ADR-012); фильтры должны выглядеть одинаково во всех модулях.
- Нужны: свой набор операторов на поле, наборы для типичных типов, `AND` / `OR` / `NOT`, вложенные фильтры по связанным сущностям, вывод типа TS и схемы Zod из одного описания.
- Правила расходятся: APP-10 разрешает запрос к хранилищу из handler, DEP-2 и DEP-4 требуют порт, а референс DDH показывает оба варианта.
- DEP-5 запрещает импорт таблиц чужого модуля, а фильтр по связи часто пересекает границу модуля.
- VAL-2 запрещает Zod в домене, а домен импортирует shared kernel (DEP-2).

## Options considered

| Развилка | Вариант | Плюсы | Минусы | Итог |
|---|---|---|---|---|
| Описание поля | билдеры `str(...)`, `int(...)` | чистые данные, доступны application-слою | нужна обёртка с типом | выбран |
| | Zod-схема в поле | гибкость значений | Zod попадает в application, нужно исключение из DEP-2 | отклонён |
| | тип внутри `Op.*` | короче | именованный набор на каждое сочетание | отклонён |
| Вложенный фильтр в SQL | только `EXISTS` | одна строка на корень; складывается под `OR`, `NOT`; не требует чужих таблиц | внутри `OR` остаётся подзапросом на строку | выбран |
| | `JOIN` для один-к-одному, `EXISTS` для остального | - | два пути в компиляторе; выбор `INNER` или `LEFT` под `OR` | отклонён |
| | `JOIN` с `DISTINCT` | - | неверные `LIMIT` и `COUNT` без дедупликации; нарушает DEP-5 | отклонён |
| Чужой модуль | публичный фасад владельца | DEP-5 соблюдён | связи между модулями только в одну сторону (DEP-9) | выбран |
| | общие таблицы для чтения | меньше кода | отход от DEP-5, ослабление проверки границ | отклонён |
| | только внутри модуля | проще | фильтр через границу модуля невозможен | отклонён |
| Query handler и БД | read-порт | DEP-2 без исключений; двойник порта в тестах (TST-5) | порт и адаптер на query | выбран |
| | Drizzle в handler | меньше файлов | исключение из DEP-2, ослабление конфига | отклонён |
| Один-ко-многим | `some` / `none` / `every` | полный набор | `every` истинен на пустой связи | выбран |
| | `some` / `none` | меньше | - | отклонён |
| | только один-к-одному | короче | вопрос вернётся при первом таком фильтре | отклонён |
| Место enum API | пакет контрактов, у домена свой enum | правила не нарушены | два enum, если он нужен домену | выбран |
| | один enum и для домена | одно определение | домен зависит от контракта API, отход от DEP-3 | отклонён |

## Decision

Нормативный текст - [`.claude/rules/query-filter-rules.md`](../../../.claude/rules/query-filter-rules.md) (QRY-1..20). Здесь - что решено.

1. Фильтр описывается одним `defineFilter` из билдеров; описание - чистые данные. Из него выводятся тип TS и схема Zod.
2. Операторы в коде - только через `Op.*`, потому что `in` - зарезервированное слово JS.
3. `oneOf` принимает строковый TS enum или непустой массив. Тип `value` на клиенте - сам enum.
4. Enum, видимый клиенту, лежит в пакете контрактов (ADP-6); домен держит свой.
5. Узел фильтра - поля и связи, объединённые через AND, плюс `AND`, `OR`, `NOT`.
6. Вложенный фильтр компилируется только в `EXISTS` / `NOT EXISTS`; связь один-ко-многим требует квантор.
7. Чужой модуль доступен только через его папку `public/`: описание фильтра и компилятор условия.
8. Для всех query handler вызывает read-порт; Drizzle только в infrastructure. Этим закрыто расхождение APP-10 и DEP-4.
9. Инструмент - внутренний пакет с входами `core`, `zod`, `drizzle`, не shared kernel.
10. Роутер - файл `<use-case>.router.ts`, класс на срез, срезы модуля под одним alias (ADP-2). Это шаблон генератора `nestjs-trpc` по умолчанию, флаг не нужен.
11. STR-6 и STR-7 дополняются папкой `public/` и суффиксами `.router`, `.filter-spec`, `.filter-binding`, `.enum`.

## Consequences

- Плюс: один способ писать фильтр; поле без явного разрешения недоступно; вложенный фильтр не размножает строки.
- Минус: enum API и enum домена существуют отдельно.
- Минус: новая папка и суффиксы, конфиг dependency-cruiser сложнее.
- Минус: внешний ключ каждой связи в фильтре обязан иметь индекс.
- Подтверждено прототипом 2026-11-08 (`nestjs-trpc` 2.14.0, Zod 4.6.7, TS 6.0.3, `declaration: true`): генератор работает со схемой из фабрики и с `z.lazy`; точный тип входа доходит до клиента; классы с одним alias сливаются в один namespace; генератор по умолчанию ищет `**/*.router.ts`.
- Не проверено: сборка в ESM и валидация по HTTP. Это первый пункт DoD у backlog QUERY-1; при расхождении действует путь из ADR-012 (свой адаптер).
- Дальше: backlog QUERY-1 (пакет и правила границ), QUERY-2 (сортировка, пагинация, текстовый поиск).

## Confirmation

Правила границ dependency-cruiser (QRY-19, ENF-1); типовые тесты и тесты на настоящем Postgres (QRY-18); пункт чеклиста AIP-6 в `ddd-review`.

## Revisit when

- Read-модель уходит в отдельную базу или модуль становится отдельным сервисом (ADR-008): `EXISTS` через границу модуля станет невозможен.
- Новая версия `nestjs-trpc` перестаёт сохранять типы схемы из фабрики или сливать роутеры с одним alias.
- Нужен фильтр, который нельзя выразить операторами контракта.
