# ADR-023: Запуск CDC: репликация Postgres - SQL-файлом, Debezium Server - файлом настроек

## Context

- Транспорт событий - Debezium (ADR-021), очередь - NATS JetStream (ADR-022).
- CDC состоит из двух частей: репликация в Postgres и Debezium Server.
- На DO доступна только публикация `FOR TABLE` (проба 2026-11-07, ADR-021).
- Владелец хочет по одному файлу-источнику правды на часть; настройка Postgres приводится к своему файлу после каждых миграций.

## Options considered

| Вопрос | Вариант | Итог |
|---|---|---|
| Описание | SQL-файл с функциями для Postgres и файл настроек для Debezium | выбран |
| Описание | скрипт находит все таблицы и применяет исключения | отклонён владельцем в пользу явного списка |
| Описание | режим `filtered`: коннектор сам правит публикацию | отклонён: состав публикации не виден в ревью; нужны права владельца таблиц |
| Смещение | таблица в Postgres (JDBC) | выбран владельцем: не нужен второй том |
| Смещение | файл на PVC | отклонён |
| Развёртывание | обычный Deployment | выбран |
| Развёртывание | Debezium Operator (Helm) | отклонён: ещё один компонент кластера |

## Decision

| Часть | Источник правды | Когда применяется |
|---|---|---|
| Репликация Postgres | один SQL-файл с функциями и их вызовами | после каждых миграций, перезаписывает конфигурацию |
| Debezium Server | один файл настроек | при перезапуске пода |

**Postgres (SQL-файл).** Шаг миграционного Job (ADR-019); сами миграции - один раз и только вперёд (ADR-013).
1. Функция слота: имя и параметры; создаёт слот, если его нет; существующий не трогает (пересоздание теряет позицию).
2. Функция таблицы: имя, схема, таблица, `REPLICA IDENTITY` (по умолчанию `FULL`), список столбцов, если уровень не `FULL`.
3. Имя публикации совпадает с именем слота.
4. Список таблиц явный и только в этом файле.
5. Публикация только `FOR TABLE`.

**Debezium Server (файл настроек).**
1. Списка таблиц нет: Debezium читает всё, что в публикации.
2. Коннектор PostgreSQL, `plugin.name=pgoutput` (по умолчанию `decoderbufs`), прямое соединение на порт 25060.
3. `publication.autocreate.mode=disabled`: публикацию коннектор не создаёт и не меняет.
4. Хеш файла - в аннотации пода (как для секретов, ADR-019): правка в git перезапускает под.
5. Позиция чтения - в слоте и в таблице смещения.

**Развёртывание.**
1. Deployment, одна реплика, стратегия `Recreate` (слот читает один потребитель), манифест в `deploy/`.
2. Смещение - таблица в Postgres (JDBC), которой нет в публикации.
3. Выход - sink `nats-jetstream`, `storage=file`; стрим существует до запуска (ADR-022).
4. Секреты - Sealed Secrets (ADR-020).
5. Образ закреплён точно (ADR-005): 3.7.1.Final вышла 2026-11-06, кулдаун до 2026-11-13; имя образа и версия подтверждаются при установке.

## Consequences

- Плюс: у каждой части один файл в git; изменения видны в ревью.
- Плюс: коннектору не нужны права на DDL.
- Плюс: новая таблица не уходит в очередь без явного вызова.
- Плюс: Debezium не нужен отдельный том.
- Минус: свой SQL и шаг запуска после миграций.
- Минус: каждая таблица добавляется вручную; удаление из публикации - отдельное действие.
- Минус: `FULL` пишет в WAL всю старую строку на каждый UPDATE и DELETE.
- Минус: служебная таблица смещения в боевой базе.
- Минус: одна реплика - простой Debezium копит WAL.
- Дальше: SQL-файл (backlog CDC-1); файл настроек и Deployment (CDC-2); роль Debezium с REPLICATION, мониторинг слота, проба здоровья (CDC-3).

## Confirmation

Только ревью: кода ещё нет. После реализации - ревью SQL-файла и файла настроек в PR.

## Revisit when

- WAL или трафик в NATS от `FULL` заметно давит на диск базы или том NATS (тогда уровень по умолчанию снижается).
- Нужно больше одного экземпляра Debezium (тогда Debezium Operator).
- DO меняет доступность логической репликации для выбранной конфигурации.
