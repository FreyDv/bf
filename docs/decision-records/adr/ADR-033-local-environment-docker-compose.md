# ADR-033: Локальная среда: docker compose с Postgres, NATS JetStream и Debezium

| | |
| --- | --- |
| **Status** | Accepted |
| **Date** | 2026-11-11 |
| **Author** | владелец |

| **Tags** | stack, local, infra |

## Context

- В кластере работают Postgres 18, NATS JetStream и Debezium (ADR-013, ADR-021, ADR-022, ADR-023); тестам нужны те же сервисы (TST-2, TST-3).
- Владелец хочет локально docker compose (2026-11-11).
- Образы закрепляются точно, версия проходит кулдаун 7 дней (ADR-005); Postgres 18.6 и Debezium 3.7.x вышли 2026-11-06, кулдаун до 2026-11-13.
- Владелец потребовал, чтобы локальный Postgres был таким же, как на DO (2026-11-11); на DO PostgreSQL 18.6, `wal_level=logical`, `max_replication_slots=20`, у `doadmin` есть REPLICATION и нет суперпользователя (ADR-021).

## Options considered

| Вариант | Плюсы | Минусы | Итог |
|---|---|---|---|
| docker compose | один файл; те же образы, что в кластере | нужен Docker | выбран владельцем |

Другие способы не сравнивались: сравнения в репозитории нет.

## Decision

1. Локальные сервисы описывает `compose.yaml` в корне; файлы сервисов - в `deploy/local/`.
2. Сервисы: Postgres (`wal_level=logical`, `max_replication_slots=20`, базы `bf_dev` и `bf_test`, имя тестовой помечает её, TST-3), NATS с JetStream и файловым хранилищем, Debezium Server под профилем `cdc`.
3. Роль приложения и Debezium - `doadmin`, как на DO: без суперпользователя, с CREATEROLE, CREATEDB, REPLICATION, BYPASSRLS и тем же членством в группах; владелец обеих баз; суперпользователь `postgres` только создаёт кластер и роли (`deploy/local/postgres/init/`).
   Параметры сервера (WAL, память, `synchronous_commit`, таймауты) заданы флагами `compose.yaml` по снимку `docs/runbooks/bfdb-postgres.md`.
4. Порты Postgres и NATS привязаны к `127.0.0.1`; значения по умолчанию только для этой машины, переопределяются через `.env`.
5. Debezium читает слот и публикацию `bf_slot` (по умолчанию в `bf_dev`), коннектор `pgoutput`, `publication.autocreate.mode=disabled`, выход - `nats-jetstream` в стрим `BF` (subject `bf.>`); слот, публикация и стрим создаются до запуска (ADR-022, ADR-023).
6. Команды: `pnpm local:up`, `local:cdc`, `local:down`, `local:reset`.
7. Образы: `postgres:18.6`, `nats:2.15.1-alpine`, `quay.io/debezium/server:3.6.3.Final`.
8. `postgres:18.6` взят раньше кулдауна ради паритета с DO по исключению ADR-034; NATS и Debezium проходят кулдаун по ADR-005 и поднимаются, когда выйдут версии из кластера.

## Consequences

- Плюс: сервисы, события и очередь локально те же по типу, что в кластере.
- Плюс: проверено 2026-11-11: после вставки строки событие дошло до стрима `BF` на subject `bf.public.smoke`.
- Минус: Debezium локально 3.6.3.Final, ADR-023 планирует 3.7.1.Final; NATS локально может отличаться от версии чарта в кластере.
- Минус: паритет с DO неполный: нет расширения `aiven_extras`, служебных ролей DO, `pghoard` и лимитов тарифа; параметры сервера скопированы по снимку 2026-11-11 и могут разойтись, если DO их изменит.
- Минус: `synchronous_commit=off` как на DO: локально тоже возможна потеря последних транзакций при сбое (backlog DBSEC-2).
- Минус: файл настроек Debezium локальный и дублирует боевой (CDC-2); при расхождении правится оба.
- Минус: слот, публикацию и стрим пока создаёт человек; автоматизация - CDC-1.
- Дальше: приложения пока не подключены к базе и NATS; `.env.example` не создан (запрещён настройками доступа агента).

## Confirmation

Ручная проверка 2026-11-11 на `postgres:18.6`: версия, `wal_level`, роль `doadmin` без суперпользователя, цепочка Debezium под этой ролью. Автоматической проверки нет.

## Revisit when

- Версия Postgres на DO меняется (DO обновил минорную или мажорную версию).
- Образы в кластере и локально расходятся на мажорную версию.
- Локальный запуск тяжелее разработки (память, время старта).
