# ADR-084: Виджеты загрузки кластера на плагине Business Charts: что выделено, что используется, что свободно

| | |
| --- | --- |
| **Status** | Accepted |
| **Date** | 2026-11-18 |
| **Author** | агент |
| **Decided by** | владелец 2026-11-18 в чате: три полукруглых виджета CPU, памяти и хранилища с сегментами FE, BE, Free и текущим использованием в центре (ТЗ и образец), затем «да на всё» на четыре уточнения ниже (п. 2-5). Плагин и запросы выбрал агент (ADR-063) |

## Context

- Дашборд «Потребление» (ADR-083) показывает графики по namespace, подам и узлам. Он не отвечает на вопрос «сколько места осталось»: Kubernetes ставит под по **запрошенному** (requests), а не по используемому.
- Владелец попросил три полукруглых виджета: сегменты FE, BE и Free, которые в сумме дают 100% ёмкости, а в центре текущее использование.
- Замер 2026-11-18: ёмкость для подов (allocatable) - 5.7 vCPU и 8.8 ГиБ (у узлов 6 vCPU и 11.5 ГиБ); frontend и backend запросили по 50m и 128 МиБ, NATS 110m и 288 МиБ, всё остальное (Cilium, ArgoCD, мониторинг, Traefik) - около 32% CPU и 31% памяти.
- Тома: 20.4 ГиБ (NATS 10, Prometheus 10, Grafana 1). У frontend и backend томов нет; их образы и логи лежат на дисках узлов, и разбивки по подам там нет.
- Встроенные панели Grafana 13.3.1 (`gauge`, `bargauge`, `piechart`, `canvas` и другие) не рисуют полукруг из сегментов, размер которых задают данные: цветные зоны `gauge` - это заранее заданные пороги, без подписи у каждой зоны; `piechart` - только полный круг.

## Options considered

| Вариант | Плюсы | Минусы |
| --- | --- | --- |
| **Business Charts 7.3.0** (`volkovlabs-echarts-panel`, Apache ECharts 5.6) | полукруг (`startAngle: 180`, `endAngle: 0`), подписи у сегментов, текст в центре, тема Grafana; плагин Grafana Labs с подписью; совместим с Grafana от 12.3 | новая зависимость; код панели - JavaScript в JSON дашборда; при старте пода плагин скачивается с grafana.com |
| Встроенный `gauge` | без зависимости | одна величина, зоны не следуют данным, подписей сегментов нет: дизайн не воспроизводится |
| `piechart` в виде кольца | без зависимости | полный круг, разворота нет |

## Decision

1. **Плагин** - Business Charts `volkovlabs-echarts-panel@7.3.0`. Точная версия, вышла 2026-11-03, 7 дней карантина прошли (ADR-005). Ставится через `plugins` в `deploy/monitoring/grafana-values.yaml`: чарт передаёт его в `GF_PLUGINS_PREINSTALL_SYNC`, Grafana ставит плагин на том до старта и сама не обновляет (`preinstall_auto_update: false`). Новая версия - правка этой строки после карантина.
2. **Четыре сегмента: FE, BE, Платформа, Free.** Платформа - все поды, кроме FE и BE. Без неё Free занижает занятое: по CPU показал бы около 97% свободного вместо 64%.
3. **Дуга - выделено, центр - используется.** У CPU и памяти сегменты - requests работающих подов (`kube_pod_container_resource_requests` × `kube_pod_status_phase{phase="Running"}`), Free - ёмкость без всех requests. Центр - использование подов (`rate(container_cpu_usage_seconds_total[5m])`, `container_memory_working_set_bytes`). Все доли считаются от одной ёмкости, allocatable узлов (`kube_node_status_allocatable`), поэтому сегменты дают ровно 100.0% (проценты округлены методом наибольшего остатка). Использование может быть больше выделенного. В CPU в центре нет системы узла (kubelet, containerd, ОС), поэтому «CPU по узлам» показывает больше.
4. **Хранилище - только тома (PVC).** Ёмкость - сумма размеров томов. Сегменты - сколько **занято** на томах FE, BE и платформы, Free - свободное место на томах, центр - всё занятое. У тома «выделено» равно его размеру, то есть всему пулу, поэтому здесь дуга показывает заполнение, а не requests. Диски узлов в этот виджет не входят.
5. **FE = frontend; BE = backend и NATS**: очередь NATS служит только backend. Группы задаются именами подов и томов в `namespace="bf"`: `frontend-.*`, `backend-.*|nats-.*`.
6. Три панели стоят первым рядом дашборда, графики ADR-083 сдвинуты ниже без изменений. Обновляются вместе с дашбордом (`refresh: 1m`), значения не захардкожены.

## Consequences

- Хорошо: видно, сколько осталось для новых подов, и это число отделено от реального использования.
- Плохо: на дашборде появился код JavaScript. Его меняет только администратор, а пользователь в Grafana один, владелец (ADR-083 п. 9).
- Плохо: без доступа к grafana.com при старте пода плагин не поставится, и виджеты покажут «плагин не найден». Графики работают и без него.
- Плохо: новый под в `bf` с другим именем молча попадёт в «Платформу». Это правка регулярных выражений в п. 5.

## Revisit when

- В `bf` появится приложение, которое не frontend, не backend и не NATS, или поды переименуют.
- Встроенный gauge Grafana научится рисовать сегменты по данным: тогда плагин убрать.
- Нужны будут диски узлов (образы, логи, `ephemeral-storage`) как отдельный виджет.
- Плагин потеряет подпись или совместимость с новой Grafana.
