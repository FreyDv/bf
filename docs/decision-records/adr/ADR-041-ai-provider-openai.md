# ADR-041: AI-провайдер: OpenAI, вызов только через порт, ключ по ADR-020

| | |
| --- | --- |
| **Status** | Accepted |
| **Date** | 2026-11-12 |
| **Author** | агент |
| **Decided by** | владелец (провайдер, 2026-11-11) и агент по поручению владельца (всё остальное, 2026-11-12): владелец написал в чате «постарайся все делать сам без моих подтверждений»; варианты ниже выбрал агент, владелец их по отдельности не подтверждал |
| **Tags** | stack, ai, security |

## Context

- Владелец 2026-11-11 назвал AI-провайдера: OpenAI (`docs/discovery/product-vision/2026-11-11-owner-product-story.md`). Это его слово, не вывод агента; других провайдеров не сравнивали.
- Зачем - направление, не решение (там же): разбор видео и аудио загруженных курсов, summary, подсказки при готовке. Модели, API, гранулярность - в будущих спеках.
- Ключ OpenAI уже назван секретом приложения в ADR-020 (Sealed Secrets, `envFromSecrets`); имя переменной и процесс, который его получает, не записаны. Фикстура чарта уже несёт `OPENAI_API_KEY` (`deploy/charts/app/ci/full.yaml`).
- Платный внешний сервис и новая зависимость требуют записи (AGENTS.md, красный флаг 3; ADR-005). Это закрывает красный флаг 3 для OpenAI.
- Backend - модульный монолит с несколькими точками входа: HTTP API, воркеры очереди, кроны (ADR-008 п. 3). Разбор длинного видео, скорее всего, пойдёт воркером через NATS (ADR-022); один секрет приложения доходит до всех его процессов (ADR-020, «В кластере» п. 2).
- Кода и спек нет: `apps/backend` - пустой скелет, `specs/` - шаблоны. Угрозы ключа и недоверенного текста курсов уже в модели угроз ADR-037; защита отложена на спеки.
- ChatGPT через MCP (BDR-001, ADR-012) - другая интеграция: ChatGPT вызывает нас, а не мы OpenAI. Здесь она не затронута.

## Options considered

| Развилка | Выбрано | Отклонено |
|---|---|---|
| Провайдер | OpenAI | не сравнивали: выбор владельца |
| Вызов провайдера | порт в `application/ports/`, адаптер в `infrastructure/`, in-memory дубль | один общий порт `AiProvider` в shared kernel: форма по API вендора, а не по нужде домена (APP-12), kernel без доменных понятий (ENF-4); вызов SDK из handler: нарушает DEP-3 и DEP-4, тест без сети невозможен (TST-5) |
| Кто держит `OPENAI_API_KEY` | только процесс, который вызывает провайдера; отдельный секрет, если это не весь backend | ключ в общем секрете backend при отдельном воркере: платный ключ получает и публичный API |
| SDK | пакет `openai` разрешён заранее, только в адаптере, сегодня не добавляется | не разрешать: первой спеке нужна ещё одна запись на зависимость |
| Затраты и данные | указатель на PRIVACY-1 | число и политику в этой записи: их нет ни в одной записи, цифра была бы выдумкой |
| Отдельный BDR на выбор вендора | не пишется | BDR о привязке к вендору: выбор записан словом владельца, смену делает дешёвой порт |

## Decision

1. **Провайдер - OpenAI.** Выбор владельца 2026-11-11. Отдельного BDR нет: выбор - записанное слово владельца, а порт (п. 2) держит смену дешёвой. «Смена провайдера» - сигнал пересмотра.
2. **Вызов провайдера - только через порт.**
   1. Порт лежит в `application/ports/`, адаптер - в `infrastructure/`, in-memory дубль - рядом с портом (`<порт>.in-memory.ts`, ADR-039 п. 3.2).
   2. Порт формируется нуждой модуля, а не API вендора (APP-12); handler и домен SDK не импортируют (DEP-3, DEP-4).
   3. Адаптер валидирует ответ провайдера при чтении (VAL-4, INF-2).
   4. Имя порта, их число, модуль, его классификация (PRG-1) и деление отказов провайдера на `Result` и `throw` (ERR-2, ERR-3) - решает первая спека, которая вызывает провайдера (`ddd-plan-module`).
3. **Ключ - `OPENAI_API_KEY`, по ADR-020.**
   1. SealedSecret, источник `.env.production`, подключение через `envFromSecrets`.
   2. Ключ получает только процесс, который вызывает провайдера. Если это воркер отдельно от публичного HTTP API, ключ лежит в отдельном секрете (ADR-020, «В кластере» п. 3), чтобы публичный API не держал платный ключ. Процесс называет первая спека.
   3. Утечка ключа - ротация значения (ADR-020).
4. **SDK.** Официальный npm-пакет `openai` разрешён заранее, только в адаптере (`infrastructure/`). Сегодня он не добавляется. В день добавления версия точная, lockfile, кулдаун 7 дней (ADR-005); отдельная запись на этот пакет не нужна.
5. **Затраты и данные - указатели.** Потолка затрат нет: записи о бюджете облака нет и не будет (владелец, 2026-11-13). Какие персональные данные уходят провайдеру и как он их хранит - PRIVACY-1. Чисел, моделей и API-поверхности здесь нет: цены и модели меняются, их выбирает спека и датирует проверку.
6. **Тесты и локальная среда не ходят к провайдеру.** Unit, use case и e2e на `bf_test` (ADR-039) используют in-memory double порта; локальная среда (ADR-033) без ключа. Настоящий ключ есть только в кластере.

## Consequences

- Positive: красный флаг 3 закрыт для OpenAI; смена провайдера - новый адаптер за тем же портом; use case и тесты идут без сети (ADR-039).
- Negative: потолка расходов нет (записи о бюджете облака нет и не будет (владелец, 2026-11-13)): платный ключ ничем не ограничен.
- Negative: что из курсов и данных покупателей уходит OpenAI, хранение и обучение на этих данных, права на контент загружаемых курсов - нигде не записаны (PRIVACY-1 и новая строка).
- Negative: границу порта вне домена машина не держит: `dep-3-domain-no-libraries` запрещает npm-импорты только в `domain/`, импорт `openai` из `application/` `pnpm deps` пропустит. Ловит только ревью, правило - новая строка.
- Negative: ключ в кластер не доставить, пока нет контроллера, скрипта и порядка первого выката (SEALED-1, SECRETS-1, CHART-2); запись описывает правило, не работающую доставку.
- Negative: что провайдер разбирает именно видео и аудио курсов в нужном виде, эта запись не проверяла: проверка - первая спека.
- Follow-ups: PRIVACY-1 дополнена ссылкой на эту запись; новые строки OPENAI-1 (правило границ для `openai`) и COURSES-1 (права на контент курсов и политика данных у провайдера).

## Confirmation

- Ревью: `ddd-review` (DEP-3, DEP-4, APP-12, INF-1..3, TST-5) и `pre-pr-review` на первой спеке с вызовом: порт, адаптер и дубль на месте, SDK только в адаптере, ключ только у названного процесса.
- Машинно: `pnpm deps` ловит импорт в `domain/`; импорт `openai` из остальных слоёв - после OPENAI-1; значения в `secrets.yaml` проверяет ревью (ADR-020).
- До первой спеки с вызовом провайдера проверять нечего: кода нет.

## Revisit when

- Смена провайдера или нужен второй: смотреть, что порт не принял форму API OpenAI.
- Появился PRIVACY-1 или запись о правах на контент курсов и они ограничивают, что можно отправлять OpenAI.
- Первая спека, которая вызывает провайдера: назвать процесс, порт и модуль; добавить пакет `openai` по ADR-005.
- Условия или цены OpenAI изменились так, что пункт 5 или бюджет перестали держаться.
