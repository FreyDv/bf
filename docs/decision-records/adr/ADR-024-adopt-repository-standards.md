## Context

Владелец поручил зафиксировать знания стандарта repositorystandards.com и источника Domain-Driven Hexagon в репозитории так, чтобы каждая будущая сессия планирования, кода и ревью следовала им без исключений. Знания, которые живут только в чате или в памяти агента, для стандарта не существуют (R3).

## Options considered

- Не внедрять; держать правила в памяти агента - отклонено (R3).
- Внедрить частично - отклонено владельцем (выбрано «мигрировать всё»).
- Внедрить полностью волнами - выбрано.

## Decision

Репозиторий следует Repository Standards 1.0.19 (профиль **core**: один автор, работа не передаётся асинхронно). Слой 2 (стек Node) применяется выборочно: расхождения с ним (Biome, Vitest, Playwright, Node 24) - исключения в манифесте с причиной. Знания лежат в `docs/standards/` (источники скопированы дословно, плюс дайджесты и правила), правила загружаются путь-зависимо из `.claude/rules/`, исполнение обеспечивают гарды (`scripts/*.mjs`, хуки `.claude/hooks/`) и CI. Отклонение допустимо только если записано.

## Consequences

- Плюс: каждая сессия начинает с одних правил; дрейф виден числом (`node scripts/self-verify.mjs`).
- Минус: накладные расходы на спеки и записи решений; `spec-guard.yml` и `gitleaks.yml` работают в CI.

## Confirmation

`node scripts/self-verify.mjs` (дрейф 0), `spec-guard.yml` на каждый PR, `scripts/verifyAgentGuards.sh`.

## Revisit when

Репозиторий переходит на профиль scale (работа передаётся другим людям) или стандарт меняет нормативное ядро несовместимо с записанными исключениями.
