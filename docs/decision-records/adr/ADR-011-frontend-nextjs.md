## Context

- Frontend на Next.js с React уже подразумевался в ADR-012 (tRPC) и ADR-009 (пакеты), но не был записан отдельно.
- Один язык на FE и BE (ADR-007); контракт FE-BE - tRPC (ADR-012).
- Публичные страницы должны индексироваться поисковиками.
- Владелец уже работает с React и Next.js.

## Options considered

| Вариант | Плюсы | Минусы | Итог |
|---|---|---|---|
| Next.js с React | SSR и SEO; привычный стек владельца; большая экосистема; один TS с backend | тяжёлый фреймворк; своя модель сборки и кэша | выбран |

Другие фреймворки не сравнивались: сравнения в репозитории нет.

## Decision

1. Frontend - Next.js с React, TypeScript (ADR-007).
2. Публичные страницы рендерятся на сервере (SSR/SSG) ради SEO.
3. Данные с backend - через tRPC-клиент и пакет контрактов (ADR-012, ADR-009).
4. Frontend - отдельное приложение монорепо (ADR-008).

## Consequences

- Плюс: общие типы с backend без генерации клиента.
- Плюс: SSR для публичных страниц из коробки.
- Минус: в монорепо две модели сборки (Next.js и Nest); `.next/**` в кэше Turborepo (ADR-009).
- Дальше: версия Next.js и способ развёртывания в кластере - при scaffold (backlog SCAFFOLD-1).

## Confirmation

Только ревью: приложения ещё нет.

## Revisit when

- Публичные страницы не нужны и SSR не используется.
- Next.js меняет лицензию или модель развёртывания так, что она не работает в нашем кластере (ADR-017).
