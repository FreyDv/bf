# ADR-048: Shared kernel - пакет `@bf/kernel`; `Result` попадает в domain только через него (уточняет ADR-009 и ADR-015)

| **Tags** | architecture, errors, boundaries |

## Context

- ENF-4 кладёт `Result` в shared kernel; ADR-009 п. 3 называет kernel пакетом (базовые типы, `Result`, ошибки, guard). Имя и путь пакета записаны не были.
- ADR-015 выбрал `Result` из neverthrow (п. 1), отклонил свой `Result` в kernel и допустил тип в domain в возвращаемых значениях (п. 3). Откуда domain его импортирует, ADR-015 не говорит.
- `dep-3-domain-no-libraries` запрещает в `domain/` любой npm-импорт; `dep-5-modules-only-through-public` считает чужим модулем каждую папку в `apps/backend/src/`. Ослаблять правило без ADR с его ID нельзя (ADR-014 п. 4, ENF-1).
- Проверено запуском `depcruise` 18.7.2 с `.dependency-cruiser.mjs` на временном дереве (фикстура в `scripts/boundaries.test.ts`, 2026-11-12):
  - импорт `@bf/kernel` из `domain/` - workspace-пакет, не npm: `dep-3` не срабатывает;
  - прямой импорт `neverthrow` из `domain/` - npm: `dep-3` срабатывает;
  - если `exports` пакета указывает в `dist/`, импорт выпадает из графа совсем (`options.exclude` в конфиге), то есть проверки не видят ни нарушения, ни легального импорта.
- Пакета и зависимости neverthrow в репозитории нет, потребителя тоже: `apps/backend` пуст (тот же довод, что в ADR-039: PRG-3). neverthrow latest 8.2.0 (`npm view`, релиз 2025-02-21), кулдаун ADR-005 пройден.
- `Result` - значение, не тип: пакет с ним нужно собирать, Node не исполняет `.ts` из `node_modules`.

## Options considered

| Развилка | Выбрано | Отклонено |
|---|---|---|
| Где kernel | пакет `packages/kernel`, имя `@bf/kernel` (ADR-009 п. 3): `dep-5` на него не действует | папка в `apps/backend/src/`: `dep-5` считает её чужим модулем, нужно исключение из `dep-5` |
| Откуда `Result` в domain | только из `@bf/kernel`, который один импортирует neverthrow и реэкспортирует `Result` | прямо из neverthrow: исключение из `dep-3` для пакета, каждый домен зависит от библиотеки, а не от kernel |
| Своя обёртка вместо реэкспорта | нет: реэкспорт | свой тип результата: код пишем и тестируем сами (отклонено в ADR-015) |
| Исключение из `dep-3` для kernel | не добавлять: фикстура показала, что оно не нужно | `pathNot` на kernel «на всякий случай»: ослабление без проверенной причины |
| Каркас пакета и neverthrow сейчас | не создавать: пакет приезжает с LOG-2 или первым модулем | создать сейчас: код и зависимость без потребителя (PRG-3, ADR-039) |

## Decision

1. **Shared kernel - пакет `packages/kernel`, имя `@bf/kernel`.** Состав по ENF-4 и ADR-009 п. 3. Тулкит фильтров (QRY-6) и порт `AiProvider` (ADR-041) в kernel не входят.
2. **Пакета сейчас нет.** `packages/kernel` и зависимость neverthrow появляются со строкой LOG-2 или с первым модулем: версия точная, lockfile, кулдаун 7 дней (ADR-005). Форма выдачи - собранный `dist` (`Result` - значение). Правила и фикстуры ниже доказывают границы уже сегодня на временном дереве, которое повторяет путь и имя пакета.
3. **`Result` в domain - только через kernel.** `domain/` импортирует `Result` из `@bf/kernel` и никогда из `neverthrow`; kernel - единственный пакет репозитория, который зависит от neverthrow, и реэкспортирует его `Result`. Это уточняет ADR-015 п. 3 (откуда импорт) и ADR-009 п. 3 (имя и путь); ADR-009 и ADR-015 остаются Accepted. Прямой импорт `neverthrow` из `domain/` отклоняет прежний `dep-3-domain-no-libraries`.
4. **Отступление от DEP-6, записанное здесь.** DEP-6 требует обернуть библиотеку общего назначения, которая расползается по многим доменным объектам; реэкспорт - не обёртка. Допущено для типа `Result` во всех модулях: ERR-2 требует тип результата, ADR-015 выбрал neverthrow и отклонил свой тип. Какие имена реэкспортируются, решает строка, создающая пакет.
5. **Конфиг границ.**
   1. Исключения из `dep-3` для kernel нет: импорт workspace-пакета ей не подлежит. Пункт DoD BOUND-1 «явное исключение» закрыт доказательством: фикстура показывает, что импорт `@bf/kernel` из `domain/` проходит, а `neverthrow` отклоняется.
   2. Новое правило `kernel-is-domain-free` (ENF-4): файл в `packages/kernel/` не импортирует ничего из `apps/`. Domain может импортировать kernel, поэтому kernel не должен вести обратно.
   3. Фикстуры в `scripts/boundaries.test.ts`: легальный импорт `@bf/kernel` из `domain/` (и проверка, что граф его видит), отклонённый импорт `neverthrow` из `domain/`, отклонённый импорт `apps/` из kernel.
6. **Чего правила не держат.** `dep-3` смотрит только npm-типы: из `domain/` проходит импорт любого workspace-пакета, не только kernel (в том числе `@bf/contracts`, запрещённый QRY-20). Белый список «из `domain/` в `packages/` только kernel» и какие npm-пакеты может импортировать сам kernel - не решены, строка BOUND-2. До неё держит ревью (`ddd-review`, AIP-6.2).

## Consequences

- Positive: первый модуль не упирается в конфиг; на вопрос «откуда `Result`» один ответ и один импорт; смена способа получить `Result` трогает kernel и импорты, а не зависимости доменов.
- Positive: ослабления конфига нет, добавлено одно правило.
- Negative: пока пакета нет, фикстуры доказывают правила на имитации; настоящий `@bf/kernel` проверяется в первый день, когда появляется (`pnpm deps` и `pnpm deps:test`).
- Negative: с `exports` в `dist/` проверки границ не видят импортов kernel из domain (`exclude` в конфиге); фикстура держит форму с исходниками. Ограничение записано здесь и в строке BOUND-2, а не скрыто.
- Negative: API neverthrow (`andThen`, `ResultAsync` и прочее) попадает в вызывающий код через реэкспорт; замена библиотеки - не правка одного пакета.
- Negative: neverthrow не выпускал релиз после 8.2.0 (2025-02-21); `Revisit when` ADR-015 - «перестаёт поддерживаться» - оценивать по этому факту.
- Follow-ups: строка BOUND-2 (белый список workspace-пакетов для `domain/`); LOG-2 создаёт пакет; TEST-3 и OPENAI-1 правят тот же файл конфига и закрываются в этом же PR по ADR-039 п. 4 и ADR-041 п. 2 и 4, нового решения им не нужно.

## Confirmation

- Машинно: `pnpm deps` и `pnpm deps:test` (шаг `Architecture boundaries` в `ci`): правило `kernel-is-domain-free` и фикстуры из п. 5.3; отказ на прямом `neverthrow` в `domain/` держит `dep-3` без изменений.
- Ревью: `ddd-review` (AIP-6.2, AIP-6.5): `Result` в domain из `@bf/kernel`, в kernel нет доменных понятий (ENF-4). Белый список workspace-пакетов - только ревью до BOUND-2.

## Revisit when

- neverthrow перестаёт поддерживаться (ADR-015) или нужен свой тип результата: п. 3 и 4.
- Строка BOUND-2 закрыта: п. 6 заменяется правилом.
- В kernel понадобился npm-пакет, кроме neverthrow: решение о том, что kernel может импортировать.
- Первый модуль нашёл, что `domain/` не может получить из kernel то, что нужно (guard, базовый `Entity`): состав kernel по ENF-4 решается с первым потребителем.
