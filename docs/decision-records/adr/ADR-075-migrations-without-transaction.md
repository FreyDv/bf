# ADR-075: Миграция без транзакции: файл `*.no-transaction.sql` с одним оператором `CONCURRENTLY` (дополняет ADR-036)

| | |
| --- | --- |
| **Status** | Accepted |
| **Date** | 2026-11-16 |
| **Author** | агент |
| **Decided by** | агент по поручению владельца, ADR-063 п. 2 (техническая развилка) |
| **Tags** | migrations, database, ci |

## Context

- ADR-036: каждый файл `apps/backend/migrations/*.sql` применяется одной транзакцией (`psql --single-transaction`, константа `CONTRACT` в `scripts/check-migrations.ts`). Postgres отказывает `CREATE INDEX CONCURRENTLY`, `DROP INDEX CONCURRENTLY` и `REINDEX ... CONCURRENTLY` внутри блока транзакции.
- ADR-018 и ADR-036 назвали это последствием без правила (MIGR-1). Индекс на большой таблице без `CONCURRENTLY` блокирует запись на время построения.
- Без транзакции `psql` фиксирует каждый оператор сам: при сбое на втором операторе первый уже применён, и повторный запуск файла ломается.

## Options considered

| Развилка | Выбрано | Отклонено |
|---|---|---|
| Пометка | суффикс имени `*.no-transaction.sql` | директива-комментарий в первой строке: не видна в списке файлов, легко потерять при правке |
| Содержимое | ровно один оператор `CONCURRENTLY` | любые операторы без транзакции: частичное применение при сбое |
| Применение | тот же `psql` без `--single-transaction` | отдельный инструмент: второй контракт применения |

## Decision

1. Файл, которому нужна работа вне транзакции, называется `<номер>_<имя>.no-transaction.sql` и содержит ровно один оператор: `CREATE [UNIQUE] INDEX CONCURRENTLY`, `DROP INDEX CONCURRENTLY` или `REINDEX INDEX|TABLE ... CONCURRENTLY`; комментарии допустимы.
2. Он применяется той же командой `CONTRACT.apply`, но без `--single-transaction` (`applyCommand(name)` в `scripts/check-migrations.ts`). Любой другой файл - как раньше, одной транзакцией.
3. Проверка миграций (`pnpm migrations:check`, шаг CI) отклоняет до запуска базы: `CONCURRENTLY` в обычном файле (с подсказкой переименовать) и файл `.no-transaction.sql` с другим оператором или с несколькими.
4. Деплой (Job миграции, DEPLOY-2) и применение миграций к `bf_test` (SCHEMA-1, ADR-071 п. 5) берут команду из `applyCommand`, а не повторяют её.
5. Сбой `CREATE INDEX CONCURRENTLY` оставляет индекс в состоянии `INVALID`. Повтор - новый файл миграции: `DROP INDEX CONCURRENTLY IF EXISTS` невалидного индекса, затем построение заново; применённый файл не правится (ADR-013).

## Consequences

- Плюс: индекс на живой таблице строится без блокировки записи, и CI проверяет файл тем же способом, каким его применит деплой.
- Минус: разбор операторов простой (по `;` без учёта строк); для операторов индекса этого хватает, сложный SQL в таком файле запрещён п. 1.
- Минус: без транзакции нет отката файла; цена - п. 5.

## Confirmation

`pnpm migrations:test` (шаг `ci`): фикстура `scripts/fixtures/migrations/concurrent-index` строит индекс `CONCURRENTLY` на настоящем Postgres; тесты плана отклоняют `CONCURRENTLY` в обычном файле и лишний оператор в файле без транзакции; команда без `--single-transaction` только для такого файла.

## Revisit when

- Нужен другой оператор вне транзакции (`ALTER TYPE ... ADD VALUE` в старых версиях, `VACUUM`): расширить список п. 1.
- Появится инструмент миграций, у которого своя пометка (ADR-013): заменить суффикс его средством.
