# ADR-013: Хранилище: PostgreSQL 18, Drizzle, миграции только вперёд

## Context

- Заказы, платежи и аналитика реляционные; нужны транзакции между агрегатами (APP-11).
- Node-стандарт оставляет слой запросов на решение репозитория.
- Владелец выбрал Drizzle и хочет только миграции «вверх».
- Где работает база - ADR-017; доставка событий из базы - ADR-021.

## Options considered

| Вариант | Плюсы | Минусы | Итог |
|---|---|---|---|
| PostgreSQL + Drizzle | SQL-близкий слой; схема в TypeScript; `drizzle-kit` генерирует SQL | моложе Prisma | выбран владельцем |
| PostgreSQL + Kysely или Prisma | рассмотрены стандартом | - | отклонён |
| DynamoDB, SQLite | - | нет транзакций между агрегатами; доступ из MCP и воркеров | отклонён |

## Decision

1. Основное хранилище - PostgreSQL 18.
2. Слой запросов - Drizzle.
3. Persistence-модель отдельно от domain (INF-5); строки валидируются при чтении (VAL-4, INF-7).
4. Миграции - SQL-файлы только «вверх», без `down`.
5. Откат схемы - новая миграция; опасные изменения в два шага (расширить, затем сузить), чтобы прежняя версия приложения работала с новой схемой.
6. Миграции применяет механизм деплоя или человек, не агент (красный флаг 1); как - ADR-018, ADR-019.

## Consequences

- Плюс: простая модель миграций; каждая запись в истории - факт.
- Минус: откат дороже и требует дисциплины двух шагов.

## Confirmation

В репозитории нет файлов `down`; ревью схемных миграций на два шага; поведенческие тесты только против БД с тестовым именем (TST-3).

## Revisit when

- Объём или нагрузка требуют второго хранилища.
- Drizzle перестаёт поддерживаться.
