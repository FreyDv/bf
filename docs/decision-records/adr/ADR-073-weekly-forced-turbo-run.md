# ADR-073: Еженедельный прогон Turborepo с `--force` - отдельный workflow `cache-check` (уточняет Confirmation ADR-009)

| **Status** | Accepted |
| **Date** | 2026-11-16 |
| **Author** | агент |
| **Decided by** | агент по поручению владельца, ADR-063 п. 2 (техническая развилка) |
| **Tags** | ci, turborepo, cache |

## Context

- Confirmation ADR-009 называет страховкой кеша «периодический прогон с `--force`»; в `.github/workflows` его не было, ADR-058 п. 5 отдал вопрос строке CI-4.
- `ci` восстанавливает кеш Turborepo прошлых прогонов (`actions/cache`, `restore-keys`), и на PR, и на `main`. Задача, у которой в `inputs` пропущен файл (ADR-058, ADR-065), проходит на устаревшем попадании в кеш, и ошибка не видна, пока кеш не сменится.
- В `ci.yml` событие `schedule` запустило бы и джобы `image`, `publish`, `tag` (публикация и коммит тега).

## Options considered

| Вариант | Итог | Почему |
|---|---|---|
| Отдельный workflow `cache-check.yml`: раз в неделю и по кнопке, `typecheck lint test --force` | выбран | не трогает `ci.yml` и публикацию; дёшево (около 3 минут в неделю) |
| `schedule:` в `ci.yml` | отклонён | запускает `image`, `publish`, `tag` или требует условий на каждой джобе |
| `--force` на каждом push в `main` | отклонён | каждый merge дольше; ADR-058 убрал `--force` из шага CI намеренно |
| Не нужен, уточнить Confirmation | отклонён | ошибку `inputs` иначе ловит только смена кеша или человек |

## Decision

1. `.github/workflows/cache-check.yml`: по понедельникам в 06:00 UTC и вручную (`workflow_dispatch`); права `contents: read`; одна джоба ставит pnpm (ADR-072), зависимости, проверяет `contracts:check` и запускает `pnpm turbo run typecheck lint test --force` без восстановления кеша.
2. Результат виден владельцу: упавший плановый прогон GitHub присылает письмом; история - вкладка Actions, workflow `cache-check`. Проверка не обязательная (не required check) и PR не блокирует.
3. Падение здесь при зелёном `ci` - ошибка кеша: чинится добавлением файла в `inputs` задачи (ADR-058), а не отключением прогона.
4. Это и есть «периодический прогон с `--force`» из Confirmation ADR-009; ADR-009 и ADR-058 остаются Accepted и не правятся.

## Consequences

- Плюс: устаревшее попадание в кеш находится не позже чем через неделю.
- Минус: около 3 минут Actions в неделю; e2e и сборка образов сюда не входят (у e2e кеша нет, `cache: false`; образы собираются в каждом `ci` заново).
- Минус: письмо о падении получает тот, кто последним менял cron (GitHub); сейчас это владелец репозитория.

## Confirmation

- Локально 2026-11-16: `pnpm turbo run typecheck lint test --force` - 23 задачи, 0 из кеша, все прошли.
- После слияния - ручной запуск `cache-check` и его зелёный результат.

## Revisit when

- Плановый прогон нашёл ошибку кеша дважды: чаще, или `--force` на `main`.
- Появится удалённый кеш Turborepo (ADR-009 его не берёт): прогон нужен и против него.
