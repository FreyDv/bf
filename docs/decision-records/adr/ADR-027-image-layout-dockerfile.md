## Context

- Образ каждого приложения собирается из монорепо (ADR-008, ADR-009) и публикуется в GHCR (ADR-026).
- Нужны: предсказуемость для одного разработчика, кэшируемые слои, образ без лишнего.

## Options considered

| Вопрос | Вариант | Плюсы | Минусы | Итог |
|---|---|---|---|---|
| Базовый образ | `node:26-slim` (Debian) | glibc, нативные модули работают | больше alpine | выбран |
| Базовый образ | `node:26-alpine` | меньше | musl ломает нативные зависимости | отклонён |
| Базовый образ | distroless | мало поверхности | нет shell, тяжёлая отладка, Node отстаёт | отклонён |
| Сборка из монорепо | `turbo prune --docker` + multi-stage | только нужное в образе; слой зависимостей кэшируется | лишний шаг | выбран |
| Сборка из монорепо | весь репозиторий в контекст | проще | любая правка сбрасывает все кэши | отклонён |
| Сборка из монорепо | `dist` собран вне Docker | быстро | окружение сборки и рантайма расходятся | отклонён |

## Decision

1. База: `node:26-slim`, закреплена по digest; digest обновляется PR с кулдауном 7 дней (ADR-005).
2. Dockerfile: `apps/<app>/Dockerfile`, контекст - корень монорепо, `.dockerignore` в корне.
3. Стадии: `prune` (`turbo prune <app> --docker`) -> `build` (`pnpm install --frozen-lockfile`, `build`) -> `runtime`.
4. `runtime`: только prod-зависимости и `dist`; без dev-инструментов и без `pnpm`.
5. Пользователь non-root (`node`); корневая ФС только для чтения, где приложение позволяет.
6. Запуск напрямую `node <entry>`, не через `pnpm start`: SIGTERM доходит до процесса.
7. Healthcheck в Dockerfile нет; пробы задаёт чарт (ADR-019).
8. Backend - один образ на все точки входа (ADR-008); процесс выбирается командой в Helm-значениях.
9. Frontend - Next.js `output: standalone` (ADR-011).
10. В образ не попадают секреты и `.env` (ADR-020, ADR-026).
11. Вспомогательные скрипты сборки - TypeScript через `node`, не bash (ADR-007).

## Consequences

- Плюс: правка кода не пересобирает слой зависимостей; образ содержит только нужное.
- Минус: образ больше alpine и distroless.
- Минус: `turbo prune` может не увидеть workspace-зависимость, если её нет в `package.json`; ошибка проявляется при сборке.
- Дальше: Dockerfile первого приложения (после SCAFFOLD-1); `output: standalone` проверяется в ADR-011 при scaffold.

## Confirmation

Сборка образа в CI (ADR-028); `hadolint` и поиск секретов (ADR-029); ревью: новое приложение использует ту же схему стадий.

## Revisit when

- Нативная зависимость не собирается на glibc-образе или образ мешает размером.
- Нужна отладка в поде, а shell отсутствует (тогда пересмотреть `runtime`).
- Node выходит из LTS (ADR-007).
