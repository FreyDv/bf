# ADR-030: Тег образа в Git: прямой коммит бота в main вместо PR с автослиянием

## Context

- ADR-019, раздел «Тег образа»: CI пишет SHA в `deploy/apps/<app>/image.yaml` через PR с автослиянием после обязательных проверок.
- PR от `GITHUB_TOKEN` не запускает проверки и не сольётся через защиту `main`; ADR-019 требует токен GitHub App.
- Владелец один и осваивает ArgoCD: нужна стандартная, читаемая схема.
- ArgoCD опрашивает Git сам; запускать workflow на коммите с тегом незачем.

## Options considered

| Вариант | Плюсы | Минусы | Итог |
|---|---|---|---|
| Прямой коммит бота в `main` | нет PR, автослияния и проверок на коммит; Git - источник правды; откат `git revert` | бот обходит защиту `main` | выбран |
| PR с автослиянием (ADR-019) | защита `main` без исключений | токен GitHub App, проверки на каждом теге, сложнее | заменён |
| ArgoCD Image Updater, режим `argocd` | токен не нужен | версия только в кластере; откат не через Git; спорно с самоуправляемым ArgoCD | отклонён |
| ArgoCD Image Updater, режим `git` | тег в Git | новый компонент и те же учётные данные записи | отклонён |

## Decision

Заменяет пункт 2 раздела «Тег образа» ADR-019 и строку про токен GitHub App в его «Consequences». Пункты 1, 3, 4 того раздела, чарт, раскладка и миграции действуют без изменений.

1. После публикации образа (ADR-026) job CI пишет SHA в `deploy/apps/<app>/image.yaml` и коммитит напрямую в `main`.
2. Коммитит бот; он единственное исключение из защиты `main`. Коммит меняет только `image.yaml`.
3. Учётная запись бота: встроенный `GITHUB_TOKEN`, если GitHub позволяет сделать его исключением правил ветки; иначе GitHub App с правом `contents: write` и только на этот репозиторий. Что выбрано, проверяется в настройках GitHub и записывается в backlog CI-1.
4. Job обновления тега под `concurrency`: коммиты не гоняются между собой; перед push - `pull --rebase`, при конфликте повтор.
5. ArgoCD: автосинхронизация с `prune` и `selfHeal`; миграции - Pre-sync Job (ADR-019).
6. Откат: `git revert` коммита с тегом.
7. ArgoCD Image Updater не используется.

## Consequences

- Плюс: нет PR, автослияния и токена GitHub App (если подойдёт `GITHUB_TOKEN`); один понятный поток: образ, тег в Git, синхронизация.
- Плюс: версия в проде всегда читается из репозитория.
- Минус: бот пишет в `main` без проверок; ограничение - код workflow, его правки идут через PR и ревью.
- Минус: история `main` содержит коммиты с тегами (как в ADR-019).
- Минус: кривой тег в `image.yaml` ArgoCD раскатит без проверки; страхует `helm template` в сборочном job перед коммитом.
- Дальше: workflow (CI-2); настройка исключения для бота (CI-1).

## Confirmation

Workflow в репозитории; правка workflow только через PR. Что бот коммитит только `image.yaml`, проверяет шаг самого job (diff перед push). Остальное - ревью.

## Revisit when

- Появляется второй разработчик (тогда PR с автослиянием и токеном GitHub App, как в ADR-019).
- Появляется второе окружение и нужно продвижение версии между ними.
- Бот закоммитил сломанный тег в прод.
