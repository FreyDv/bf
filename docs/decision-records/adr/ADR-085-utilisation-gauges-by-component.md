# ADR-085: Виджеты загрузки по компонентам кластера, стопкой на всю ширину (заменяет пункты 2, 5 и 6 ADR-084)

| | |
| --- | --- |
| **Status** | Accepted |
| **Date** | 2026-11-18 |
| **Author** | агент |
| **Decided by** | владелец 2026-11-18 в чате: «вместо platform видеть: kube, Traefik, Prometheus + экспортёры, Grafana, ArgoCD, NATS, DEBEZIUM» и «сделай виджеты больше и размести их вертикально 3 стопки». Как задать группы и раскладку, выбрал агент (ADR-063) |
| **Tags** | observability, metrics, dashboard |

## Context

- ADR-084 собрал в один серый сегмент «Платформа» всё, кроме FE и BE (п. 2), отнёс NATS к BE (п. 5) и поставил три виджета в один ряд (п. 6).
- Владелец хочет видеть, кто именно внутри платформы ест ресурсы: около трети кластера, основная часть его ёмкости, сейчас неразличима.
- Десять сегментов с подписями не помещаются в треть ширины дашборда.
- ADR-084 остаётся Accepted. Его пункты 1, 3 и 4 (плагин, «дуга - выделено, центр - используется», хранилище - только тома) действуют без изменений.

## Options considered

| Вариант | Плюсы | Минусы |
| --- | --- | --- |
| **Группы в коде панели, один запрос `sum by (namespace, pod)`** | 3 запроса на виджет при любом числе групп; правило «кто есть кто» в одном месте; под, не попавший ни в одну группу, виден как «Прочее» | правило - JavaScript в JSON дашборда |
| Отдельный PromQL-запрос на каждую группу | правило видно в запросах | 11 запросов на виджет; под без группы молча пропадает, и сумма перестаёт быть 100% |

## Decision

1. **Сегменты** (заменяет п. 2 ADR-084): FE, BE, NATS, Debezium, kube, Traefik, «Prometheus + экспортёры», Grafana, ArgoCD, «Прочее» и Free. «Прочее» показывается, только когда в него что-то попало. Free - ёмкость без всех остальных сегментов. Доли по-прежнему от одной ёмкости и дают ровно 100.0%.
2. **Кто есть кто** (заменяет п. 5 ADR-084). Правило задано по namespace и имени пода, для хранилища - по имени тома; срабатывает первое подходящее:

   | Сегмент | Правило |
   | --- | --- |
   | FE | `bf`, `frontend-*` |
   | BE | `bf`, `backend-*` |
   | NATS | `bf`, `nats-*` (сервер и nats-box) |
   | Debezium | имя `debezium*` в любом namespace; пока не установлен (CDC-2), сегмент 0 |
   | kube | namespace `kube-*`: Cilium, CoreDNS, агенты DO, контроллер Sealed Secrets |
   | Traefik | `traefik` |
   | Prometheus + экспортёры | `monitoring`, всё, кроме `grafana*` |
   | Grafana | `monitoring`, `grafana*` |
   | ArgoCD | `argocd` |
   | Прочее | всё остальное |

   Запросы: `sum by (namespace, pod)` requests работающих подов (CPU, память) и `sum by (namespace, persistentvolumeclaim)` занятого на томах. Группирует код панели.
3. **Раскладка** (заменяет п. 6 ADR-084): три виджета стопкой, каждый на всю ширину дашборда. Дуга слева, легенда справа таблицей, по строке на сегмент: цвет, имя, процент, абсолютное значение. На самой дуге подписаны сегменты от 3%, остальные видны в легенде и в подсказке при наведении. Графики ADR-083 - ниже трёх виджетов, без изменений.
4. **ArgoCD на дуге - 0.** У его подов нет requests: он ничего не резервирует, хотя использует около 760 МиБ памяти. Его использование видно в центре и на графиках ниже.

## Consequences

- Хорошо: видно, какая часть кластера сколько резервирует, и новый под без правила не пропадает.
- Плохо: виджеты стали выше, графики теперь ниже первого экрана.
- Плохо: переименованный или новый компонент попадёт в «Прочее», пока правило в коде панели не поправят.

## Revisit when

- В «Прочее» что-то попало: нужна новая строка в таблице п. 2.
- У ArgoCD появятся requests: его сегмент перестанет быть нулём.
- Debezium встанет с другим именем пода, чем `debezium*` (CDC-2).
