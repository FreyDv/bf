## Context

- `bfdb` - управляемый Postgres 18 DigitalOcean (runbook `bfdb-postgres.md`), один узел `db-s-2vcpu-4gb`, диск 60 ГиБ. Таблиц приложения ещё нет.
- ADR-083 п. 10 уже назвал источник для алерта на WAL: `postgres_exporter` под ролью только на чтение (`LOGIN`, `pg_monitor`), SQL роли применяет человек (красный флаг 1). Сам алерт на WAL - в CDC-3.
- Изнутри Postgres не видно сервера базы: CPU, памяти, диска. Остановленный потребитель слота держит WAL на этом диске без предела (`max_slot_wal_keep_size=-1`, ADR-021).
- У DO есть эндпоинт метрик кластера базы для Prometheus: `https://<хост>:9273/metrics`, базовая аутентификация, логин выдаёт API (`GET /v2/databases/metrics/credentials`, токен с правом записи), тот же список доверенных источников, что у подключений. Только Standard Edition. Хост публичный. Имена метрик DO не публикует (docs.digitalocean.com, «How to Monitor PostgreSQL Clusters», прочитано 2026-11-18).

## Options considered

| Вариант | Видит | Не видит |
| --- | --- | --- |
| **Оба источника** | всё ниже | - |
| Только `postgres_exporter` | соединения по состояниям, транзакции, строки, кэш, размеры баз, блокировки, deadlocks, временные файлы, долгие транзакции, слоты и WAL | CPU, память и **диск** сервера |
| Только эндпоинт DO | CPU, память, диск, load, часть статистики Postgres | список метрик не опубликован; слоты и WAL в нём не найдены (ADR-083 п. 10) |

## Decision

1. **Оба источника.**
2. **`postgres_exporter`**: чарт prometheus-community `prometheus-postgres-exporter` 8.2.5 (экспортёр v0.20.1, вышел 2026-11-10, карантин ADR-005 прошёл 2026-11-17), Application `postgres-exporter` в `monitoring`, файл `deploy/argocd/postgres-exporter.yaml`. Подключение: приватный хост, порт 25060, база `bf`, `sslmode=verify-full` с CA проекта DO (ADR-053). Коллекторы - по умолчанию; `_dodb` и шаблоны исключены. Без токена сервис-аккаунта, без RBAC, не root, корень только на чтение.
3. **Роль `monitor`**: создаёт DO (`doctl databases user create`), права - `database/roles/03-as-doadmin-monitor.sql`, применяет владелец: `CONNECT` на `bf` и `pg_monitor`, а если `doadmin` не может выдать `pg_monitor` (Postgres 16+ требует опции ADMIN) - каждую из трёх входящих в неё ролей. Ни данных, ни записи.
4. **Эндпоинт DO**: задание Prometheus `bfdb-do`, `https`, `basic_auth` из файлов, `tls_config.ca_file` - CA проекта. Опрос раз в минуту. Доступ: кластер уже доверенный источник `bfdb` (правило `k8s`); пускает ли оно на порт 9273 - проверка после выката.
5. **Секреты**: один SealedSecret `bfdb-monitoring` в `monitoring` (`DATA_SOURCE_PASS`, `DO_METRICS_USERNAME`, `DO_METRICS_PASSWORD`; запечатан `scripts/seal-secret.ts`, ADR-060) и ConfigMap `bfdb-ca` с CA - в `deploy/monitoring/bfdb/`, третьем источнике Application `prometheus`. Под Prometheus монтирует только два ключа эндпоинта, пароль экспортёра в него не попадает.
6. **Дашборд «Postgres»** (ConfigMap `postgres-dashboard`, свой провайдер): верхний ряд - доступна ли база, соединения от предела, попадание в кэш, размер `bf`, самая долгая транзакция, WAL в слотах; графики - соединения по состояниям, транзакции, строки, кэш, размеры баз, блокировки, deadlocks и временные файлы, слоты, долгие транзакции. Ряд сервера базы (CPU, память, диск) - по метрикам DO, после первого сбора.
7. **Алерты** (группа `bfdb`): «База bfdb недоступна» (`pg_up < 1` 5 минут, critical); «Соединений больше 80% от предела» (10 минут, warning); «Диск bfdb занят больше 80%» - по метрике DO, после первого сбора. Экспортёр или эндпоинт, который не отвечает, уже ловит «Цель сбора метрик недоступна» (ADR-083).

## Consequences

- Хорошо: виден диск базы и WAL слотов, главный риск CDC (ADR-021), до того, как Debezium встанет.
- Хорошо: роль `monitor` нужна и CDC-3, вторая роль для мониторинга не понадобится.
- Плохо: логин эндпоинта DO, судя по пути API, общий на аккаунт; смена его (`PUT /v2/databases/metrics/credentials`) требует перезапечатать секрет.
- Плохо: имена метрик DO неизвестны до первого сбора; панели сервера и алерт на диск дописываются отдельно.
- Риск: экспортёр опрашивает базу раз в 30 секунд; на `db-s-2vcpu-4gb` это доли процента CPU (не измерено).

## Revisit when

- DO опубликует имена метрик или переведёт кластер на Advanced Edition (эндпоинта там нет).
- Появятся таблицы приложения: включать ли `stat_statements` (самые дорогие запросы, нужно расширение `pg_stat_statements`).
- CDC-2 создаст слот: порог алерта на WAL - CDC-3.
