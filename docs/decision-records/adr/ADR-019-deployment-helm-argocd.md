# ADR-019: Деплой: общий Helm-чарт app и ArgoCD, манифесты в deploy/

## Context

- Приложения (ADR-008) выкатываются в кластер `malinina` (ADR-017).
- Деплой ведёт ArgoCD: сверяет кластер с Git.
- Нужно решить: где лежат манифесты, как устроен чарт, как попадает тег образа, как применяются миграции.

## Options considered

| Вопрос | Вариант | Плюсы | Минусы | Итог |
|---|---|---|---|---|
| Манифесты | `deploy/` в этом репозитории | один PR на код и деплой | коммиты с тегами образов в `main` | выбран |
| Манифесты | отдельный GitOps-репозиторий | чистая история деплоя | второй репозиторий со своими правами | отклонён |
| Чарт | один общий чарт `app` | один подход для всех (ADR-018) | общий шаблон сложнее | выбран |
| Чарт | чарт на приложение | проще читать | шаблоны копируются и расходятся | отклонён |

## Decision

**Раскладка.**

```
deploy/
  charts/app/               общий чарт: Deployment, CronJob, миграционный Job, SealedSecret
  apps/<app>/values.yaml    несекретная конфигурация приложения
  apps/<app>/secrets.yaml   зашифрованные значения (ADR-020)
  apps/<app>/image.yaml     тег образа, который обновляет CI
  argocd/                   ArgoCD-приложения
  sealed-secrets/           открытый сертификат (ADR-020)
```

**Чарт.**
1. Приложение не пишет шаблонов: только значения (образ, порты, переменные, расписание).
2. Хеш секретов - в аннотации Deployment: смена секрета перезапускает поды.
3. Версия чарта фиксируется; сторонние чарты в `deploy/argocd/` закреплены точно (ADR-005).

**Миграции на проде.**
1. Применяет миграционный Job с хуком Pre-sync перед выкаткой новой версии; секреты БД не покидают кластер.
2. Упавшая миграция останавливает синхронизацию; работающая версия остаётся.
3. Ни агент, ни CI на PR не пишут в боевую БД (красный флаг 1).

**ArgoCD.**
1. Ставится в кластер вручную один раз (bootstrap, описан в runbook - ADR-017), дальше управляет всем из `deploy/argocd/`, включая себя.
2. Компоненты кластера (ingress, cert-manager, NATS и др.) добавляются отдельными записями, когда выбраны.

**Тег образа.**
1. Образ собирается при merge в `main` (ADR-018).
2. CI записывает тег по SHA в `deploy/apps/<app>/image.yaml` через PR с автослиянием после обязательных проверок.
3. Сборочные workflow игнорируют изменения этого файла, чтобы не запускать себя по кругу.
4. Откат деплоя - `git revert` PR с тегом; схема только вперёд (ADR-013).

**Проверка чарта** - `helm lint` и `helm template` для всех приложений:
1. Pre-commit: последним шагом после границ, только если staged есть файлы `deploy/`.
2. CI на PR: если менялся `deploy/`, после границ.
3. Helm - локальное требование разработчика (AGENTS.md).

## Consequences

- Плюс: один PR на код и деплой; новое приложение - значения, не шаблоны; откат - откат коммита.
- Плюс: упавшая миграция не раскатывается.
- Минус: история `main` содержит коммиты с тегами образов.
- Минус: PR от `GITHUB_TOKEN` не запускает проверки и не сольётся через защиту `main` - нужен токен GitHub App.
- Дальше: чарт `app` (backlog CHART-1); токен бота (CI-1); Helm в предварительных требованиях AGENTS.md (SCAFFOLD-1).

## Confirmation

CI красный при ошибке `helm lint`/`helm template`; ревью: новое приложение не добавляет собственные шаблоны.

## Revisit when

- Появляется второе окружение.
- Коммиты с тегами образов начинают мешать в истории `main` (тогда отдельный GitOps-репозиторий).
