# ADR-037: Базовая безопасность: ответ на каждую ось security-baseline.md

## Context

- R7 и R19 требуют записанный ответ по каждой из 16 осей [`security-baseline.md`](../../standards/vendor/repository-standards-core/method/security-baseline.md): ось, которую не рассматривали, и ось, которую сняли сознательно, через год неотличимы.
- Часть осей уже закрыта записями (секреты, зависимости, права CI, проверка входа); часть не закрыта; две (аутентификация, авторизация) принадлежат другой строке бэклога.
- Репозиторий и образы публичные (ADR-026): всё, что лежит в репозитории или слое образа, читает любой.
- Кода приложений и приложений в кластере ещё нет, поэтому «не применимо на старте» - честный ответ там, где нет поверхности атаки.
- Состояние GitHub и реестра сверено командами чтения 2026-11-12; что не проверено - сказано в строке.

## Options considered

| Развилка | Выбрано | Отклонено |
|---|---|---|
| Форма | один ADR, таблица «ось / ответ / где живёт»; решённое - ссылкой (R4) | несколько ADR по группам осей: размазывает R19 |
| Аутентификация, авторизация | именованная отсрочка в AUTH-1 с уже известными инвариантами | выбрать механизм здесь: дублирует AUTH-1 |
| TLS | принять TLS на балансировщике и http в VPC как записанный риск | TLS до подов (cert-manager, re-encrypt): новая зависимость и ADR, сложность для двух человек |
| Лимиты частоты | периметр ingress-nginx, без библиотеки в приложении | библиотека в NestJS: новая зависимость, состояние между репликами |
| Уязвимости зависимостей | Trivy report-only, срок исправления критичного 7 дней | блокирующий Trivy: надо заменять ADR-029, блокирует одного человека |
| Бэкапы | записать как непроверенные, дать строку на restore-тест | заявить 7 дней и PITR как факт для `bfdb`: не проверено |
| Adversarial testing | не применимо на старте | fuzz-харнесс без кода: нет цели, новая зависимость (PRG-3) |

## Decision

1. Таблица ниже - ответ по каждой из 16 осей. Ответ бывает: решено (ссылка), решено здесь, принятый риск, именованная отсрочка, не применимо.
2. **Именованная отсрочка - ответ**, если названа строка бэклога, которая её решает, и записано, что уже известно. Пустая ячейка ответом не считается. Так уточнён DoD строки SEC-1 («каждая ось отвечена или не применимо»): отсрочки в таблице - AUTH-1, OBS-1, SEALED-1, STACK-2, CI-1, PRIVACY-1.
3. Другие записи эта не заменяет: ADR-020, ADR-026, ADR-029, ADR-030, ADR-036 действуют как были; здесь они только связаны.

| Ось | Ответ | Где живёт |
|---|---|---|
| **Secrets** | Решено ADR-020: Sealed Secrets, строгая область, закрытый ключ копией только в менеджере паролей владельца, при утечке ключа меняются сами значения. Уточнение: CI публикует образы встроенным `GITHUB_TOKEN` (ADR-026), токена реестра в GitHub Secrets нет; что лежит в GitHub Secrets (токен для коммита тега, ADR-030), решает CI-1. Секреты ловят gitleaks в CI и GitHub secret scanning с push protection (включены, проверено `gh api` 2026-11-12). **Отсрочка:** период ротации и происхождение пары ключей - SEALED-1 (контроллер не установлен). | ADR-020, ADR-026, `.gitleaks.toml`, SEALED-1, CI-1 |
| **Authentication** | **Отсрочка в AUTH-1.** Известно: два раздельных аккаунта (Даня, Валерия), права раздаёт Даня позже (владелец 2026-11-11); покупатель без аккаунта, заказ ведёт по номеру телефона (рассказ владельца 2026-11-11: направление, не решение, AUTH-1 подтверждает). Вход ChatGPT через MCP не решён; подтверждено владельцем только что ChatGPT не публикует, не платит и не удаляет без владельца, полный список вызовов отложен до первой MCP-спеки. Срок жизни сессий и отзыв - AUTH-1. | AUTH-1, `docs/PRODUCT.md` (Non-goals), `docs/personas.md` |
| **Authorization** | **Отсрочка в AUTH-1.** Известно: права выдаёт Даня; авторизация применяется вне фильтра вызывающего, `WHERE scope AND (filter)`, фильтр клиента её не заменяет (QRY-17). Модель (роли, области, политики) и место применения (сервис, БД) - AUTH-1. | AUTH-1, `query-filter-rules.md` |
| **Input validation** | Решено: граница - request DTO с Zod, ошибки собираются вместе (ADR-012, VAL-1..6, ADP-8); домен держит охранные проверки (DOM-E3); строки БД валидируются при маппинге (VAL-4); фильтры - allowlist с пределами вложенности и списков (QRY-3, QRY-16). **Отсрочка:** проверка загружаемых файлов (видео и аудио курсов) - STACK-2 (хранилище, не решено) и спека возможности «курсы». | ADR-012, ADR-024, `architecture-rules.md`, STACK-2 |
| **Output and injection** | Решено: SQL только параметрами Drizzle, `sql.raw` запрещён (QRY-15, ADR-013); ответы - whitelist DTO (ADP-4); ошибки без трассировки и чувствительных метаданных (ERR-6). Данные запроса не подставляются в строку SQL и в команду оболочки: процессы запускаются массивом аргументов, без shell. **Отсрочка:** вывод недоверенного текста покупателя (заметки заказа, адреса, телефоны) в интерфейсе владельца не решён; спека каждой возможности, показывающей такой текст, заполняет trust boundaries (стандарт). | ADR-013, ADR-024, `architecture-rules.md`, спеки возможностей |
| **Transport and headers** | **Принятый риск:** TLS завершается на DO Load Balancer (сертификат `malinina-ca`, Let's Encrypt), дальше http от балансировщика к узлу внутри VPC `default-tor1`; трафик в VPC не шифруется. Причина: сквозной TLS - новая зависимость и ADR для команды из двух человек, явной угрозы внутри VPC нет. Слой заголовков и лимитов - ingress-nginx (стоит с 2026-11-03). Значения HSTS, CSP и прочих заголовков, запись о выборе ingress как компонента (ADR-019: компоненты кластера - отдельными записями; Cilium Gateway API тоже есть в кластере) и исключение бота для коммита тега - CI-1. | `docs/runbooks/malinina-kubernetes.md` (находка 7), CI-1 |
| **Rate limiting and abuse** | Периметр: аннотации ingress-nginx `limit-rps` и `limit-connections` ([документация](https://kubernetes.github.io/ingress-nginx/user-guide/nginx-configuration/annotations/)); лимит считается по IP клиента и отдельно на каждую реплику контроллера (реплик 2, эффективный предел выше). IP клиента берётся из PROXY protocol или `X-Forwarded-For` при `use-forwarded-headers`; как это настроено за балансировщиком DO, в репозитории не записано, до проверки лимит может считать адрес балансировщика - проверка в CI-1. Прикладных библиотек лимита нет (новая зависимость требует ADR). Поиск, изменение и отмена заказа по телефону - вектор перебора номеров (вывод из рассказа владельца, не измерение): лимиты на эту процедуру пишутся в раздел abuse cases спеки этой возможности. Реализация аннотаций - INGRESS-1. | INGRESS-1, CI-1, спека lookup по телефону |
| **Logging and privacy** | Принципы: телефон, адрес доставки, секреты и токены не попадают в логи и метрики; список скрываемых полей задан в pino-адаптере (ADR-032 п. 4, ERR-6); метаданные ошибок без персональных данных. **Отсрочка:** срок хранения логов, потолок цены, доступ к Grafana - OBS-1 (владелец отложил 2026-11-11). Правовой режим и удаление данных покупателя в корпусе не записаны - PRIVACY-1. | ADR-032, OBS-1, PRIVACY-1 |
| **Dependencies** | Решено ADR-005: точные версии, lockfile, кулдаун 7 дней, новая зависимость - ADR. Обойти кулдаун можно в двух случаях: критичное исправление безопасности (ADR-005 п. 4) и образ локальной среды, чья версия уже работает в managed-сервисе DO (ADR-034). Аудит: владелец читает отчёт Trivy в summary CI (HIGH и CRITICAL с исправлением, не блокирует, ADR-029); критичная находка с доступным исправлением исправляется в течение 7 дней после того, как попала в отчёт или оповещение. Trivy становится блокирующим с появлением второго разработчика (триггер ADR-029). Dependabot alerts выключены (`gh api .../vulnerability-alerts` вернул 404, security updates `disabled`, 2026-11-12); включает владелец - GHSET-1; version updates не включаются. | ADR-005, ADR-029, ADR-034, GHSET-1 |
| **CI permissions** | Решено ADR-036: триггеры `push` в `main` и `pull_request`, без `pull_request_target`; `contents: read` сверху; `packages: write` только в job `publish`; секрет в workflow один - `GITHUB_TOKEN` в `publish`, jobs PR секретов не читают. Остальные workflow: `spec-guard` и `gitleaks` - `contents: read`; `standards-update-watch` - `contents: read` и `issues: write` (по cron заводит issue; единственное исключение). Actions закреплены по SHA. Защита `main`: squash, `enforce_admins`, обязательные проверки `ci`, `image`, `spec-guard`, `secret scan`, без force-push. Токен по умолчанию read-only и без права одобрять PR, запуск от первых контрибьюторов требует одобрения (всё проверено `gh api` 2026-11-12). | ADR-036, `docs/runbooks/github-settings.md`, `.github/workflows/` |
| **Agent boundaries** | Оставлено как есть: deny и ask в `.claude/settings.json`, хуки `PreToolUse` (no-remote-db-writes, no-force-push, no-ci-secret-writes, elicitation-guard), самотест `scripts/verifyAgentGuards.sh`. Известные пробелы: нет `kubectl`, `helm`, `doctl`, `kubeseal`; запись через `gh api` кроме `DELETE` (`PUT`, `PATCH`, `POST`) не закрыта; записи прототипа (fly, cdk, terraform, aws, prisma) безвредны. Закрытие - AGENT-1. | `.claude/settings.json`, `.claude/hooks/`, AGENT-1 |
| **Data at rest** | Бэкапы - управляемые бэкапы DO: по [документации](https://docs.digitalocean.com/products/databases/postgresql/how-to/restore-from-backups/) раз в день, хранятся 7 дней, восстановление создаёт новый кластер; PITR [ограничен 7 днями](https://docs.digitalocean.com/products/databases/postgresql/details/limits/). У `bfdb` на 2026-11-10 шесть копий. **Восстановление не проверено**, срок хранения и PITR у `bfdb` не проверены: на бэкапы не полагаться, пока BACKUP-1 не выполнен. Шифрование диска и бэкапов у DO в найденной документации не заявлено: считается непроверенным, проверка входит в BACKUP-1. Доступ к базе: доверенные источники - кластер и адрес владельца (DBSEC-1), SSL включён; приложение подключается под `doadmin`, единственной ролью, - отдельная роль и проверка SSL - DBSEC-3; `synchronous_commit` - DBSEC-2. Хранилища, которые ещё не стоят (PVC NATS, чанки Loki в Spaces, слот Debezium), получают ответ в записи, которая их ставит: NATS-1, OBS-2, STACK-2, CDC-3. | `docs/runbooks/bfdb-postgres.md`, BACKUP-1, DBSEC-2, DBSEC-3 |
| **Adversarial testing** | **Не применимо на старте:** кода и поверхности атаки нет (`apps/backend` - пустые `main.ts` и `app.module.ts`), harness без кода - спекулятивная абстракция (PRG-3). Вместо него: в спеку каждой возможности про деньги, доступ и персональные данные входит раздел abuse cases; тесты фильтров (QRY-18) и поведенческие тесты слайсов (TST-1, TST-2) растут вместе с кодом. Пересмотр - TEST-1 и первая спека, принимающая недоверенный ввод. | TEST-1, `query-filter-rules.md` |
| **Threat model** | **Активы:** закрытый ключ Sealed Secrets (ADR-020); слот Debezium и диск `bfdb` (WAL без предела, ADR-021); данные заказов, телефоны и адреса покупателей; пароль БД и ключ OpenAI (ADR-020); право менять `main` и workflow (всё, что попало в `main`, ArgoCD выкатывает, ADR-030). **Противник:** оппортунист из интернета (сканеры, перебор телефонов, нагрузка на публичную витрину); утечка из публичного репозитория или слоя образа; ошибка владельца или агента; недоверенный текст (заказ, видео и аудио курса), который доходит до ChatGPT через MCP или до OpenAI (средства защиты - спеки MCP и курсов). **Цена для владельца:** утечка данных покупателей, простой продаж, ротация всех секретов. **Вне модели:** целевая атака на DigitalOcean как провайдера, физический доступ к машине владельца. | эта запись |
| **Embargoed work** | Репозиторий публичный (проверено 2026-11-12), ответ нужен. Исправление ещё не раскрытой уязвимости разрабатывается во [временном приватном форке security advisory GitHub](https://docs.github.com/en/code-security/security-advisories/working-with-repository-security-advisories/about-repository-security-advisories), не в публичной ветке, issue или PR. Спека, строка бэклога и запись CHANGELOG пишутся там же, пока идёт работа (R3), и входят в `main` вместе с исправлением. До этого mainline не несёт ничего об уязвимости. Условие снятия: исправленный образ опубликован. Снимает эмбарго владелец, публикуя advisory; условие и владелец называются в момент начала эмбарго. **Сейчас приватные отчёты не работают:** private vulnerability reporting выключен (`gh api .../private-vulnerability-reporting` вернул `{"enabled":false}`, 2026-11-12), а `SECURITY.md` отправляет отчёты туда; включает владелец - GHSET-1. | `SECURITY.md`, GHSET-1, SPEC.md R3 |
| **Negative scope** | Не считается уязвимостью (список от 2026-11-12, пересматривается при событиях ниже): отсутствие HA у control plane и `bfdb` (один узел); ручное обновление Kubernetes; находки Trivy без доступного исправления; http внутри VPC от балансировщика до подов (принятый риск, строка Transport); публичность исходного кода и версий зависимостей. | эта запись |

4. **Жёсткость подов - политика.** Под, который ставит общий чарт `app`, запускается не от root, с `seccompProfile: RuntimeDefault`, `allowPrivilegeEscalation: false`, `capabilities.drop: [ALL]`, `readOnlyRootFilesystem` и `automountServiceAccountToken: false`. Всё это в чарте уже есть (`deploy/charts/app/templates/_helpers.tpl`, `deployment.yaml`, ADR-027). Не хватает NetworkPolicy; применяет ли её Cilium в кластере, не проверено. Реализация - CHART-3.
5. **Новые строки бэклога** этой записью: CHART-3, BACKUP-1, GHSET-1, AGENT-1, INGRESS-1, DBSEC-3, PRIVACY-1. CI-1 сужен: TLS-риск решён здесь.

## Consequences

- Плюс: ни одна из 16 осей не пуста; решённое связано, а не пересказано (R4); будущая спека берёт из таблицы готовый ответ про trust boundaries и abuse cases.
- Минус: аутентификация и авторизация закрыты отсрочкой, а не механизмом; первую спеку с доступом нельзя брать в план до AUTH-1.
- Минус: восстановление `bfdb` и шифрование диска не проверены; до BACKUP-1 потеря базы может оказаться невосстановимой.
- Минус: трафик от балансировщика до подов не шифруется; образ с известной уязвимостью может попасть в прод, заметит его только тот, кто читает отчёт Trivy.
- Минус: приватные отчёты об уязвимостях сейчас не работают, пока владелец не включит их (GHSET-1).
- Минус: решения приняты агентом по общему поручению владельца, не по каждому пункту; владелец может опровергнуть любой пункт новой записью.
- Дальше: строки, названные в Decision п. 5; отсрочки закрываются в AUTH-1, OBS-1, SEALED-1, STACK-2, CI-1, PRIVACY-1.

## Confirmation

Машинной проверки у базовой безопасности нет (стандарт её не вводит). Подтверждают: gitleaks в CI; `pnpm deps`; `pnpm charts` и `pnpm charts:test` для чарта; `bash scripts/verifyAgentGuards.sh` для хуков; защита `main` проверяется командами из `docs/runbooks/github-settings.md`; ревью спек на раздел trust boundaries и abuse cases. Не подтверждено ничем: восстановление `bfdb`, шифрование диска, NetworkPolicy в кластере, IP клиента за балансировщиком, включение приватных отчётов.

## Revisit when

- Появляется второй разработчик: Trivy блокирует (ADR-029), права и ревью пересматриваются.
- AUTH-1 принят: строки Authentication и Authorization заменяются ссылкой на запись.
- Подключается внешний платёжный провайдер или публикуется витрина с поиском заказа по телефону: пересмотреть http внутри VPC и лимиты.
- BACKUP-1 показал, что восстановление не работает или срок хранения меньше записанного.
- Реальный инцидент, либо репозиторий становится приватным (эмбарго и negative scope теряют смысл).
