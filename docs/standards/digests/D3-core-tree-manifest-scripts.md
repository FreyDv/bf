# Repository Standards — shipped tree, manifest, guards and scripts — fact-preserving digest

Sources: `docs/file-map.md`, all 50 `docs/tree/*.md` pages, `standard/standard.manifest.json`, the shipped config/elicitation/workflow files, every script under `standard/scripts/` and every hook under `standard/.claude/hooks/`. Project: Repository Standards (repositorystandards.com); `standard/` is the tree an adopting repo receives. Standard's own ADRs are cited as "standard ADR-NNN"; the adopter's numbering starts at ADR-001 and never meets the standard's.

Vocabulary used throughout (from file-map.md / manifest `adaptRules`):
- `copy` — "ship verbatim; the repo gets a byte-for-byte copy (guards, templates that carry no repo-specific content)"; content-checked by sha256.
- `merge` — "combine the standard's content with what the repo already has, keeping both (ignore files, CI that already has jobs)"; may declare `requiredKeys`.
- `fill-from-repo` — "scaffold the shell from the standard, then author the body from THIS repo's reality - never blind-copy the example prose (ARCHITECTURE, PRODUCT, specs)".
- `reference` — "do not copy; link to the living standard - always latest (standard ADR-004/025)".
- Needed: `required` = a miss is drift; optional = a note. Profile `core` = every repo; `scale` = teams. An entry with no profile counts as core.

## 1.1 docs/tree/agents-md.md — `AGENTS.md`
- Required, core, `fill-from-repo`, R1. Required headings: Altitude; The loop runs itself (unprompted); Volunteer, don't wait to be asked; Say where you are.
- "The first file your coding agent reads, and the single source of truth for how this repo works." Cursor reads it natively; Claude Code reaches it through a thin `CLAUDE.md` router; Codex and the rest read it directly.
- "Everything else points here. Nothing else restates it." — "the moment two files describe the same convention, one of them is wrong and nobody knows which."
- Purpose: "So an agent arrives competent instead of curious." Carries the one instruction that makes the standard work: "before acting on a request, check whether a skill owns it." A user should never have to say "remember to use the skills".
- Six things, shipped as empty slots "because nobody else can fill them": the repo map (one line each); commands (install, dev, build, test, the checks); conventions (merged from `docs/conventions.md`, the canonical block); red flags (numbered list of things that must stop an agent and fetch a human); the working language (which artefacts in which language); hard bans.
- Red flags must be concrete; example list: 1. Writing to a remote database (DML/DDL/migrations) — deliver a .sql instead. 2. Contradicting an Accepted ADR — propose a superseding ADR first. 3. Adding a dependency without a decision record. 4. Force-pushing a branch someone else has pulled.
- Does not go here: a copy of anything (rule in `docs/conventions.md` → AGENTS.md carries merged block, CLAUDE.md points here; "Restating it in a third place is drift with a delay"); product knowledge (what = specs, why = decision records; this file says how work is done); anything an agent cannot act on ("Aspiration reads as instruction and gets followed").
- "`CLAUDE.md` and `.cursor/rules` are routers, not homes." A rule written into one applies to one agent silently.
- Usage: written during alignment from the repo's own reality, then edited like a living document, e.g. `> we never write raw SQL against staging - add it to the red flags`.
- Decisions: one entry point, the rest routers (this is R1, not a decision record); "The empty slots ship empty" — plausible defaults were tried and are worse: a default reads as decided, nobody revisits it, "commands that were never true".

## 1.2 docs/tree/backlog-md.md — `backlog.md` (alt `docs/backlog.md`)
- Required, core, `fill-from-repo`, R15.
- "The single ordered list of work the repo knows it still owes itself" — features plus the documentation, spec and decision debt brownfield onboarding surfaced.
- Markdown, in the repo, agent-first: readable/appendable/re-orderable without an API token; survives whatever tracker you use.
- Purpose: "So that noticing something and not fixing it is a recorded act."
- Row shape (file declares more columns — see `docs/backlog.md`): `| Id | Intent | For whom | Source | Done when |`, e.g. `| INV-4 | Export retries on timeout | Ops lead Ola | asked: #212 | a timed-out export resumes without a manual replay |`.
- Rules: an intent names its persona ("internal work names the internal one rather than borrowing a customer"); names its source, "one of five declared categories" ("every item has a source" is only a rule while it is a column somebody has to fill); names what done looks like (an item without that never leaves).
- At `scale`: an **In flight** section: which intents left the pool and into which sprint. "An intent is in the pool or in exactly one sprint, never both, and `sprint-guard` fails the build when that stops being true." The guard checks the table too: each row must name a sprint that exists and is still open, and state how many intents it really holds.
- Does not go here: a mirror of your tracker (repository holds intents, tracker holds execution history, one-way bridge; running without a board is a real option — see docs/method/tracking-work.md); ideas (`docs/ideas/`); anything without a done condition ("Improve performance" is a feeling; "The export finishes under 30s for a 10k-row account" is an intent); a custom backlog engine (format is compatible with the Backlog.md tool).
- Usage: `> the booking export has no retry and dies on a timeout - not fixing it in this change, write it down so we do not lose it` — agent files it with source, role that has to act, and done.
- Decisions: backlog lives in the repo (tracker fails because brownfield debt is about the code and must be readable by the agent working in the code); every intent names a persona and a done condition (optional meant absent); standard ADR-028 — pool and sprints are one system.

## 1.3 docs/tree/changelog-md.md — `CHANGELOG.md` (alt `docs/CHANGELOG.md`)
- Required, core, `fill-from-repo`, R18. Required heading `Unreleased`.
- "The record of what changed, in developer language, and the only place change history accumulates." Entry shape:
  ```
  ## Unreleased
  ### A headline saying what changed and for whom (YYYY-MM-DD)
  What was wrong, what it is now, who it affects.
  ```
- Purpose: "So that a release is a deliberate act rather than a side effect of merging." A PR describes its change; the maintainer promotes `Unreleased` into `## x.y.z - <date>` and moves the version, once. Checked at two levels: file exists, and `Unreleased` heading is in it.
- No other document grows a history section: spec, ARCHITECTURE, runbook describe the present; git holds every past state; this file holds the curated record.
- Goes in: prose aimed at a person deciding whether the release touches them (one or two paragraphs beat commit subjects); every change (complete and mechanical). `RELEASE-NOTES.md` is a different, curated plain-language output written at release — "not the changelog with the boring lines removed".
- Does not go in: a version heading or bump ("A PR that writes `## 1.4.0` has decided a release happened"); internal codes (ticket ids, rule numbers, backlog identifiers); a second mechanism (a per-PR fragments folder was tried and removed — conflicts resolve in seconds by keeping both lines; nothing enforced the folder).
- More than one changelog — two independent axes (standard ADR-044), "never conflate them":
  - Multiple release lines (maintained `1.x` beside `main`'s `2.x`): one changelog per line, each with its own `Unreleased`; a PR writes under the heading on the branch it targets and bumps that line's version, PATCH by default.
  - Multiple independently-versioned, independently-publishable units from one tree (rails/rails's thirteen gems, each with its own CHANGELOG.md in its directory): one changelog per unit; a PR writes under every unit it touches and bumps each, PATCH by default; a change spanning two gems gets two entries and two bumps, one per file.
  - A repo can face either, both, or (the common case) neither — one root `CHANGELOG.md`.
- Decisions: "R18 - a PR describes its change under `Unreleased` and bumps the version itself, PATCH by default." Owner directs a different bump or explicit no-bump per PR; same rule extends to release lines and units, never a second mechanism. (Note: the manifest/file-map purpose text for this entry instead says a PR "never touches the version - R18's one path, at every profile"; both statements are in the sources.) "R25 - the PR that promotes `Unreleased` moves the version", and the version is one fact restated nowhere unchecked. R4 — history does not accumulate inside living documents.

## 1.4 docs/tree/claude-hooks.md — `.claude/hooks`
- Optional, core, `copy`, R19.
- Shell guards that run before a tool does: a write against a remote database, a force-push onto a branch someone else pulled, a secret about to be committed. "These are not linters. A linter tells you afterwards; a hook refuses."
- Two properties: **They fail closed** — a hook that cannot load its library or whose dependency is missing denies; "A guard that fails open is worse than no guard, because it is trusted." **They are tested** — a guard prints only when it refuses, so a broken one is silent; hence `scripts/verifyAgentGuards.sh`, run after any change in here. Empirical: an earlier version pasted as one long line into a settings file carried three bypasses nobody spotted ("nobody reads a nine-hundred-character line").
- Goes in: a check that is cheap, deterministic, and safer to enforce than to remember. Each guard splits the command on `;`, `&&`, `||`, `|` and newlines and asks **per segment** whether that segment reaches something dangerous — otherwise a harmless local call glued in front of a destructive remote one vouches for the whole string.
- The segment must not decide whether the command is destructive: the remote-database guard once required host and write verb in the same segment; a pipe, a backslash line-wrap and a heredoc each put them in different segments, so `psql -h prod \` on one line and `-c "DROP TABLE users"` on the next ran unchecked. "Where a command reaches is per segment; what it does is read across the whole string."
- Does not go in: anything slow; anything needing the network; anything prone to a false refusal ("A guard that blocks legitimate work gets disabled... This is the real failure mode, not the missed catch").
- Surprise: a guard reads the text of the command, so it refuses a command that merely contains a destructive example (docs with a sample `psql` line against a remote host). Write the file with a file tool rather than a heredoc.
- Decisions: guards are scripts in `hooks/`, not one-liners in settings; fail closed always; one dispatcher `guards.sh` finds siblings by its own path — `settings.json` used to name each guard via `$CLAUDE_PROJECT_DIR`, and with it unset the shell exits 127 with empty stdout, "which Claude Code treats as a non-blocking error and runs the command anyway"; the dispatcher turns a missing, unreadable, or nonzero-exiting (syntactically broken) guard into a denial; its own absence is covered by the `||` in `settings.json`; unknown SQL is refused, not guessed at (`psql -h prod -c "$(cat migration.sql)"` — a guard that cannot read the command has not checked it, same rule as missing `jq`); host matching is case-sensitive deliberately (`psql` lowercase `-h`; uppercase `-H` is curl's header flag; case-insensitive matching blocked local work combining the two).

## 1.5 docs/tree/claude-md.md — `CLAUDE.md` (alt `AGENTS.md`)
- Optional, core, `merge`, R1.
- "A router, not a home." Claude Code loads it first; its job: send the agent to `AGENTS.md` and state the rule that must arrive before anything else — check whether a skill owns this request before acting. Non-Claude agents: whatever the tool reads first carries the same two sentences.
- Goes in (almost nothing): read `AGENTS.md` first (source of truth); check the skills before acting, and again when the work is done; the note that `.standards-version` records a bookmark rather than a version you are held at.
- Does not go in: any rule — conventions, red flags, commands, branching model live in AGENTS.md; a rule here applies to Claude Code only. "This is the most common way a repo's instructions rot."
- Why the skills reminder is here and not only in AGENTS.md: it must land before the agent forms a plan. Repeated at the end too: closing steps most easily skipped — reconciling the spec against what you built, filing what you noticed and did not do, reviewing your own diff before pushing.
- Decisions: routers point, never hold; the skills rule is stated twice on purpose ("Repetition is normally a defect in this standard. Here it is load-bearing").

## 1.6 docs/tree/claude-settings-json.md — `.claude/settings.json`
- Optional, core, `merge`, R19. Required keys (manifest): `permissions.deny`, `hooks.PreToolUse`.
- The agent's permission baseline: which commands run without asking, which are refused outright, which hooks fire before a tool executes.
- Goes in: three lists and the hook wiring — **allow** for the ordinary, **ask** for things worth a pause, **deny** for what must never happen — and the `PreToolUse` hooks for cases a pattern cannot express.
- Does not go in: a rule the guards should enforce (a permission pattern matches a command string; does not understand intent, working directory, or which host — that belongs in a hook that reads the whole command and splits on `;`, `&&`, `||`, `|`); secrets or paths outside the repository (the file is committed).
- Two failure modes: blanket `ask` on something routine trains the reflex that defeats every later prompt (allow it, put real protection in `deny`); "One Bash call, one command" — the matcher evaluates the whole string, so two individually-allowed commands joined by `&&` still prompt; fix: separate calls, not a broader pattern.
- Decisions: `merge` not `copy` (the standard contributes a baseline); "Deny beats narrow allow" (enumerating every safe path is unbounded; naming the handful that must never happen is not).

## 1.7 docs/tree/claude-skills.md — `.claude/skills` (alt `.agents/skills`)
- Required, core, `copy`, R22. Content-checked per member (24 shipped SKILL/support files).
- "The standard as executable procedures." One directory per skill, each holding a `SKILL.md`: describing a feature, breaking it down, building it, closing it, reviewing your own branch, ingesting meeting notes, moving to a newer standard. "These ship with the tree and stay. They are not scaffolding you delete after adoption."
- Bet: prose methodology gets read once and applied differently; a procedure gets executed.
- Rule for a new skill: not the count — whether its `description` names a situation, "in words a user would actually type", that no other skill's description names. "The description is the only text a request is matched against." Two overlapping descriptions each lose the sentence about half the time. Write about when to reach for it, never the artefact: good — `Use when the user describes a feature, story or behaviour change and the repo needs a capability spec written or updated.`; bad — `Writes a capability spec file.`
- `docs/skill-map.md` lists every skill grouped by the moment it fires, generated from the skills' own frontmatter.
- Goes in: a procedure run repeatedly whose step order matters. Does not go in: a one-off migration (a script); anything specific to your product's domain (stops being updatable with the standard); anything duplicating a skill already here.
- Non-Claude agent: these are the reference form; port strictly and completely before claiming compliance; "`self-verify` accepts the ported location. A partial port is drift rather than a variant".
- Decisions: standard ADR-019 (procedures ship executable; partial port is drift); skills stay after adoption ("the loop is the product, not the setup"); descriptions are the interface (not names users must remember).

## 1.8 docs/tree/claude.md — `.claude/`
- Directory holds "procedure and guardrail, never knowledge". What is true lives in `docs/` and `specs/`, readable without an agent and versioned with the code.
- Inside: `skills/` (lifecycle as procedures; each fires on its own when the request matches its description); `hooks/` (guards before a tool runs); `settings.json` (permission lists and which guards are wired in).
- Does not go in: anything a person needs to read to understand the product (a decision → decision record; behaviour → capability spec; "A rule that exists only in this folder is invisible to everyone not running Claude Code"); repo-specific product knowledge; a one-off migration.
- Non-Claude: the whole directory is the reference form; port strictly; `self-verify` accepts the ported location; partial port is drift.
- Decisions: standard ADR-019; procedure here, knowledge in `docs/` (keeping both in the agent folder makes the product unreadable to anyone not running the same agent).

## 1.11 docs/tree/docs-architecture-md.md — `docs/ARCHITECTURE.md`
- Optional, core, `fill-from-repo`, R1.
- Structure: pieces, boundaries, what talks to what. Peer of `specs/`: "`ARCHITECTURE.md` never says what a booking does; a spec never says which service owns it."
- Purpose: "So a newcomer, human or agent, can locate a change before making it."
- Levels: **Context** (what the system is and what it talks to that it does not own); **Containers** (deployable pieces — services, workers, database, queue — and what runs where); **Components** (inside each container, modules and allowed dependencies; where boundaries get stated); **Code** — deliberately skipped (code and specs are the truth at that level; diagram stale within a sprint).
- Does not go in: behaviour (specs); decisions (why Postgres over Mongo is an ADR; this file records that it is Postgres and links the record); aspiration; screenshots of diagrams (keep diagrams as text — Mermaid, ASCII, anything diffable).
- Usage: authored at adoption from the repository's reality; edited when structure moves (`> we split the export worker out of the API - update the architecture`).
- Decisions: structure and behaviour separate files; code level skipped on purpose; no TDR stream ("living technical design" is structure here or behaviour in a spec).

## 1.12 docs/tree/docs-conventions-md.md — `docs/conventions.md`
- Optional, core, `merge`, R1.
- The canonical conventions block: rules "too small to be decisions and too real to leave unwritten". Ships as a separate file merged into `AGENTS.md` at adoption; AGENTS.md is the living home; this file is the delivery mechanism.
- Purpose: rules where reversing costs a search-and-replace, not a rewrite — not decision records.
- Shipped block (verbatim content):
  - Conventional Commits, ticket after the colon; no AI/tool attribution; ASCII hyphen only; small focused PRs.
  - **Branch and history (R23):** branch off main and base every PR on main; update by rebase, never merge main into your branch.
  - **Comments:** explain why, never what. Match the density of the file you are editing. If a comment restates the line below it, delete it.
- Two worth calling out: "The working language is a configuration, not a constraint" — decide per artefact and write it down (code and commits in English, docs in the team's language, user-facing copy in the persona's); "A fact has one home (R4)" — a count, version, path, command lives in one file, everywhere else links; where a restatement must exist, declare it in `docs/facts.json` and a guard fails when they stop agreeing ("twenty rules" outlived the twenty-first by weeks).
- Does not go in: anything contestable (decision record); anything the guards already enforce mechanically, unless a person needs to know before the guard fires; restatements in a third file (do not copy into `CLAUDE.md` or `.cursor/rules`).
- Decisions: standard ADR-012 — in-repo instructions are the source of truth; personal memory, global agent configs and chat may point at repo rules, never hold them; a rule only outside the repo is treated as missing ("'It is in my memory' is not a location"); conventions ship as a file and end up merged (otherwise updating conventions is a three-way merge inside a heavily edited AGENTS.md).

## 1.13 docs/tree/docs-decision-records.md — `docs/decision-records`
- Required, core, `fill-from-repo`, R5. Also a manifest `reference` ("decision-records-guide", R5).
- "If a decision has no record it does not exist: reviewers and agents treat undocumented divergence as a red flag."
- Two streams: **ADR** asks why, technically; folder `adr/`; overruled by an architect. **BDR** asks why, for the business; folder `bdr/`; overruled by a product owner. "When you cannot tell which, ask who would overrule the decision. When both would, write the BDR and let the ADR reference it."
- Goes in: a contestable, re-litigable trade-off. One file per decision, `ADR-NNN-slug.md`, "three digits, gapless, never reused". A retired record is marked `Superseded` or `Withdrawn`, never deleted.
- Example (ADR-014: One authored tree) sections: `**Status:** Accepted`, `**Date:**`, `## Context`, `## Decision`, `## Options considered` (numbered, rejected with reason), `## Consequences`, `## Revisit when`. "That example is the target length, not a simplified version of one." Length is a cost; a section with nothing to say gets one line; "A draft that runs long is usually arguing for the decision rather than recording it."
- `Revisit when` names the concrete signal that would reopen the decision — "the difference between a record and an opinion".
- `Confirmation` belongs to both streams: how you would find out the decision is not being kept (a guard, test, CI check, review step, the spec it changed) — distinct from `Revisit when` and, in a BDR, from `How we would know we were wrong`. Naming where compliance is checked is not designing it (the ADR's job).
- Does not go in: how it behaves (capability spec); how it is built (ARCHITECTURE.md; no TDR stream); a settled way of doing things (search-and-replace cost = convention in AGENTS.md; rewrite cost = decision; a significant choice usually produces both); a maybe (`Proposed` = awaiting ratification; speculation → `docs/ideas/`); the standard's own decisions (an `ADR-0NN` reference inside a shipped file points at the standard's; "Your repo's records start at `ADR-001` and the two numbering lines never meet").
- Usage: `> we agreed on Postgres over Mongo yesterday, mainly for the reporting joins - write it up`; `> we need a queue for the export jobs - record the decision first`. Agent drafts with the options it can find, trade-offs, recommendation; asks only what it cannot work out; you approve; it flips to `Accepted`. Wrong accepted record: `> ADR-014 says one tree; we are splitting it - supersede it` — new record supersedes; old keeps its text plus a `Superseded by` line.
- Altitude ("Which wins when two documents disagree"): `PRINCIPLES.md` → ADR/BDR → `specs/<capability>` (behaviour) + `ARCHITECTURE.md` (structure) → conventions, agent rules, skills → code. Higher wins; code disagreeing with an accepted record is a stop-and-propose.
- Decisions: records immutable once accepted; standard ADR-010 — nothing is a record until approved; no TDR stream; at most three options per record ("More is analysis paralysis wearing a template").

## 1.14 docs/tree/docs-discovery.md — `docs/discovery`
- Optional, core, `fill-from-repo`, R5.
- "The inbox of a topic." One folder per subject holding provenance-stamped extracts of meetings, mails, findings a spec will be written from.

## 1.25 docs/tree/docs-sprints.md — `docs/sprints`
- Optional, scale, `fill-from-repo`, R15.
- A sprint: bounded work with an owner, a goal, an end date everybody agreed to; one file per sprint at `docs/sprints/<team>/<slug>.md`. Goal in one sentence, end date once; "When the date arrives the sprint closes, whether or not the work finished." Every intent names its current holder.
- Example: `# Dispatch, sprint 4`, `**Goal:** ...`, `**Ends:** 2026-08-15`, `**Owner:** Maja`, `## Intents` table `| id | title | assignee | size | status |` with rows `INV-2 ... doing`, `INV-3 ... blocked:INV-2`.
- Three things are the guard's interface (an earlier version of this page got all three wrong, so a real duplicate was reported `OK - each in exactly one`):
  - Rows live under `## Intents` — exactly that H2 (a deeper level is not the same heading); `sprint-close` writes a second table of the same ids under `## Outcome`; a sprint file without `## Intents` is an error, not an empty sprint.
  - The id is its own first cell, matched by its column's name (`INV-2` with the title in the next column; `INV-2 Reassign an active route` in one cell is reported as unreadable); the guard reads whichever column the header calls `id`; a table with no `id` column falls back to the first one; backticks or bold around the id are fine.
  - The status is the last cell, whatever columns are added. Blocking has no column: `blocked:INV-2` goes in the status cell and the guard fails when that id does not exist, is already finished, or is the row itself. `split:INV-2b` (what `/sprint-close` writes) counts as finished for that check and is checked the same way: the remainder must be a row that exists and is not this one.
  - The title is the other half of the id: read from the column named `title`; one title in two files under two ids is one intent in two places; a `split:<id>` pair may share a title, nothing else may.
- `Size` is a cold-start ranking signal only, never converted into a duration (standard ADR-029); once closed sprints exist the forecast comes from measured durations. An intent that does not finish is split, never re-sized.
- Does not go in: the backlog (pool or exactly one sprint, never two sprints — standard ADR-028); a running commentary (closing note by `sprint-close`, or a decision record); a person's whole week (support rotations, reviews, interrupts).
- Usage: never by hand — `/sprint-open` (move chosen intents out of the pool, with a goal and a date) and `/sprint-close` (check each intent against its done, return what did not). Skipping `sprint-close` "destroys the only data the next forecast has".
- Decisions: standard ADR-028 sprints are the team layer (scale; solo repos skip); standard ADR-029 measurement forecasts, sizes are the cold start, story points rejected, "no blended mode"; standard ADR-030 the holder is state, not history (one current holder, overwritten on reassignment; git is the audit log).

## 1.38 docs/tree/scripts-self-verify-mjs.md — `scripts/self-verify.mjs`
- Required, core, `copy`, R16. Run `node scripts/self-verify.mjs`. Prints **drift**: how many required entries are unmet. Zero and exit 0 = compliant with the manifest; anything else exits 1 with the list.
- Order of checks: the recorded state, then files (names; for verbatim-shipped ones, content), then the keys a merged file must keep, then required headings, then the guards. Each result printed; "It never stops at the first failure."
- `copy` entries hashed against the manifest `sha256`; present-but-different is reported as *differs* not *missing*; a deliberate change is recorded as a `content` exception.
- Flags: `--warn` (exit 0 regardless; drift unchanged — "A flag that lowered the drift number would make the number negotiable"); `--profile core|scale` (one profile's entries only); `--skeleton` (the pristine shipped tree — no recorded state, no guards, no placeholder scan).
- Does not certify: the mechanical tier only (file there, content the standard's where it owns it, heading there, guard passes). Judgment (records record real decisions; a spec serves its persona) stays at review. A `fill-from-repo` file is your content — only presence and template markers are checked.
- Placeholder scan warns about unfilled `<markers>`, `{{TOKENS}}` and table rows still made of ellipsis cells; never counts as drift ("converting judgment into an integer is how a metric starts being gamed"). A row of empty cells is not a marker.
- Convention: "Angle brackets in prose mean replace me; angle brackets in code formatting are notation." Fenced blocks and inline code stripped before the scan (otherwise `specs/<capability>` in the shipped AGENTS.md could never clear it). Cost: a real marker hidden inside backticks goes unseen — templates keep fill markers in prose.
- Decisions: manifest-driven ("A new requirement is a manifest entry, not a release of this script"); everything reported before exiting; warnings never add to drift.

## 1.39 docs/tree/scripts-spec-guard-mjs.md — `scripts/spec-guard.mjs`
- Required, core, `copy`, R11 ("the tool ships at core, the blocking CI gate is scale").
- Fails a PR in which a capability's code changed and its spec did not. Commands: `node scripts/spec-guard.mjs --base origin/main --block` and `node scripts/spec-guard.mjs --audit --block`; both run on every PR.
- Audit reads tracked files and untracked files git is not ignoring; it used to read only the tracked list with a filesystem fallback when git listed nothing, so one tracked spec hid every new directory.
- How it decides: reads `specs/capability-map.json`, turns each glob into a regex (`**` any path, `*` within a segment), matches changed files; a capability whose code matched and whose `specs/<capability>/` did not = failure.
- Qualified entry `{"glob": "config/rules.json", "couples": "shape"}` fires on key-structure change, not values. A glob starting with `!` excludes (sibling capability inside a claimed folder). Where `$unclaimed` is declared, diff mode also reports a changed file no capability claims and `$unclaimed` does not declare. `{"external": "<repo>", "reason": "..."}` = implementation in another repository; nothing enforced; audit names it on every run.
- Cannot catch: a spec edited to say nothing; an unmapped capability in diff mode (hence the audit); changes outside the map in a repo that declares no `$unclaimed`.
- Surprise: compares commits, not the working tree — an uncommitted spec fix shows as a failure until committed.
- Decisions: per-PR, no bypass ("in the same PR" is what makes "update the spec before implementing" real); globs rather than a build-tool dependency graph (Layer 1 is stack-agnostic).

## 1.40 docs/tree/scripts-spec-structure-mjs.md — `scripts/spec-structure.mjs`
- Required, core, `copy`, R16 (guard entry cites R10). Run `node scripts/spec-structure.mjs --block`.
- Refuses: a spec that serves nobody (persona from `docs/personas.md`; `**Serves:**` checked against the roster, not merely for being filled); a roster it cannot read (rows without backticks, placeholder never filled → run fails; "an empty roster would otherwise pass every spec"); a spec shaped like a ticket (`001-feature/`); a spec missing the sections of its declared tier — `**Spec tier:** buildable` must carry `## Data contracts`, `## Interface contracts`, `## Acceptance criteria`, each with something under it (a non-applicable section keeps its heading and says so, like `## Open questions` says "None known."); `behavioral` is the escape hatch (R9); no tier declared → warned, not blocked; a section heading written twice (the clarify gate greps for the first `## Clarifications`; a later session is a new `### Session YYYY-MM-DD`).
- Ignores: `/spec-plan` and `/spec-tasks` scaffolding — `plan.md`, `tasks.md`, `research.md`, `data-model.md`, `quickstart.md`, `contracts/`, `checklists/` — ephemeral (standard ADR-010), not held to the persona gate; a PR between `/spec-plan` and `/spec-reconcile` legitimately carries all of it; in full-tree mode reported as a warning (still committed after close = cleanup did not run).
- The roster is a table because a guard has to read it; the worked example stays out of the table.
- Decisions: standard ADR-006.

## 1.41 docs/tree/scripts-spec.md — `scripts/spec`

## 1.42 docs/tree/scripts-sprint-guard-mjs.md — `scripts/sprint-guard.mjs`
- Optional, scale, `copy`, R15. Run `node scripts/sprint-guard.mjs --block`. A repo without sprints has nothing to check.
- Refuses: the same intent in two places; the same intent in two places under two ids (title check; the one legitimate pair, `split:<id>` and its remainder, is exempt); a block pointing at nothing or at finished work (`blocked:INV-3` checked against intents that exist, including `split:<id>` rows which count as finished); a split whose remainder was never cut (`split:INV-2b` with no INV-2b row); a closed sprint still holding what it did not finish; a pool pointing at a closed sprint or counting it wrong (`## In flight` table; `/sprint-open` writes the row, `/sprint-close` removes it; once the table holds any row, an open sprint nothing points at is caught too).
- Row reading: status from the last cell; title from the column named `title`, falling back to the cell after the id, compared with markup stripped and whitespace collapsed; block and split references resolved without regard to case and reported in the row's own spelling (`ADR-auth`, `INV-2b` are documented id shapes; uppercasing failed `ADR-auth`); block checks run with or without sprints present.
- Decisions: standard ADR-028; the invariant is mechanical, not a convention.

## 1.43 docs/tree/scripts-verifyagentguards-sh.md — `scripts/verifyAgentGuards.sh`
- Optional, core, `copy`, R19. Run `bash scripts/verifyAgentGuards.sh` after any change under `.claude/hooks/`; CI runs it on every push and PR (it "used to exist and be called by nothing").
- Why: a guard prints only when it refuses; a broken guard is silent. The inline one-line version carried three bypasses.
- Covers: real command strings — chained, quoted, local calls glued before remote destructive ones, hostnames crafted to look like loopback; both directions asserted; ordinary spellings — a pipe, a backslash line-wrap, a heredoc, an absolute path, `-hHOST`, `PGHOST` in the environment ("Every one of those shapes was a live bypass while this file reported that all guards behave as specified").
- Decisions: guards are scripts, not JSON one-liners; both directions checked; a denial has to be well-formed deny JSON (any non-empty stdout used to count); a nonzero exit or unexpected stderr is a failure of its own, not a verdict; the scoring is checked against guards that are deliberately wrong.

## 1.46 docs/tree/spec-md.md — `SPEC.md`
- Optional, core, `copy`, R2 (sha256-checked).
- The whole standard as numbered rules on one page; every rule is MUST, SHOULD or MAY. "When a doc, a guard and this page disagree, this page wins, and the other two are the bug."
- R21 quoted as the example: everything a repo consumes MUST be pinned exact and move only by an explicit, reviewed diff — dependency manifests and overrides carry exact versions (no ranges), sealed by a committed lockfile; container images, CI runners and actions name an exact version or digest, never `latest`, never a floating tag; a new version SHOULD clear a release-age cooldown (paved road seven days); a critical security fix MAY bypass the cooldown through a recorded, temporary exclusion.
- MUST is compliance; SHOULD is the paved road you can leave with a recorded reason; MAY is yours; the escape hatch is written into the rule.
- Does not go in: anything technology-specific (Layer 1 is stack-agnostic by rule); explanation (why = decision record, how = method); counts of itself (`tree-check` fails a surface that hand-writes the rule count).
- Connection: `standard.manifest.json` is the machine-readable projection; a rule becomes an entry, a check, a number. "A rule with no manifest entry is advice; an entry with no rule is a check nobody can justify."
- Decisions: one page, numbered; rules are stable identifiers, never renumbered (a removed rule leaves its number retired); obligation levels explicit.

## 1.47 docs/tree/specs-capability-map-json.md — `specs/capability-map.json`
- Required, core, `fill-from-repo`, R11. "Without it the coupling guard exits zero and quietly checks nothing."
- One key per capability matching the folder under `specs/`, with its code globs; example `payments: ["**/payment/**", "**/payu/**", "shared/**/payment*"]`, `bookings: [..., { "glob": "config/booking-rules.json", "couples": "shape" }]`. `**` any path, `*` within a segment. `"couples": "shape"` fires only on key-structure change.
- `!` excludes: `payments: ["**/payment/**", "!**/payment/refunds*"]`, `refunds: ["**/payment/refunds*"]`. An exclusion cannot make a file vanish: `--audit` reports what it hands over if no other capability picks it up, and reports the exclusion itself when it stops matching anything. Co-located tests already covered.
- Does not go in: a capability with no spec; globs so broad they match everything (`src/**`); globs so narrow they match nothing.
- "The failure that has no symptom": an unmapped capability is never considered — `spec-guard --audit` runs on every PR for that reason.
- Usage: authored at adoption from the example; extended per capability (`> add the notifications capability to the map - the code is under src/notify and shared/mail`).
- Decisions: standard ADR-011 (map is core, enforcement scales); globs, not a build-tool integration; qualified entries instead of excluding config files.

## 1.48 docs/tree/specs.md — `specs/`
- Required, core, `fill-from-repo`, R8. Also a manifest `reference` ("spec-writing", R8, "how to write a capability spec - the tiers, the contracts, what makes buildable checkable (R8, R9)").
- "SPEC = the current truth of a CAPABILITY, not SPEC = the description of a ticket." Edited in place forever; `main` always says what production does.
- One folder per capability named after the domain concept (`specs/bookings/spec.md`, `payments/`, `availability/`). A large capability may split (`specs/bookings/{overview,lifecycle,modifications,cancellation}.md`) but stays one domain.
- Every spec names the persona it serves (from `docs/personas.md`) and in one line how; "A spec that serves nobody is a candidate for deletion, not for merge." A rule helping one persona and hurting another → a recorded BDR the spec cites.
- Buildable is the default: "An engineer or an agent could implement and verify this capability from the spec alone, without reverse-engineering the code." Carries contracts: exact schemas and enums, every endpoint with inputs/outputs/errors, algorithms as implementable steps, state machine as a transition table, flags that change behaviour, acceptance criteria in Given/When/Then. "Contracts quote real identifiers verbatim." Escape hatch `behavioral`: prose invariants and edge cases; must declare itself in the header and carry a one-line justification.
- Does not go in: tickets (`specs/001-booking/`, `specs/017-booking-change/`); pages and routes (a concept appearing on three pages is one spec; surfaces are cross-references); versions (`payments-v2`); history (git holds the evolution); ticket language ("This feature adds...", "in RL-123 we...").
- Two rules easy to skip: every capability needs an entry in `capability-map.json` (unmapped = rots silently); a behaviour change and its spec update land in the same PR (guard is per-PR, no bypass).
- Loop of skills: `/spec-specify` (one capability, from what you said), `/spec-clarify` (questions until nothing open), `/spec-impact` (which other capabilities this ripples into), `/spec-update` (edit every affected spec to the target state), `/spec-plan`, `/spec-tasks`, `/spec-implement`, `/spec-reconcile` (spec == code == tests, specs agreeing with each other). The gate is `/spec-clarify`: no open markers of the `[NEEDS ...]` family — a missing decision, input, or asset works like an unanswered question. An open question the work answered gets closed in the same PR.
- Decisions: standard ADR-002 (by capability, never per ticket or page); standard ADR-006 (names its persona); git is the change mechanism (a separate change-folder model was built and removed — branch spec is target truth, `main` is current truth, diff is the delta); no plans or tasks competing with specs (when a plan and a spec disagree, the spec wins).

## 1.49 docs/tree/standard-manifest-json.md — `standard.manifest.json`
- Required, core, `copy`, R2 (no sha256 — a file cannot hold its own hash).
- "The machine-readable projection of the spec"; `self-verify` reads nothing else. Adding to the standard is data, not a release; only a change to how an entry is interpreted is an engine change.
- Five arrays (example JSON with `"version": "1.0.0"`): **`files`** (what must exist; each carries the rule it enforces); **`sections`** (a heading inside a file); **`guards`** (a command that must exit zero); **`decisions`** (noted, never checked — judgment); **`references`** (method docs by reference, noted and never existence-checked).
- Fields: `adapt` (`copy` verbatim / `merge` reconciled / `fill-from-repo` authored shell); `profile` (`core` or `scale`; none = core); `required` (drift vs note; belongs to `files` and `sections` only — a `decisions` entry carrying it is refused because R7 "names no subset and asserts no count"); `sha256` (what a `copy` entry must hash to — string for a file, one hash per member for a directory; generated by `tools/manifest-hashes.mjs`, asserted by `tools/tree-check.mjs`; works offline because hashes travel in the manifest copy; without them "19 of the 20 skills, or last version's `SPEC.md`, satisfied" the entry); `requiredKeys` (for `merge` entries; dotted key paths that must survive — presence only, JSON objects or YAML block mappings; for hook wiring, workflow triggers, supply-chain policy blocks); `exceptions` (your repo's recorded deviation: `file`, `section`, `content`, `key`, each with a `reason`; not drift; never raises the adoption percentage; cannot be used on a guard's own script).
- Does not go in: anything requiring judgment; prose (`purpose` is one line for the generated map); your repo's own additions — a stack adds `stack.manifest.json` beside it, concatenated into one drift number; `stack.<technology>.manifest.json` per stack where more than one coexists.
- Decisions: standard ADR-005; `decisions` and `references` noted, never checked.

## 1.50 docs/tree/standards-version.md — `.standards-version`
- Required, core, `fill-from-repo`, R2.
- One line, one version number: the state of the standard the repo last aligned to. "A bookmark, not an anchor." Answers one question: where the next update measures its delta from (an update is a delta, not a re-scaffold).
- Content: `1.0.0`. Written by the alignment skill and updated by the update skill; never edited by hand.
- Not a pin (latest is the only target; no supported way to stay on 0.9; tags exist to track the standard's own development); not a version you request (`@<version>` or `--version` in a quickstart is documentation that predates the decision and is a bug); not a compatibility claim (compliance is what `self-verify` reports).
- "Missing this file costs two drift points rather than one": failed to record which state it follows, and failed to carry the file that says so.
- Decisions: standard ADR-025 (version pinning was the original model and was removed; the word "pin" was swept out of every live surface — last four occurrences were in a JSON description, a script's usage comment, and the two entry files an agent reads first); a weekly watch, not an auto-update (`standards-update-watch.yml` never edits this file).

## 2.1 `standard/standard.manifest.json` — schema

Top-level keys (in file order):
- `$about` (string) — the manifest's own documentation. Facts it states:
  - "The align-engine manifest (standard ADR-005). The align/update/self-verify skills read THIS to know what an aligned repo must have - instead of hardcoding it in prose or JS."
  - Paths are the client layout, identical to the `standard/` tree in the standards repo.
  - `since` names the release that first shipped an entry; "unreleased rides the next cut".
  - An aligned repo carries a copy of this file matching the state it last aligned to (a bookmark, never a version it stays at — standard ADR-025); `scripts/self-verify.mjs` checks the repo against it and reports drift as a number.
  - Method docs are adopted BY REFERENCE, never copied; the `references` section names them at their home (standard ADR-004/023); self-verify notes them, checks no files.
  - Top-level `profile` (core|scale, standard ADR-011) ships set to `scale` ("check everything"); align rewrites it in the repo's copy from the intake's answer; self-verify and the shipped CI gate both read it and both fall back to `scale` when missing, "so a copy that lost the field is checked at the stricter tier rather than the looser one and self-verify says the field is absent instead of defaulting in silence".
  - Normative source is SPEC.md; each entry cites the rule it enforces (`rule`).
  - Content fields: a `copy` entry carries `sha256` — a hash string for a file, one hash per member for a directory — generated by `tools/manifest-hashes.mjs`, verified by `tools/tree-check.mjs`, never hand-written; self-verify hashes the local file against it (CRLF normalized to LF; the manifest itself carries none since a file cannot hold its own hash; a member missing from a directory entry is reported the same as a changed one, "so a required item quietly removed is a content failure, not a silent pass"). A `merge` entry MAY declare `requiredKeys` — dotted key paths that must be present in the merged result (JSON objects and YAML block mappings; presence only, never a value).
  - `exceptions` shape: `{ "kind": "file"|"section"|"content"|"key", "match": "<path>" for a file or its content, "<file>#<heading>" for a section, "<file>#<key.path>" for a key, "reason": "..." }`. self-verify reports it as excepted rather than drift (R17), keeps it in the adoption denominator "so excepting can never raise the percentage", prints the count in the summary. Bounded: no `guard` kind ("a guard is a live check - waiving its verdict removes it instead of recording a deviation from it"); a guard's own script cannot be excepted by `kind: "file"` (a missing guard script is skipped, so that would disable a blocking check at drift 0 — use `kind: "content"`, which keeps the guard running); an exception with no `reason` is not a recorded one.
  - `provenanceCommit` (standard ADR-052): the standards repo's full commit SHA this copy last aligned to; ships `null`; `align-to-standards`/`update-to-latest` write it on every successful run; the delta is computed from it; `.standards-version` stays the human-facing bookmark.
  - `removedPaths` (standard ADR-052): append-only list of `{ path, since, note }` for paths the standard removed — hand-maintained at release time like CHANGELOG.md, never generated from a tree diff; self-verify fails a repo that still has a listed path on disk, waivable only through `exceptions`.

- `version`: `"1.0.19"`.
- `provenanceCommit`: `null`.
- `layer`: `1`.
- `profile`: `"scale"`.
- `adaptRules`: `copy`, `merge`, `fill-from-repo`, `reference` (definitions quoted at the top of this digest).
- `files[]` — entry fields: `path`, `purpose`, `adapt`, `required`, `profile`, `since`, `rule`; optional `altPaths[]`, `sha256` (string, or object member→hash), `requiredKeys[]`.
- `references[]` — `id`, `path` (in the standards repo), `purpose`, `since`, `rule`.
- `sections[]` — `file`, `heading`, `purpose`, `required`, `profile`, `since`, `rule`.
- `guards[]` — `id`, `run`, `kind` (`static` | `diff`), `blocks`, `purpose`, `profile`, `since`, `rule`. (self-verify additionally understands an optional `requires: [{ "kind": "command"|"path", "match", "hint" }]` on a guard — see Part 3.)

## 2.6 `standard/.claude/elicitation/README.md`
- "The places this standard must ask a person instead of deciding for them, and the shape every one of those questions takes." `points.json` is the declaration; three layers read it, each catching what the previous lets through:
  - `elicitation-points-check` — proves every declared point has a call site somewhere in a skill; runs on every pull request, against a baseline that may only shrink.
  - `elicitation-check` — the answers in a finished run were really given, and the quotes were really said; against a session transcript, after the fact.
  - `.claude/hooks/elicitation-guard.mjs` — the artifact is not written until its question fired; at the moment of the write, "and it is not the agent's decision". Only the third is unskippable, and only the third is useless on its own ("it knows a question happened, not whether the answer was honoured").
- Why a mechanism, not advice: the rule existed as prose (`onboard.md`: mark inferred work unconfirmed, put the interview in the backlog) and did not hold — a full adoption wrote five personas, appended a section to thirty-three owner-written records, seeded a twenty-item backlog with owners, moved `docs/ADR` and `docs/BDR` under the standard's directory name across seventy-eight files, and quoted the owner declaring a full migration in a sentence he never typed. One question was asked (about duplicated hooks), because duplication was the only thing mechanically visible. "A skill that says 'ask' has no way to ask. `AskUserQuestion` blocks once it is called - the gap was never in the blocking, it was in reaching the call."
- The shape — every question offers the same three answers, in this order: **answer** (person decides now → `human`); **suggest** (agent proposes, person checks later → `provisional` + a backlog row naming the point; artifact opens with the `[NEEDS REVIEW]` marker); **stub** (placeholder, do not guess → `absent`; artifact opens with the same marker naming what belongs there).
- `suggest` is not a way around the question; it counts as human presence (attributable, timestamped, marked artifact). The failure prevented: "the agent proposed something and the record reads as though a person agreed".
- A run with nobody watching takes the third answer: writes the stub, declares the point `absent`, leaves the gap visible; the run reads as unfinished. `inferred` is narrower than it sounds and most points refuse it ("concluding a preference from a repository is guessing with a better name"). A handful of points refuse the stub too (who the repo is for, what the owner meant by the adoption) — an unattended run stops there. "Not asking is allowed; not asking and shipping an answer anyway is not."
- "The options are never the whole answer space" — the question tool always lets a person type their own; in the first live run, asked to pick `core` or `scale`, somebody wrote "several people, no sprints, tasks taken off a backlog". Take it as the answer, record what they actually said, and fix the question.
- The marker: the provenance row records `suggest`/`stub` but not which artifacts it wrote or whether anyone confirmed them (one `suggest` can draft twelve retroactive decision records; record eleven reads `Status: Accepted`). So every file written under `suggest` or `stub` opens with one marker directly under the title (standard ADR-057, revised by standard ADR-058: one marker, not two):
  - `> [NEEDS REVIEW] drafted by the adoption run on 2026-09-03 from the route table and \`roles.js\`. Backlog: PERSONAS-1.`
  - `> [NEEDS REVIEW] nothing written here yet; should hold the datastore decision and why. Backlog: ADR-013-1.`
  - Always the same two things follow: what it was drafted from (or what belongs there for a stub) and the backlog row that tracks it. Who acts is not named (the record's kind says it: ADR technical, BDR and `docs/personas.md` product). A drafted decision record stays `Proposed`, never `Accepted`.
  - The marker leaves with the review and nothing else (no `verified-by`, no date); `git log` says who removed it; a commit stripping the marker while changing nothing else "is not a review, it is a chore someone cleared". `self-verify` counts every marker still in the tree next to the adoption percentage without moving it (standard ADR-038); `elicitation-provenance` requires the backlog row every marker names to exist.
- Which answer leads: the first option is the recommended one and is the one the question labels as recommended — "order and label are the same claim"; where the tool renders a label, no other option may carry it. It is "always the answer that converges on the standard - its layout, its shape, the whole of it" and, where that is not the axis, the answer a person gives now rather than defers. Declared per point as `recommended`; `elicitation-points-check` fails when the skill offers something else first. Measured on a live adoption, four of five recommendations pointed at the least convergent answer, including "keep your own layout and map the standard onto it".
- A point asked down more than one path declares all of them: `skill` and `file` both take a list; `elicitation-points-check` requires a call site in each and the same recommended answer in each (the same specification question is put by the skill that writes Requirements, the one that clarifies, the one that changes, the one that reconciles).
- "It binds every question, not only the twenty-two declared here" — the agent invented an undeclared question (where tracked work lives) and recommended keeping the parallel tracker.
- Keeping the repository's own way must stay on the list (a standard imposed without consent gets reverted) but is never the default; `null` is reserved for a question with no such axis: "consent is asked, never recommended".
- Language: the question is put in the language the person is writing in, from their first message — never a point itself. `[adopt.language]` is a point: the language the artifacts are written in (an unasked slot in `AGENTS.md` since the beginning). `elicitation-points-check` compares the skill's written option order against `recommended`; it cannot compare what was spoken.
- Carrying the id: every `AskUserQuestion` call names the points it asks in `metadata.source`, space-separated (never seen by the person; header reads as prose — **Layout**, not `[adopt.layout]`). The bracketed `[id]` in the header is still read (transcripts before 1.0.4; adopted repos on older skills). Without the id the replay layer can only count questions — "count is exactly the metric that let eighteen missing questions look like a working product".
- What the guard refuses: a `Write` or `Edit` to a gated path unless one of three holds — that point's question already fired in this session; the content declares the point `absent` (`adopt.personas: absent`, frontmatter or JSON key); or the point is repository-scoped and the committed ledger already records an answer. A `Bash` command that moves a path git already tracks is refused under `adopt.layout` (renaming is legitimate and offered as the first answer; doing it without asking is what broke fifty-three links). An untracked file the adoption created is the run's own to move. Fails closed: no transcript = refused.
- Cannot bootstrap itself: a `PreToolUse` hook binds when the session starts; an adoption lands the hook, `points.json`, the `PreToolUse` matcher and the ledger before writing anything else, then stops so the session can restart. None of the four is gated.
- An adoption happens in two repositories: `align-to-standards` is driven from a checkout of the standard and writes into the target; the driving checkout wires the guard itself; the guard recognises which side it is on from the tree's shape (driving checkout carries the tree under `standard/`; adopter has it at the root); on that side it judges only the writes that leave the checkout. Read from the tree rather than a setting (a setting would be an exemption). The ledger checked is the one in the repository the write lands in.
- Coverage: "Seventeen of the twenty-two points are enforced here - sixteen by the path they gate, `adopt.layout` by the rename." The other five are not writes to a nameable path: `adopt.continue` (phase boundary), `adopt.commit-plan` (a commit), `adopt.guards` (whatever guard configuration the target keeps), `green.conventions` (the layout before there is one), `spec.unknowns` (a decision inside a spec being written). The static check and human review carry those five.
- Scope: every point declares `scope`. **repository** — asked once; once the ledger carries an answered row for it "and that row is committed", later sessions write without asking (committed, not merely written — reading the file on disk would let a run add the row and the artifact in one breath). **work** — asked every time (the scope of this specification, the materials behind this digest, the participants in this run). Treating everything as work-scoped refuses an ordinary `adr-write` months later (guard gets removed); treating everything as repository-scoped licenses every write for life.
- Provenance states table: `human` (answered by a person, checkable against the transcript); `provisional` (agent-authored under explicit `suggest`, awaiting verification); `inferred` (concluded from the repository and said so — never valid where the answer is a preference); `absent` (deliberately empty under `stub`); `unverified` (claimed human, no transcript — counted separately, never folded into "validated").

## 2.9 `standard/.gitattributes`
- Rules: `*.sh text eol=lf`; `*.mjs text eol=lf`; `.claude/hooks/* text eol=lf`; `scripts/spec/* text eol=lf` (the last two cover extension-less scripts).

# Part 3 — every script and hook under `standard/scripts/` and `standard/.claude/hooks/`

## 3.1 `scripts/self-verify.mjs` — the compliance run (R16; standard ADR-005, ADR-011, ADR-016, ADR-022, ADR-037, ADR-038, ADR-052, ADR-057/058, ADR-009; R17; R7; R22)
- Purpose: "prove this repo still complies with the standard it is pinned to." Runs after `align-to-standards`, after `update-to-latest`, and in CI on every PR — same pass/fail each time. Mechanical tier only; judgment tier reviewed at PR (method doc `https://github.com/repository-standards/core/blob/main/docs/method/self-verify.md`).
- CLI: `node scripts/self-verify.mjs` (gate: exit 1 on any failure); `--version x.y.z` (also assert `.standards-version` equals the target); `--warn` (report only, always exit 0); `--profile core|scale` (core-profile entries only; without the flag the manifest copy's `profile` is the default, then scale = everything; `solo`/`team` accepted silently as deprecated aliases for core/scale); `--skeleton` (verify the shipped tree itself: skip the version pin, guards, fill-from-repo files, placeholder scan).
- Inputs: `standard.manifest.json` (cwd); every `stack*.manifest.json` matching `/^stack(?:\.[A-Za-z0-9][A-Za-z0-9._-]*)?\.manifest\.json$/` in cwd (standard ADR-016/037: one file per stack, read in filename order); `.standards-version`; the files/sections the manifest names; git (`git rev-parse --is-inside-work-tree`, `git ls-files`, `git check-ignore -v`, `git symbolic-ref --short refs/remotes/origin/HEAD`, `git ls-files -- "*node_modules/*"`); `PATH` (for guard prerequisites); `.gitignore` presence.
- Path existence is answered from directory listings, not `existsSync` — the filesystem's answer is case-insensitive on macOS/Windows (`readme.md` satisfied `README.md` on a Mac and failed on Linux CI). A missing required file is checked for a case twin before the adopter is told to create it (on APFS/NTFS writing `CHANGELOG.md` beside `ChangeLog.md` lands on and destroys the existing file).
- Result categories: `pass`, `fail` (one point of drift each), `note` (dim), `warning` (`WARN`, never drift), `unrun` (`SKIP` — "a check that could not run at all is neither a pass nor a failure"; counted and named in the verdict), excepted (dim, `isExcepted`, stays in the adoption denominator).
- Checks, in execution order (also summarised in the Part 4 table):
  - **0 manifest**: `standard.manifest.json` present but unparseable → FAIL `manifest`.
  - **0b stack manifests**: each matching file parsed; unparseable → FAIL `stack`; note `"<file>: <technology|unnamed> @ <version>|with no version declared - technology layer counted in the same drift number (ADR-016/022)"`; no `version` → WARN; a path declared by two stack manifests → WARN (checked once per declaration, counted twice; "the two stacks disagree about who owns the path (report it to them)"); stack `files`, `sections`, `guards`, `exceptions` are concatenated onto the manifest's.
  - **0c profile**: `--profile` flag wins; else manifest `profile`; else `scale`. No flag and no field → WARN "the manifest copy declares no profile - defaulted to scale; declare core or scale so the tier is a decision, not a fallback (standard ADR-011)"; a declared valid value (core/scale/solo/team) → note; unknown → WARN "treated as scale".
  - **1 version pin**: `--skeleton` → note skipped. Missing `.standards-version` → FAIL "repo is not pinned to a standard version (run align-to-standards)"; not matching `/^\d+\.\d+\.\d+/` → FAIL malformed; `--version` mismatch → FAIL; else PASS `pinned to X`. Manifest `version` ≠ pin → FAIL "the manifest must match the pin".
  - **Exceptions validation** (R17): kind not in `file|section|content|key` → FAIL ("a guard cannot be excepted at all"); empty `reason` → FAIL ("an unexplained deviation is not a recorded one"); `kind: file` whose `match` is a guard's own script (any `[\w./-]+\.(mjs|cjs|js|sh)` token in a guard `run`) → FAIL (disables a blocking check at drift 0; use `kind: content`). A `content` match may end in `/**` to waive a subtree (content only; each waived member still counted and printed).
  - **Workflow branches**: for every manifest file under `.github/workflows/*.ya?ml` present, if the file's `branches: [...]` lists do not include the repo's default branch (from `origin/HEAD`) → WARN "the trigger cannot fire, and nothing else reports it because the manifest can only require that the key exists". Silent when the default branch cannot be read.
  - **References**: note `"N method docs adopted by reference from the living standard - always latest (ADR-023/025)"`.
  - **Files loop** (skipping scale entries under `--profile core`, counted): `adapt: reference` → note. Present (path or altPath): if git-ignored AND nothing under it tracked (`git check-ignore -v`) → FAIL-or-except "exists on this disk but is git-ignored and untracked (<rule>) - it is not in the repository" (found on a platform whose .gitignore excluded `/docs/`, where 16 of 48 entries live); else PASS `<path> (<purpose>)`, then content check, then key check. Missing: case twin → WARN "DO NOT CREATE <path>: on a case-insensitive filesystem that write lands on <twin>"; `--skeleton` + fill-from-repo → note; required → FAIL-or-except "<path> missing - <purpose>"; optional → note "absent (optional)".
  - **Content check (2a)** for entries with `sha256` (not excepted as `file`): file hash = sha256 of UTF-8 text with CRLF→LF; unreadable → treated as a difference. String hash: match → PASS "matches the standard's copy"; else FAIL-or-except(`content`) "differs from the standard's copy" with hint "run update-to-latest to take the standard's copy, or record the change as an exception: { \"kind\": \"content\", ... }". Resolved via an altPath: a string-hash entry must still hash equal ("an alternate path is a different location for the standard's file, not permission for a different file"); a directory entry at an altPath is a **port** (`.agents/skills` for `.claude/skills`, R22): bytes not compared, but every top-level shipped member name (extension stripped, up to depth 3) must appear → note when all present, FAIL-or-except listing absent names otherwise (a monorepo symlinked `.claude/skills` at its own 31-skill system and reported 100% adopted). Directory entry at its own path: one result for the whole entry — members missing/changed each individually exceptable (`content`, counted as waived); PASS "matches the standard's copy (N files[, k excepted])" or FAIL "does not match the standard's copy: n missing (...); m changed (...) of N shipped files".
  - **Key check (2b)** for `requiredKeys`: JSON → parse (unparseable → FAIL "required keys cannot be checked"); YAML → a small block-mapping key-path reader (sequence items and flow mappings out of scope); other formats → FAIL "neither JSON nor YAML". Each key present → PASS `<file> > "<key>"`; absent → FAIL-or-except(`key`, `<path>#<key>`) "a merge keeps what the repo already has AND what the standard brings; this key is the part of <path> the standard is asking for".
  - **Sections loop**: file resolved through the entry's own altPaths (a changelog at `docs/CHANGELOG.md` used to pass the file check and fail the section). Heading found as ATX (`#{1,6} ... heading`, case-insensitive) or setext (heading text on one line, `===`/`--` underline on the next, fenced blocks skipped; a single `-` is a list item) → PASS; missing → FAIL-or-except(`section`) for required; file absent → FAIL "<file> missing, so "<heading>" cannot be checked" for required.
  - **removedPaths (2c)**: path absent → PASS "is gone (removed since X)"; present → FAIL-or-except(`file`) "still exists but the standard removed it in X - <note> - delete it ... or record an exception".
  - **Guards loop** (skeleton: note, none run): skip `self-verify` itself; `kind: diff` → note "runs in CI on the PR diff, not here"; script named in `run` (`scripts/<name>.mjs`) not installed → SKIP/unrun "NOT RUN - its script ... is not installed"; prerequisites missing → unrun "NOT RUN - <what>. A check that could not start has measured nothing, so it counts as neither drift nor adoption". Prerequisites: declared `requires: [{kind: "command"|"path", match, hint}]` (malformed entry → FAIL "unusable requires entry"); `command` resolved on PATH (with `.exe/.cmd/.bat` on win32), `path` by existence; plus inferred from `run`: quoted text blanked, split on `&&`, `;`, `|`, `&`, newline, `||` groups kept as one fallback group, first word of each group probed unless a shell builtin, `node`/`nodejs`, or a word with `/` — a group whose every alternative is a plain name resolving nowhere is reported. Then `execSync(run)` → PASS "<id> passed" or FAIL "<id> failed:" with indented stdout+stderr.
  - `--profile core` → note "N scale-only entries skipped".
  - **Decisions**: if any → note "the decision catalog applies where it applies - confirm at review ... (R7 names no subset and asserts no count ...)". Any decisions entry with a `required` field → FAIL "a decision area cannot be required by the manifest (R7 ...)". `decisions` that is not an array is ignored rather than thrown on.
  - **Unused exceptions**: an exception that matched nothing → WARN "is excepted but met anyway - delete the exception".
  - **No manifest branch**: WARN "no standard.manifest.json in this repo - measured against the built-in skeleton below, which is a fraction of the standard's entries. The number here is NOT the delta from the standard"; skeleton checks: `AGENTS.md`, `specs`, `docs/decision-records` (FAIL if missing); backlog at `docs/backlog.md` or `backlog.md` (FAIL if missing); `scripts/spec-structure.mjs --block` run if installed (PASS/FAIL), else note.
  - **2d placeholder / fill scan** (not in `--skeleton`; all WARN, never drift): fill paths = every present non-directory `fill-from-repo` entry (path or altPath) ∪ floor `AGENTS.md, README.md, SECURITY.md, docs/PRINCIPLES.md, docs/PRODUCT.md, docs/ARCHITECTURE.md, docs/personas.md, docs/backlog.md`. For each: RAW_PLACEHOLDER_RE (`{{UPPER_SNAKE}}` anywhere, or a line starting `> **Template`) on the raw body, or PLACEHOLDER_RE on the body after stripping fenced/`~~~` blocks, HTML comments, indented code blocks (4 spaces/tab after a blank line, not under a list item) and backtick spans (run-length matched; may span lines but never a blank line) — `{{...}}`, `<word or phrase>` (Unicode letters; single-word HTML element names excluded; no `:` `/` `=` or leading `/`), or a table row whose every cell is `...`/`…` → WARN "still carries template placeholders - filled shells, not copied ones, are the point". Otherwise prose (comments and headings removed, bullets stripped) empty → WARN "has no content beyond its headings - it counts as present, and presence is not substance"; prose matching NOTHING_YET (`todo`, `tbd`, `fixme`, `xxx`, `n/a`, `none`, `coming soon`, `to be written/filled/done/completed`, `fill (me) in`, `placeholder`, `wip`, `work in progress`) → WARN "says only "..." - it counts as present". Decision records (`docs/decision-records/**/(ADR|BDR)-NNN-*.md`, any depth, symlinks are leaves) are scanned with the unambiguous forms only (mustache, ellipsis rows, raw forms) — the `| **Author** | {{AUTHOR}} |` template row — because records quote `<standard>@<version>` in prose.
  - **2e hollow**: no capability spec (`specs/<cap>/<file>.md`, depth ≥3, excluding `.template.`, `readme.md`, `plan.md`, `tasks.md`, `checklists/`) → WARN "no capability spec exists here yet ... drift measures the manifest, so it reaches 0 on a repo that has specified no behaviour at all"; sets `hollow`.
  - **2f NEEDS REVIEW**: count of fill paths + record files + capability specs whose body matches `^>\s*\[NEEDS REVIEW\]` (standard ADR-057/058; reported, never scored).
  - **2c vcs** (not skeleton): tracked files with a `node_modules` path segment (`git ls-files -- "*node_modules/*"`, maxBuffer 64 MB) → WARN "N file(s) under node_modules/ are tracked in git[ - and this repo has no .gitignore at all]: a committed dependency tree is what a capability glob matches by accident".
  - **3 stray transition skills** (standard ADR-009 / SKILL-1): `.claude/skills/{align-to-standards,onboard-repo,modernize,greenfield-start}` present → WARN "is a transition skill and must not ship here - delete it".
- Report: header `self-verify - compliance with manifest <version>` (or "the BUILT-IN SKELETON"); one line per result with tag `FAIL`/`WARN`/`SKIP`/`····`/`PASS`, name padded to 10. Arithmetic: `drift` = failures; `applicable` = results that are not warnings and (not dim or excepted); `adopted = applicable - drift - excepted`; `pct = round(adopted/applicable*100)` (100 when nothing applicable). "EXCEPTED ENTRIES STAY IN THE DENOMINATOR" — excepting lowers the percentage, never raises it (a tree with 13 file exceptions once printed 100% (32/32) where intact it printed 49). Verdict line at drift 0: `self-verify: [OK - ]drift 0 - P% adopted (a/b), E excepted - compliant with the standard` plus suffixes: " - the percentage is how much of the standard's manifest is present here, not a grade of this repository"; skeleton scope note; "N CHECK(S) NOT RUN HERE (ids): a missing prerequisite, counted as neither drift nor adoption" (then the `OK - ` prefix is dropped); "N authored file(s) flagged above as unfilled or empty, counted as present"; hollow note " - AND THAT IS THE WHOLE CLAIM: no capability spec exists here yet ..."; "N entr(ies) still carr(y) a [NEEDS REVIEW] marker and await(s) a human". Exit 0. Otherwise `self-verify: drift N - P% adopted ... - N required entr(ies) (is|are) unmet` on stderr; exit 1, or 0 with `--warn`.

- Purpose: "Three mechanical structure checks on capability specs" (the file's header lists five numbered checks plus a sixth warn-only): no ticket-numbered paths; every capability spec names a persona from the roster; a claimed status is earned; a section heading appears once; a buildable spec carries its sections. "The 'structure lint' half of specs/enforcement.md, made mechanical."

## 3.3 `scripts/spec-guard.mjs` — code↔spec coupling guard (R11; "source-of-truth rule 5" / "rule 4")
- Purpose: flags when code in a capability's domain changed without touching that capability's spec — the mechanical half of same-PR spec coupling. "It cannot prove the spec is correct; it forces the author to touch the spec or consciously decide not to."
- CLI: `--staged` (pre-commit, staged files, warn only); `--base <ref>` (CI diff vs base ref); `--audit` (full-tree map soundness); `--block` (exit non-zero on violation; default warn, exit 0). No flag: `diff --name-only --diff-filter=ACDMR HEAD` plus `ls-files --others --exclude-standard` (a file not yet added is still a change).
- Inputs: `specs/capability-map.json` (missing → "not found - skipping (author it to enable the guard)", exit 0); git with `-c core.quotePath=false` (non-ASCII paths arrived quoted and matched no glob — found on caddyserver/caddy); `git merge-base <base> HEAD` (the before side; falls back to the base tip); `git show <ref>:<file>` via `execFileSync` (no shell: a path with a space is one path). Paths with a `node_modules` or `.git` segment are dropped everywhere (a dependency bump broke the gate for a capability nobody touched; the audit read thousands of vendored files as unclaimed); a note says how many were ignored.
- Map parsing (`bad(msg)` prints `spec-guard: specs/capability-map.json - <msg>` plus the entry grammar and exits 1): unknown `$`-key other than `$about`/`$unclaimed` → error; `$unclaimed` must be a list of non-empty glob strings and may not contain `!` entries; an entry is a glob string, `"!<glob>"` (empty exclusion → error), `{ "glob", "couples": "content"|"shape", "dataKeys"? }` (`dataKeys` must be a list of strings and only with `shape`; an exclusion written as an object → error), or `{ "external": "<repo>", "reason": "..." }` (both non-empty; `couples`/`dataKeys` on it → error); a capability whose entries are all exclusions → error ("claims no code at all"); a non-array value → error.
- `claimed(entries, f)` = some non-excluding glob matches and no excluding glob matches — the single ownership question used by both modes. External entries carry no regex and are excluded from `compiled`.
- `--audit`: file lists = `git ls-files` ∪ `git ls-files --others --exclude-standard` (vendored dropped), falling back to a filesystem walk when both are empty (fresh degit); capability dirs = `specs/<cap>/<file>`; four problem classes: `orphans` (spec dir with no map entry — "they silently rot"), `specless` (map entry with no `specs/<cap>/` dir), `emptyGlobs` (a glob or exclusion matching no file in the tree; retired capabilities — any spec file with `**Status:** retired` — exempt; external entries exempt by construction), `unclaimed` (only when `$unclaimed` declared: non-`specs/` files claimed by nobody and matching no `$unclaimed` glob; first 20 shown). External bindings printed as notes on every run. OK line: `spec-guard --audit: OK (N capability specs, all mapped; M globs, all matching; <files, each claimed or declared unclaimed | the unclaimed-code check is OFF - declare "$unclaimed" ... to turn it on>[; k retired capability/ies not checked for empty globs][; e external binding(s) not enforced here])`, exit 0; otherwise the lists to stderr with hints, exit 1 with `--block` else 0.
- Diff mode: changed files include D (deleted) deliberately ("removing a capability's code entirely - a retirement, not an edit - is still a change that must land with a spec update (R11)"). For each capability: `specTouched` = any changed file under `specs/<cap>/`; `codeTouched` = a changed non-`specs/` file claimed by the capability where some matching glob couples on content, or couples on shape and the JSON key shape changed. Shape = every key path with array indices collapsed (`files`, `files[].path`), stopping at declared `dataKeys` paths; compared between the merge-base (or HEAD/staged index) and after; added, deleted or unparseable on either side counts as changed. Data-only edits print `note - <file> changed as data, key shape unchanged - no spec coupling`. `codeTouched && !specTouched` → violation. `unclaimedChanges` (only when `$unclaimed` declared): changed, still-existing, non-`specs/` files claimed by no capability and matching no `$unclaimed` glob (deletions excluded — "A deleted file the map never covered is a map problem the deletion SOLVES").
- Output: `spec-guard: OK`, exit 0; else "code changed in these capabilities without a spec update: - <cap> (update specs/<cap>/ or state why no change is needed)" and/or "N changed file(s) belong to no capability: ... Add the path to the capability whose behaviour it implements, or declare it under "$unclaimed" ... A capability whose globs describe a layout the code does not have is a coupling guard watching an empty set, and it reports OK forever."; exit 1 with `--block` else 0.

## 3.4 `scripts/facts-check.mjs` — declared restatements agree with their home (R4)
- Purpose: "a fact lives in one place; every other place must agree with it." Complements tree-check (which BANS a fact from surfaces where it adds nothing): covers facts that legitimately appear in several places. Motivating drift: "twenty rules" while SPEC.md had 21; "11 lifecycle skills" while the tree held 12.
- CLI: `node scripts/facts-check.mjs [--facts docs/facts.json]`. Missing config → "no <file> - skipping (declare the facts this repo restates to enable it)", exit 0.
- Fact shape: `{ id, what, home, claims: [{ file, pattern }] }`; `home` is one of `{ "count": "<glob>" }` (how many files match; glob via `./lib/glob.mjs`; walk base = the fixed prefix before the first wildcard, `.` when the wildcard is the first segment — `*/CHANGELOG.md` once returned 0 and blamed the prose; `./` prefixes normalised), `{ "countMatches": { file, pattern } }` (how many times one file declares it, `gm` flags; zero → error "the home pattern matches nothing"), `{ "read": "<file>" }` (whole trimmed content), `{ "match": { file, pattern } }` (first capture, `m` flag — the same flag a claim uses; no match → error). Anything else → "home must be one of: count, countMatches, read, match".
- Text boundary: every read goes through `readText`; a NUL byte in the first 8000 bytes → error "<file> is not UTF-8 text ... facts-check reads UTF-8 text only ... Give it a text home the artifact is built from, or leave the restatement undeclared and say so where it is restated (R4)" (an ASCII string inside a binary matched and gave a green tick; a UTF-16 one reported "matches nothing").
- Per claim: file missing → FAIL "<file> does not exist"; pattern (`gm`) matches nothing → FAIL "the claim in <file> matches nothing - the surface was reworded past its pattern, so nothing was covering it"; every match's capture group 1 must equal the home value → else FAIL "<file> says "X", the source says "Y" (<what>)". Clean fact → `ok <id> = <value> - N restatement(s) agree`.
- Exit: any failure → `facts-check: FAIL - N fact(s) restated wrong or no longer covered`, exit 1; else `facts-check: OK - N fact(s), every restatement agrees with its source`, exit 0. `node_modules` and `.git` skipped in walks.

## 3.5 `scripts/schema-pair.mjs` — DDL and typed twin stay 1:1 (R24)
- Proves: (1) the declared edge resolves both ways — each `.sql` names a counterpart that exists and the counterpart names the `.sql` back; (2) every name the DDL defines (table, column, enum type, enum label) appears in the counterpart. Does not prove types agree (language-specific; belongs to the stack repo). Direction deliberate: the database is the source of what exists; a typed module may carry more (input shapes, derived fields) — an extra field there is not drift. Names compared case-insensitively with separators removed (`created_at == createdAt`).
- CLI: `node scripts/schema-pair.mjs [--dir <path> | --file <path>]` (default `database/schema`); `--block` (exit non-zero on failure; default warn, exit 0). A flag with a missing/flag-like value → "<flag> needs a path" (exit 1 with --block else 0); both flags → "name two different targets - pass one"; an explicitly named target that does not exist → "does not exist - the target was named explicitly" (never a skip); default target absent → "no database/schema/ - skipping (R24 binds repos that own a database)", exit 0; `--dir` on a file → "is a file - pass it as --file"; `--file` on a directory → "is a directory - pass it as --dir"; directory with no `.sql` → "holds no .sql - nothing to pair", exit 0.
- Parsing: `pair: <path>` comment (any comment syntax; trailing punctuation stripped; `normalize`d). SQL comments stripped; `CREATE [UNLOGGED|TEMP] TABLE [IF NOT EXISTS] name (...)` → table + columns (first token of each top-level comma-separated item, skipping `primary|foreign|constraint|unique|check|exclude|like|index|partition|deferrable|initially`); `CREATE TYPE name AS ENUM (...)` → enum + quoted labels. Twin tokens = all identifiers in the twin (its own `pair:` declarations removed so `bookings.sql` does not vouch for a table `bookings`), normalised.
- Failures: `.sql` with no `pair:` → "names no counterpart - add a "pair: <path>" comment (R24)"; counterpart missing → "names X, which does not exist"; counterpart does not name the sql back → "does not name X back - the pair is declared on one side only"; each missing name → "<twin> is missing <name> (<kind>[ of <table|enum>]), defined in <sql>". OK per pair: `ok <sql> <-> <twin>`.
- Exit: failures → `schema-pair: N break(s) in the declared pairs - the schema and its twin have drifted`, exit 1 with --block else 0; else `schema-pair: OK - N schema file(s), M names covered by their twin`.

## 3.6 `scripts/decision-records-check.mjs` — index and directory agree (R5; standard ADR-005, ADR-048)
- Purpose: two streams (ADR technical / BDR business) each keep files and a README table indexing them by number; nothing checked them against each other (a second `BDR-004` was minted; an Accepted `BDR-004` was missing from the index — both at drift 0).
- Checks: (1) duplicate id — two files, or two index rows, claim the same stream + number; (2) file with no index row; (3) index row citing a file not there; (4) no reopening signal — a binding record with no usable `## Revisit when` (standard ADR-048: read for shape, not presence). Exempt from (4): records whose `| **Status** |` value starts with `superseded|rejected|deprecated|withdrawn` (anchored — "Accepted ... supersedes ADR-013" is not exempt); `Proposed` is not exempt. Clean → `decision-records-check: OK (N record(s), index and directory agree)`, exit 0; else `... N problem(s). Number gapless, never reused (adr-write/bdr-write); the directory is the source of truth, not a remembered count.`, exit 1 with --block else 0.

## 3.8 `scripts/backlog-archive-check.mjs` — closing a row is a relocation (R15; standard ADR-051, ADR-038)
- Checks: (1) removed, not archived — a diff that takes a row out of the pool without that id reaching the archive ("fires seventeen times on the commit that motivated the record"); (2) empty `where`; (3) `where` points nowhere (a named path not in the repository); (4) in both files (pool and archive). Exempt from (1): an id present in a sprint file (it left the pool, it did not close) and a row carrying `split:<id>` whose remainder row is live in the pool or a sprint. Checks 2–4 skip where there is no archive; check 1 does NOT skip on a missing archive ("the first closure is exactly when the archive is supposed to appear"); it skips when no `--base` is given or the pool is absent. Not checked: whether the destination captures the finding (substance, standard ADR-038).
- CLI: `node scripts/backlog-archive-check.mjs` (archive shape only); `--base <ref>` (CI: also the removal check); `--block`.
- Paths: pool `docs/backlog.md` then `backlog.md`; archive `docs/backlog-archive.md` then `backlog-archive.md`; sprints under `docs/sprints` (files starting `_` skipped). Id pattern `^[A-Z][A-Z0-9]*-[A-Za-z0-9-]+$`; `split:<id>` pattern; cells unwrapped of backticks/asterisks/underscores. Tables read by header names (header = the row above a `---` separator row); id from the `id` column or the first cell; fenced blocks and HTML comments invisible (same comment state machine as sprint-guard).
- No pool → "no docs/backlog.md or backlog.md - skipping (no work ledger yet)", exit 0. No archive and no `--base` → "no docs/backlog-archive.md and no --base - skipping (nothing closed yet)", exit 0.
- Archive checks: empty `where` → "<id> has an empty `where` - a row whose content cannot be relocated was not done. Name what its content became (a record, a spec, a dossier, a changelog entry), or take the row back to the pool."; path-shaped tokens in `where` (`[\w.@-]+/[\w./@-]+` or `[\w-]+\.[a-z]{2,4}`; URLs dropped whole first; trailing punctuation stripped) that do not exist → "points its `where` at <path>, which is not in this repository. A pointer that does not resolve is the archive rotting quietly"; id in both pool and archive → "is in both ... A row lives in one place".
- Removal check with `--base`: before-pool = `git show <merge-base(base,HEAD)>:<pool>` (merge base, not base tip); null → "<pool> is new in this change - nothing to compare"; every id in before-pool that is in neither pool nor archive, not in a sprint, and not a live split remainder → "<id> was removed from <pool> and is not in <archive>. Closing a row is a relocation: put its finding where findings live, what shipped in the CHANGELOG, and the row in the archive with a `where` (standard ADR-051)."
- Output: clean → `backlog-archive-check: OK (N archived, M live | M live, nothing archived yet)`, exit 0; else each problem via `console.error` (block) or `console.warn`, then "N problem(s)[ - warning only, add --block to fail]", exit 1 with --block else 0.

## 3.9 `scripts/sprint-guard.mjs` — the one-place invariant (R15; standard ADR-028, ADR-029)
- Invariant: "One intent is in the backlog pool OR in exactly one sprint - never both, never two." Six directions checked: an id in more than one place; the same work under two ids (title check); an id a closed sprint's outcome says was returned that never lands in the pool; a sprint file whose rows cannot be found; a `blocked:`/`split:` status pointing at finished or nonexistent work; the pool's in-flight pointer rows against the sprints they name.
- CLI: `node scripts/sprint-guard.mjs` (report, exit 0); `--block` (exit 1 on violation; CI, scale profile).
- Inputs: pool `docs/backlog.md` then `backlog.md` (both manifest paths); sprint files = `.md` under `docs/sprints/` excluding `_`-prefixed files/directories (templates) and `TIMELINE.md`/`README.md` (derived or descriptive). Id pattern `^[A-Z][A-Z0-9]*-[A-Za-z0-9-]+$` (`INV-3`, `PAY-2`, `ADR-auth`, `DRIFT-2`), cells unwrapped of markup. Title normalised (markup removed, whitespace collapsed, lowercased; must contain a letter or digit in any script).
- No sprint files and no pool → "nothing to check", exit 0. Sprints but no pool → "N sprint file(s) but no backlog at ..." + "the pool half of the invariant cannot be checked without a backlog", exit 1 with --block else 0.
- Reading: a line generator tracks the current `## ` heading (only an H2 changes the section), skips fenced blocks and HTML comments with a left-to-right in-line scan (`| PAY-7 | fix <!-- was PAY-4 --> the export |` and a `-->` inside prose were the two holes). Sprint intents are read only under `## Intents` (`^intents\b`, case-insensitive); the pool is read whole. Table columns re-resolved at each separator row from the header above it: id column = the header cell named `id` (else 0), title column = `title` (else id+1); status = last cell. A sprint with no `## Intents` → unreadable ("a sprint's rows live under that exact H2 (a deeper level does not count), because a closed sprint's `## Outcome` table names the same ids"); rows under it but no intent id in the id cell → unreadable ("the id is its own cell (`PAY-2`), the title goes in the next one").
- Derived facts: `where` id→files; `status` id→last status; `work` title→rows (once per id per file); `blocks` (`blocked:<id>`), `splits` (`split:<id>`); references resolved case-insensitively to a declared id and reported in the row's spelling.
- Problems: `clashes` (id in >1 file); `duplicatedWork` (one title, ≥2 ids, ≥2 files; exempt when exactly two ids form a split pair); `stale` blocks (reference exists nowhere, or target is `done`, or target was split); `selfBlocked`; `splitNowhere` (remainder id exists nowhere — "the remainder was never cut"); `selfSplit`; `unreadable` sprint files; `unreturned` (a closed sprint — `| **Status** | closed |` — whose `## Outcome` has `Returned to the pool: A, B` naming ids not in the pool); pool `## In flight` pointer table (recognised by columns named `sprint`, `team`, `goal`, `target`, `items`; sprint path from a markdown link or bare/backticked path; resolved against the pool's directory, as given, and under `docs/`): `unreadablePointers` (no `sprint` column, or blank sprint cell), `danglingPointer` (no such sprint file; tried paths listed), `stalePointer` (points at a closed sprint — "closing a sprint removes its pointer row"), `wrongCount` (`items` is a bare number ≠ the sprint's intent rows), `unreadableCount` (`items` not a bare number, e.g. `6 items`), `unpointed` (once the table has any row: an open sprint no row points at). Block/split checks run with or without sprints.
- Output: clean → `sprint-guard: OK - N intent(s) across M place(s), each in exactly one[, k live block(s)]` (or "N intent(s) in the pool, no sprints in use"), exit 0; else each problem line, then a summary explaining the violated rule(s) — e.g. "An intent belongs to the pool or to one sprint. Pulling one into a sprint removes its row from <pool>; closing a sprint unfinished returns it."; "Two ids over one title is the same violation wearing a new number - move the row, do not copy it and renumber the copy."; "A `blocked:<id>` status must name an intent that exists, is not itself, and is neither `done` nor already split."; "A `split:<id>` status must name the new row cut for the remainder - a different id, and one that exists (standard ADR-029)."; the format reminder pointing at docs/tree/docs-sprints.md and `docs/sprints/_template.md`; the `## In flight` explanation ("A table with no rows in it is a pool not running sprints and is not checked; a table missing one row is a pool that has lost track of a sprint, which is."); exit 1 with --block else 0.

## 3.10 `scripts/elicitation-provenance.mjs` — the ledger stays honest (R28; standard ADR-057/058, ADR-052)

## 3.11 `scripts/lib/glob.mjs` — one glob translator (R16 entry "what more than one guard needs")
- Why: spec-guard and facts-check each carried their own translator with the same defect — `**` replaced by `.*` without consuming the adjacent slash, so `**/payment/**` did not match `payment/index.ts`; the shipped capability-map example's first two entries are that shape, so a top-level capability got `spec-guard: OK` on a money path.
- Syntax: `*` = any run of characters inside one segment (never crosses `/`); `**` = any number of segments INCLUDING NONE; everything else literal. Examples: `**/payment/**` matches `payment/index.ts`, `payment/x/y.ts`, `app/payment/index.ts`; `shared/**/payment*` matches `shared/payment.ts`, `shared/a/b/payment-intent.ts`; `src/**` matches `src/index.ts`, `src/a/b.ts` but not `srcx/index.ts`. A trailing `**` wants at least one segment ("a file named `src` is not one of" src's contents); every other position matches zero segments as well as many.
- Exports: `globToRegExpSource(glob)` (unanchored source: whole-glob `**` → `.*`; leading `**` → `(?:[^/]+/)*`; trailing `**` → `/.+`; middle `**` → `(?:/[^/]+)*`; a pending separator is emitted only after a middle form) and `globToRegExp(glob)` = `^...$`. Regex metacharacters `.+^${}()|[]\?` escaped; `*` → `[^/]*`.

## 3.12 `scripts/generate-dashboard/index.mjs` (+ `src/gate.js`, `src/gate.css`, `src/page.js`, `src/page.css`) — the work dashboard (R15; standard ADR-024, ADR-046, ADR-049)
- Purpose: renders a repository's work state as one static page `_dashboard/index.html` from committed files (backlog pool, sprints, changelog, decision records, specs, ideas, open questions, discovery). "Two people who run it on the same commit get byte-identical output, so the page is a projection of the repo and never a second place where work is tracked. Sources that a repo does not have are skipped, not faked."
- CLI: `node scripts/generate-dashboard/index.mjs [repo-root] [--out <file>] [--watch] [--serve [port]] [--anonymise|--anonymize] [--with-discovery] [--registry <path>] [--lock]`. ## 3.15 `scripts/spec/check-spec-clarified.sh` — the clarify gate (standard ADR-010, ADR-024; "this standard's addition", not upstream)
- Usage: `check-spec-clarified.sh <path-to-spec.md>`; exit 0 = gate passed; exit 1 = failed (message on stderr). Plain bash + grep only. "Every check fails CLOSED" (three fail-open bugs once got a spec to ready-to-develop with live questions). Passing earns `Status: ready-to-develop`.
- Checks in order:
  1. Argument missing → usage, exit 1; file missing → "FAIL - spec file not found", exit 1.
  2. `grep -q '^## Clarifications'` — absent → FAIL "has no '## Clarifications' section." + "run the clarify loop first (/spec-clarify); record answers and deferrals under '## Clarifications'." + "that heading is SYNTAX, not prose - it stays exactly '## Clarifications' in a spec written in any language (see docs/method/working-language.md). Translating it does not satisfy this check, it hides the spec from it." + "do not plan or generate tasks for a spec that is not ready-to-develop."
  3. `grep -cF '[NEEDS '` > 0 → FAIL "still has N open [NEEDS ...] marker(s) (the gap list - what is missing and who brings it):" + the lines + "resolve each marker - answer it (/spec-clarify), land the missing decision/input/asset, or record an explicit deferral under '## Clarifications'."
  4. Unbracketed family names as list items (`^\s*-\s*\*\*(CLARIFICATION|DECISION|INPUT|ASSET)-[0-9]+`) → FAIL "open marker(s) written as a numbered list item instead of the required [NEEDS ...] bracket form" + "rewrite each as [NEEDS CLARIFICATION: ...] / [NEEDS DECISION: ...; owner: ...] / [NEEDS INPUT: ...; owner: ...] / [NEEDS ASSET: ...; owner: ...]".
  5. Marker-shaped tokens the gate cannot read (`LC_ALL=C`): `[<ALL-CAPS words>: ...]` or `[<anything containing a non-ASCII byte>(:|：) ...]` not followed by `(` or `[` (a markdown link is not a marker) → FAIL "bracketed token(s) shaped like an open marker but not one of the four forms the gate can read" (reproduced: a Chinese spec with translated markers printed PASS with four unresolved items); "the text INSIDE the marker is prose and may be in any language".
  6. `## Open questions` section: scanned line by line with HTML comments (in-line) and fences stripped; section ends at the next `## `/`# `; absent → FAIL "has no '## Open questions' section (the capability template requires it)." + "add it, and write 'None known.' under it when there genuinely are none"; any non-blank line other than `none|none known|none at this time|no open questions|no known gaps` (optional trailing `.`) → FAIL "has N live line(s) under '## Open questions':" + lines + "that section passes only when it says there are none ('None known.'). Anything else there is an open item, however it is phrased" + "move each one: an unresolved gap becomes a typed [NEEDS ...] marker in the section it belongs to ..., a settled note goes into the section it describes, and a known gap the repo will not block on goes to the backlog with a link from there."
  7. PASS: "clarify gate: PASS - <file> has a '## Clarifications' section, no open [NEEDS ...] markers, and nothing live under '## Open questions' (ready-to-develop)."

## 3.22 `.claude/hooks/guards.sh` — the PreToolUse dispatcher
- Runs every guard in its own directory and relays the first denial. Resolves siblings from its own path (`dirname "${BASH_SOURCE[0]}"`); cannot locate its directory → hard deny "the agent guards could not locate their own directory". `GUARDS="no-remote-db-writes.sh no-force-push.sh no-ci-secret-writes.sh"`. stdin (the hook payload JSON) is buffered once (`PAYLOAD="$(cat)"`) and replayed per guard.
- Per guard: not readable → hard deny "the agent guard <name> is missing or unreadable, so this command was never checked. Restore .claude/hooks/ from the standard."; run `bash <path>` with stderr discarded; non-empty stdout → print it and exit 0 (relay); empty stdout with nonzero exit → hard deny "the agent guard <name> exited <rc> without a verdict" ("the exact shape that makes a syntax error in one of these files indistinguishable from approval"). All clean → exit 0.
- `hard_deny` prints deny JSON itself ("Not via lib.sh: this has to work when lib.sh is the thing that is gone"). Its own absence is covered by the `||` fallback in settings.json.

## 3.23 `.claude/hooks/lib.sh` — shared guard helpers
- `json_escape` without jq (sed for `\` and `"`, tabs/CR to spaces, newlines to `\n`); `deny <reason>` prints `{"hookSpecificOutput":{"hookEventName":"PreToolUse","permissionDecision":"deny","permissionDecisionReason":"<escaped>"}}` and exits 0.
- On load: `jq` missing → immediate deny "the agent guards cannot run because 'jq' is not installed ... Install jq (macOS: brew install jq; Debian/Ubuntu: apt-get install jq - see .../docs/method/prerequisites.md)".
- `read_command` = `jq -r '.tool_input.command // ""'` (stderr discarded); its exit status distinguishes a parse failure from "no command" (jq exits 0 on a well-formed call with none).
- `split_segments` — splits on `||`, `&&`, `;`, `|`, and a lone `&` not part of a redirection (`2>&1`, `&>log`); naive (no quote awareness). `split_segments_quoted` — awk state machine: metacharacters inside single/double quotes are text; backslash escapes outside single quotes; `esc` reset at end of line (a trailing backslash continues the command). The force-push guard keeps the naive split on purpose (an apostrophe in a commit message would otherwise swallow a `git push --force`).
- `SEARCH_CMD_RE` = `grep|egrep|fgrep|rg|ag|ack|sed|awk|echo|printf|cat|head|tail|less|more|find|fd|diff|comm|sort|uniq|wc|jq|tr|cut|column|tee`; `segment_is_search` — true when the segment's own command (after env assignments, `sudo`, `env`, `command`, `nohup`, `time`, optional path) is one of those or `git grep`, and the segment contains no `$(` or backtick.
- `LOCAL_HOST_RE` = `(localhost|127\.0\.0\.1|\[::1\]|::1)([:/[:space:]"']|$)` — anchored so `localhost.evil.example.com` is not loopback. `host_is_remote <host>` — quotes stripped; empty → not remote; a path (`/...`) is a unix socket → not remote; else not matching the loopback pattern.
- `inline_value <NAME> <text>` — value of the last `NAME=` assignment (quotes stripped). `ASSIGNMENT_ONLY_RE` — a segment that is only (exported or bare) assignments. `carried_value <NAME> <segment> <previous> <unsafe_fn>` — what NAME is worth to later segments: only an assignment-only segment carries; an `export` carries whatever it names; a bare assignment carries only when `<unsafe_fn>` refuses its value (a bare local value is "no evidence about what a later command will read"); otherwise the previous value is kept.

## 3.24 `.claude/hooks/no-remote-db-writes.sh` — no write to a database that is not on this machine
- Fails closed: cannot source `lib.sh` → deny "could not load .claude/hooks/lib.sh"; `read_command` parse failure → deny "could not parse its input as JSON"; empty command → exit 0 (allow).
- Signals read across the WHOLE command: `WRITE_PRESENT` when `WRITE_RE` matches — verbs `insert|update|delete|drop|alter|create|truncate|grant|revoke|merge|vacuum|reindex|cluster|refresh`, `copy ... from`, `comment on`, `reassign owned`, `pg_(terminate|cancel)_backend`, a `-f` flag (attached or spaced), `--file`, a `.sql` filename, or an input redirection `<` (not `<<`); `OPAQUE` when `$(` or a backtick appears (command substitution = unknown content). Hosts are established PER SEGMENT (`split_segments_quoted`). Stated cost: "a remote SELECT next to an unrelated `rm -f` denies, because `-f` is one of the write signals. That is the correct direction for this control, and the way out is to run the two commands separately."
- Clients: `SQL_CLIENT_RE` = `psql|pgcli|mysql|mysqlsh|mysqladmin|mariadb|mariadb-admin`; schemes `postgres(ql)?|mysql2?|mariadb`; `RESTORE_RE` = `pg_restore|mysqlimport`; `CLIENT_BOUNDARY` = `(^|[^[:alnum:]_.-])` (so `/usr/local/bin/psql` and `bash -c "psql ..."` count; the trailing boundary keeps `mysqldump`/`mariadb-dump` out — "a dump is a read"). Scope stated: SQL family only; `mongosh` and `redis-cli` are NOT covered.
- Per segment: an assignment-only segment records carried values for `DB_HOST DATABASE_HOST POSTGRES_HOST PGHOST PGHOSTADDR MYSQL_HOST DATABASE_URL DB_URL` and `DB_SSL_TUNNEL PGSSLTUNNEL` (via `carried_value`) and is skipped; a search segment is skipped. `remote=1` when a connection URI (`scheme://[user@]host`) has a non-loopback host; or a client/restore invocation has a host from `-h HOST`/`-hHOST`/`--host[=| ]HOST` or lowercase conninfo `host=HOST` (quotes stripped; a `/` host is a socket) that is not loopback; or, with no host flag, `PGHOST`/`PGHOSTADDR`/`MYSQL_HOST` from the segment's inline assignment or the carried value is remote (an explicit host beats the environment). `-h` is matched case-sensitively (curl's `-H`).
- Denials when remote: a restore client → "restoring a dump writes to the database, and this one is not local. Restore into a local database instead, or hand the dump to a human to load."; `WRITE_PRESENT` → "never WRITE to a remote database - no DDL, no DML, no migration CLI, no executing .sql files. Read-only SELECT is fine. Ship a schema change as a reviewed .sql file under database/schema/ for a human to apply."; `OPAQUE` → "this command reaches a remote database and builds its SQL from a command substitution, so what it would run cannot be read here ... Inline the statement, or read the file and ship the change as a reviewed .sql under database/schema/."
- Migration/seed runners: `RUNNER_RE` = a runner tool (`pnpm|npm|yarn|npx|bun|bunx|deno|node|tsx|ts-node|python[0-9.]*|php|bundle|rake|rails|mix|knex|prisma|drizzle-kit|sequelize(-cli)?|typeorm`) followed anywhere by a verb (`(db:)?migrate(:x)*`, `(db:)?seed(-with-reset)?(:x)*`, `migration:(run|revert)`, `ecto.(migrate|rollback)`, `db (push|seed)`, or an entry file under `migrate/` or `seed/`); `RUNNER_NAMED_RE` = `alembic upgrade|downgrade`, `flask db upgrade|downgrade`, `flyway migrate|undo|clean|baseline|repair`, `liquibase update*|rollback*`, `dotnet ef database update|drop`. Read-only: `migrate:(status|verify|list|current*|check*)`, `migrate status|diff` anywhere; flags `--status|--verify|--dry-run|--plan` only when not after a package-manager script (`pnpm|npm|yarn|bun ... migrate/seed`); `--reset` always a write. For a non-read-only runner: tunnel vars resolved (`true|1|yes|on`) → deny "<NAME>=<value> (from <source>) means the local port this runner would reach is a tunnel to a remote database, and a migration is a write."; host vars resolved in runner precedence — inline on the segment ("the command"), carried ("an earlier assignment"), the process environment ("the environment"), then every env file in `REMOTE_DB_ENV_FILES` (default `.env .env.local database/.env`, relative to the repo root = hooks dir `../..`; last assignment wins; `export`, quotes, trailing `#` comment and CR stripped) — each file naming a host is judged; `*URL` values reduced to their host (sqlite/file URLs = localhost); a remote host → deny "this migration or seed runner would write to <host> (<NAME> from <source>), which is not a local database ... Point <NAME> at the local database, or ship the schema change as a reviewed .sql under database/schema/"; no host seen anywhere → deny "this looks like a migration or seed runner and no database host is visible ... Name the host on the command (DB_HOST=localhost ...), or set REMOTE_DB_ENV_FILES in the hook command in .claude/settings.json to the env file this runner reads."
- Clean command → exit 0 with no output.

## 3.25 `.claude/hooks/no-force-push.sh` — no force-push or history rewriting
- Same fail-closed preamble (lib.sh, JSON parse, empty command → allow). Naive `split_segments`.
- `PUSH_RE` — a `git push` invocation allowing `-C <dir>`, `-c <kv>`, `--opt`, `-x` between `git` and `push`, with a non-word boundary before `git`. `FORCE_RE` — `--force` with no tail restriction (git accepts unambiguous abbreviations: `--force-with-l`, `--force-if-inc`; `--forc` is ambiguous and rejected by git; no benign push option shares the prefix); a short-flag cluster containing `f` anywhere (`-qf` and `-fq`); `+refspec`. `DELETE_RE` — `--de[a-z]*` (`--de` is the shortest unambiguous abbreviation; `--d` is ambiguous with `--dry-run`), a cluster containing `d`, or `:branch` after whitespace (empty-source refspec).
- Per segment containing a push: force → deny "never force-push or rewrite published history (--force, --force-with-lease, --force-if-includes, -f, +refspec). A normal git push is allowed. If a force-push is genuinely needed, hand the exact command to a human."; delete → deny "never delete a remote branch (git push --delete, git push -d, git push origin :branch). Whoever still has work based on it loses the ref, and nothing on the remote records that it existed. ... hand the exact command to a human."

## 3.27 `.claude/hooks/elicitation-guard.mjs` — a gated artifact is not written until its question fired (R28)
- PreToolUse hook; reads the tool call JSON on stdin (`tool_name`, `tool_input.{file_path|notebook_path|command|content|new_string|new_source}`, `transcript_path`). Output contract: a refusal is well-formed deny JSON on stdout with exit 0, never a nonzero exit (verifyAgentGuards scores nonzero as BROKEN).
- Flow: unparseable stdin → deny "could not parse its input as JSON ... It fails closed on purpose". Tool not in `Write|Edit|NotebookEdit` and not `Bash` → allow. Points file: `standard/.claude/elicitation/points.json` then `.claude/elicitation/points.json`; none parseable: if one exists but does not parse → deny "<file> exists but could not be parsed ... Fix the JSON and retry."; none at all → allow. Glob dialect: `**` spans directories, `*` does not cross `/`, matched at `(^|/)...$`.
- Bash: `movedFromUnder(cmd)` — per segment (split on newline, `;`, `&&`, `||`, `|`), matches `[git [-C <dir>]] mv <args>`; tokens quote-stripped; `-t DIR`/`--target-directory DIR` (detached), `-tDIR`, `--target-directory=DIR` (attached) make the destination explicit, otherwise the last argument is the destination; every source path that git already tracks (`git -C <dir|path's dir|.> ls-files --error-unmatch -- <path>`; absolute paths resolved in their own directory) is a move. No tracked moves → allow. Gating points = those with `gate_renames`. Write/Edit: target = `file_path`/`notebook_path` (backslashes normalised); no target → allow; gating points = those whose `gate_globs` match. No gating points → allow.
- Driving-checkout rule: `DRIVES_ADOPTIONS` = both `standard/.claude/elicitation/points.json` and `standard/.claude/hooks/elicitation-guard.mjs` exist in cwd; if so and every owner directory of the targets resolves (`git rev-parse --show-toplevel`, walking up to an existing ancestor for not-yet-created directories) to this checkout's own root → allow (judge only writes that leave the checkout). Moved paths that do not all belong to one work tree → no owner, nothing read, refusal below.
- Settling a point without asking: `stubbed(p)` — the written content or the ledger (`docs/adoption-provenance.md` / `standard/docs/adoption-provenance.md` under the owner root) declares `<id>: <state>` (YAML/JSON spellings `id: state`, `"id": "state"`) or a ledger row `| id | state |` for a state the point allows other than `human`/`provisional` (i.e. `absent` or `inferred`). `settled(p)` — only for `scope: repository`: the COMMITTED ledger (`git -C <owner> show HEAD:<ledger>`) has a row `| id | human |` or `| id | provisional |` (whichever the point allows) — committed, not merely written ("reading the file on disk would let a run add the row and the artifact in one breath"). Unmet = gating points neither stubbed nor settled; none → allow.
- Transcript: no `transcript_path` → deny "<target> is gated by <ids> and this guard has no transcript to check the question against. It fails closed on purpose". The transcript (JSONL) is scanned for lines containing `AskUserQuestion`; only an `assistant` message's `tool_use` block named `AskUserQuestion` counts ("Structural, not textual ... Compaction replays the model's own summary of a session back as a user turn"); asked ids = `input.metadata.source` split on whitespace/commas, plus `[id]` bracketed in any `questions[].header`. Unreadable transcript → deny. Every unmet point asked → allow.
- Refusal text for the first missing point: "Refused: <writing|moving> <target> needs [<id>] answered first." + the point's `asks` + "Call AskUserQuestion for "<id>" - either metadata.source "<id>", or "[<id>]" in the header; either alone is read. Three answers, always: they answer now -> provenance human; you suggest, they verify later -> provisional, plus a backlog row naming the point; a stub, and you do not guess -> absent, with a visible gap marker" + either "With nobody to ask, write the stub instead of a guess: put `<id>: absent|inferred` in the artifact's provenance and leave the gap visible. That passes here and reads as unfinished later." or "This one has no stub form: <why>. It has to be answered by a person, so an unattended run stops here rather than inventing it." + for repository-scoped points: "This question belongs to the repository, not to this piece of work: it is asked once, and docs/adoption-provenance.md is where the answer lives. If it was already answered, the row has not been committed yet - commit it and this write goes through without asking again."

### What self-verify checks — in the order the script runs them
| # | Check | Outcome kinds |
|---|---|---|
| 0 | Parse `standard.manifest.json` (if present) | FAIL `manifest` when unparseable |
| 0b | Parse every `stack*.manifest.json`; note technology@version; concatenate files/sections/guards/exceptions | FAIL unparseable; WARN no version; WARN path declared by two stacks |
| 0c | Resolve profile: `--profile` → manifest `profile` → `scale` | WARN no profile (defaulted to scale); note declared; WARN unknown value |
| 1 | `.standards-version` present, `x.y.z`, equals `--version` target if given | FAIL missing / malformed / mismatch; PASS pinned; note under `--skeleton` |
| 1' | Manifest `version` equals the pin | FAIL mismatch |
| 2x | Validate `exceptions`: kind in file/section/content/key; non-empty reason; `file` kind never on a guard script | FAIL per bad entry |
| 2w | Workflow `branches: [...]` lists include the default branch (`origin/HEAD`) | WARN per workflow that cannot fire |
| 2r | Count `references` | note "N method docs adopted by reference" |
| 2f | `files` loop (profile-filtered): reference-class note; present → ignored-and-untracked FAIL/except, else PASS; then content (sha256 / ported names / directory members) and requiredKeys (JSON/YAML presence); missing → case-twin WARN, skeleton note, required FAIL/except, optional note | PASS / FAIL / excepted / WARN / note |
| 2s | `sections` loop: heading present (ATX or setext, fences skipped) in the file or its altPaths | PASS / FAIL (required) / excepted |
| 2c | `removedPaths` loop: each listed path absent | PASS gone / FAIL-or-except still present |
| 2g | `guards` loop (not skeleton; profile-filtered): skip self; diff-kind note; script missing → SKIP; prerequisites (declared `requires` + inferred commands) missing → SKIP; run → PASS/FAIL with output | PASS / FAIL / SKIP(unrun) / note / FAIL malformed `requires` |
| 2p | `--profile core`: count skipped scale entries | note |
| 2d' | `decisions`: catalog applies where it applies (R7); any `required` field | note; FAIL per entry with `required` |
| 2e' | Exceptions that matched nothing | WARN "excepted but met anyway" |
| alt | No manifest: skeleton (AGENTS.md, specs, docs/decision-records, backlog; spec-structure if installed) | WARN not-the-delta; PASS/FAIL per skeleton item |
| 2d | Fill scan (not skeleton): fill-from-repo files + floor eight — template placeholders (raw mustache / template banner; angle/mustache/ellipsis after code stripping); empty prose; "nothing yet" prose. Decision records: unambiguous forms only | WARN only (never drift) |
| 2e | No capability spec exists (`specs/<cap>/*.md`) | WARN; sets hollow verdict note |
| 2f' | Count `[NEEDS REVIEW]` markers in fill files, records, specs | count in verdict (never drift) |
| 2c' | Tracked `node_modules` files | WARN (plus "no .gitignore" when absent) |
| 3 | Stray transition skills under `.claude/skills/` (align-to-standards, onboard-repo, modernize, greenfield-start) | WARN delete it |
| R | Report: per-result lines; drift = FAIL count; adoption % with excepted in the denominator; verdict suffixes (percentage meaning, skeleton scope, checks not run, unfilled files, hollow, NEEDS REVIEW) | exit 0 at drift 0; exit 1 otherwise (0 with `--warn`) |
