# Contracts - hard rules (contract-first tRPC, ADR-017)

1. All FE <-> BE and service <-> service calls are tRPC through `@bf/contracts`; no ad-hoc REST,
   no hand-written HTTP clients, no second RPC style.
2. Schemas are hand-written zod in `packages/contracts/src/<svc>/schemas.ts` and import nothing
   from `apps/*`, NestJS or Drizzle. `router.ts` is generated by `pnpm contracts:generate` and
   never edited; `pnpm contracts:check` fails on drift.
3. Every procedure declares `input` **and** `output` schemas so the generated router type is
   self-contained. Router alias = entity plural (`orders`), procedure = verb (`getById`, `list`,
   `place`); every service exposes `health.ping`.
4. Adding optional fields is safe; renaming or removing a field is a breaking change: every
   consumer moves in the same PR (the type check is the contract test) and the capability spec's
   interface contract moves with it.
5. Browsers always call the edge (`apps/api`, `/<svc>/trpc`), never a service directly; Nest
   services call each other through `TrpcClientModule` from `@bf/trpc`, which propagates the
   correlation id and the caller's identity headers.
6. Breaking changes to a contract are a red flag (AGENTS.md): stop and record the decision.
