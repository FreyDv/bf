# @bf/contracts

Contract-first tRPC contracts for every NestJS service. Consumed through the workspace
(`"@bf/contracts": "workspace:*"`) — nothing is published to a registry.

```
src/
  common/           id, pagination, health ping — shared zod schemas
  <service>/
    schemas.ts      HAND-WRITTEN zod input/output schemas (+ inferred TS types)
    router.ts       GENERATED by nestjs-trpc — `export type AppRouter`
    index.ts        export * from './schemas'; export type { AppRouter as <Service>Router }
```

Entry points: `@bf/contracts/common`, `@bf/contracts/auth`, `@bf/contracts/order`,
`@bf/contracts/course`, `@bf/contracts/billing`, `@bf/contracts/admin`, `@bf/contracts/ai`.

## Rules

1. **Schemas first.** Every procedure declares `input` **and** `output` with schemas imported from
   this package (`@Query({ input: usersGetByIdInputSchema, output: usersGetByIdOutputSchema })`).
   With an explicit `output` the generator never needs `ReturnType<>` of app code, so `router.ts`
   stays self-contained (zod + `@trpc/server` only).
2. **Zod only.** `schemas.ts` must not import from `apps/*`, NestJS or drizzle.
3. **Never edit `router.ts`.** Regenerate with `pnpm contracts:generate` (all services) or
   `pnpm --filter <svc> contracts:generate`. CI fails on drift (`pnpm contracts:check`).
4. **Naming.** Router alias = entity plural (`users`, `orders`), procedure = verb
   (`getById`, `list`, `upsert`, `remove`). Every service exposes `health.ping`.
5. **Breaking changes.** Adding optional fields is safe; renaming/removing requires updating every
   consumer in the same PR — the type-check is the contract test.

## How generation works

`scripts/trpc-generate.mjs <svc>` runs the Rust CLI shipped with `nestjs-trpc` against
`apps/<svc>/src/trpc.module.ts` (the file with the literal `TRPCModule.forRoot({...})`), globs
`src/**/*.router.ts`, and writes `packages/contracts/src/<svc>/router.ts` (imports rewritten to
relative paths, prettier applied). The npm tarball ships the native binary without the exec bit,
the script fixes that.

## Consuming

- **Nest → Nest**: `TrpcClientModule.register<AuthRouter>({ name: 'auth' })` from `@bf/trpc`
  (reads `AUTH_URL`), then `@InjectTrpcClient('auth') auth: TrpcClient<AuthRouter>` and
  `auth.users.getById.query({ id })`. Correlation id and the caller's identity headers are
  propagated automatically.
- **Next.js / scripts**: `createTRPCClient<OrderRouter>({ links: [httpBatchLink({ url: `${API}/order/trpc`, headers })] })`.
  Browsers always go through the edge (`apps/api`), never to a service directly.
